# 客户控制台独立页面与历史记录浏览

本 RFC 负责客户控制台的页面组织、内部导航、客户历史查询和页面状态。账户金额、预授权、实际扣费与账单归属由账户资金 Spec 和 RFC 负责；客户身份、两个独立入口产物及静态托管仍由 `0010` 负责。管理员账户页的四按钮弹层布局由 `0011` §4.3 负责，两种页面不共用布局规则。

## 1. 页面与导航

| 客户地址 | 页面 | 主要数据 |
| --- | --- | --- |
| `/` | 概览 | 余额（客户现在能用的钱）、更新于（时刻）、通往调用记录、账单与资金记录、API Key 的入口。 |
| `/usage` | 调用记录 | 处理中请求与已结束历史分开；已结束历史可选日期并继续翻页。 |
| `/billing` | 账单与资金记录 | 日期区间、请求数、产出张数、扣费净额，以及可按类别筛选、翻页的真实收支流水。 |
| `/keys` | API Key | 创建、列出与确认吊销。 |
| `/settings` | 账户设置 | 登录邮箱、可复制的账户 id、改口令与退出。 |

客户主机名下的这五个地址共享客户入口产物，导航只切换客户页面，不加载管理端代码。桌面使用持续可见的页面导航；窄屏折成可打开的导航菜单，不把五页内容纵向拼接。浏览器后退、前进和直接刷新按地址恢复页面。日期区间放入非敏感 URL 查询参数；会话令牌、API Key 明文和重置令牌均不得进入 URL。

概览只请求当前账户金额；不请求全量账单、历史用量或资金流水，也不分别显示已结算余额、持有中或可用额，更不出现单笔预授权金额。客户页面唯一的余额标题是「余额」，取 `available_microusd`：请求受理时按占住的额度减少、结算后按实际扣费多退少补。它下面只有一行“更新于 …”，不给任何一个内部分项金额，也不写解释预授权占用或结算机制的文案：那套机制属于平台内部，客户侧只呈现“余额”这个事实。概览也照 V-D14 的方式处理失败与加载：取数失败显示错误与重试入口、不画成 0，加载中不显示数字；另给一个手动刷新入口，让客户在请求受理或结算之后自己取一次准数。账户 id 从首屏标题移到设置页。账单默认从 29 天前的本地零点到打开页面的当前时刻，覆盖含今天的 30 个本地自然日；选择本地日期时将起止时刻换成 UTC 半开区间发给服务端，并明确显示本地时区。账单选择写入当前地址的查询参数，离开再返回时恢复该区间。概览不显示没有区间限定的“扣费总额（全部）”，也不计算平均每次扣费。

## 2. 调用记录

处理中请求单列在历史列表上方，显示请求时刻、型号和状态，可手动刷新；仍需对账的请求也显示为处理中，它不进入已完成请求数。已结束历史默认从 29 天前的本地零点查询到当前时刻，可调整日期；使用 `terminal_at` 作为日期筛选与倒序依据，同一终态时刻用 Job id 排序，行内同时给出请求时刻与终态时刻、型号、状态、图片数和实际扣费。接口的 Job id 仅作服务端翻页排序，不进入对客响应；客户页面不展示内部 Job 标识。未收费的失败或零实收记录显示 0，不把预授权算作扣费。

`GET /v1/customer/usage` 保留既有不带新参数时的响应和行为，增加可选的 `view=active|completed`、`cursor` 与 `next_cursor`。新页面分别读取两组：`active` 可刷新，`completed` 按终态时刻及 Job id 倒序连续翻页。已结束记录的终态时刻在提交后不可变，因此新完成的请求只会插入游标之前，不会使后续页面漏项；对筛选条件或日期区间不匹配的游标返回参数错误。当前 `limit` 上限保持受控。终态时刻由账户资金设计 `0013` §5 落地；在其字段可用前不得把请求创建时刻冒充结算时刻。

处理中的请求不承担稳定历史：`view=active` 不接受游标，也不返回 `next_cursor`，超过 `limit` 时用既有的 `truncated` 说明“还有更多在处理中”。

## 3. 账单与资金记录

同一个日期区间驱动账单汇总和流水列表。账单只请求一次 `/v1/customer/billing`，页面内所有汇总组件共用这份结果；请求失败显示错误和重试，不把缺失值渲染成 0。`charged_microusd` 是有符号净额：负值以正数金额标“净支出”，正值标“净返还”，零值标“收支相抵”。`credit` 不进入扣费净额；`capture` 与 `adjustment` 在流水中分别标明“实际扣费”和“资金调整”，金额方向仍按服务端有符号值展示。页面不把净额除以请求数并称为平均扣费。

`GET /v1/customer/ledger` 保留既有参数及响应字段，增加可选的 `kind=credit|capture|adjustment`、`cursor` 与 `next_cursor`。缺省查全部真实收支，未知 `kind` 返回 400。列表按 `(created_at, id)` 倒序分页，游标只对同一账户、日期区间、类别与排序有效；变更筛选条件清空游标。游标是不透明的定位信息，不含凭据。账户只能通过客户会话确定，不能从查询参数选择；资金流水不返回预授权与释放。账单区间的跨天归属及净额仍按账户资金 Spec `0002` §5，不由页面重新求和。

查询索引分别覆盖账户与真实流水的 `(account_id, created_at, id)`、已结束请求的 `(account_id, terminal_at, id)`；处理中请求按账户和请求时刻读取。终态时间索引可与账户资金设计 `0013` §5 合并核定，不重复建立同用途索引。翻页采用数据库查询，不把全量历史加载到浏览器后切片。

每次取数都在服务端验证会话和账户所有权。历史响应继续提供原有 `count`、`truncated` 等字段以兼容旧调用方，新增的 `next_cursor` 为无下一页时的 `null`；前端只在它非空时显示“继续查看”。游标用仅由服务端掌握的环境密钥加密并认证，携带排序位置、账户与筛选条件（页面的原值，逐项比对）；内部 Job id 不以可解码的文本出现在响应里。密钥在进程重启后保持一致；更换密钥会使旧游标失效，页面可提示重新查询。游标解码失败或与当前账户、筛选条件不符返回 400，不静默从首页重查，游标也不能代替会话认证。

**区间与翻页是一件事**：页面首次进入算出的 `since`/`until` 就是这段历史的边界。两个历史页面都把它写进地址查询参数（缺省区间用 `replaceState` 补写，不新增一条历史）；“继续查看”原样复用同一个 `since`/`until` 与游标，**不重算“现在”**——重算会让第二页的区间与游标里的筛选面不符而被拒。客户改动日期区间即放弃当前游标，从新的首页重新查。游标本身不进地址：它是翻页状态，不是筛选条件。

## 4. API Key、设置与会话

API Key 明文只在创建成功的当前页面弹层里存在；关闭弹层立即清除组件中的明文，列表只读标签、创建时刻与吊销状态。吊销先展示密钥标签并要求确认，再发送删除请求；成功后刷新列表。账户设置单独承载改口令、账户 id 与退出；改口令成功清掉已失效会话并回登录页。

路由守卫在没有会话时只挂载登录/注册页面，保留用户输入的内部目标地址；登录成功回到该页面。登录响应已有 `expires_at`，客户会话状态保存此时刻并在到期时清除页面数据；服务端提前吊销导致的未认证响应也集中清除本地会话和页面数据，回登录页，不把先前加载的余额或密钥留在可见页面。切换客户页面不额外创建会话；浏览器刷新仍沿用 `0010` 的会话存放规则。找不到的客户页面显示客户侧 404 页面，不回落到账户概览或管理界面。

## 5. 与既有设计及交付的边界

`0011` 的客户控制台三标签页目标由本 RFC 接管；`0011` 继续负责管理员导航与账户页。`0010` 的双入口构建、按主机分发与静态回退保持适用。生产客户主机名的 `/usage` 等无扩展名路径仍由静态回退返回 `portal.html`，`/v1` 和 `/api` 继续保留 JSON API 的 404 语义；不能为实现深链把未知 API 路径回成 HTML。开发服务与生产静态托管都要验证直接打开五个地址。

金额字段改名义、客户页面只显示一个「余额」数字（可用额口径）、`terminal_at` 与跨天账单规则依赖账户资金方案落地。本整改可以先完成导航、分页面与密钥确认，但在整体交付验收前必须接入账户资金方案的新字段；不得将旧余额值提前标作已结算余额。运营充值入口、计价、预授权、管理员账户页和在线支付均不在本 RFC 范围内。

部署需为所有 API 实例配置同一份客户历史游标加密密钥，且仅从环境变量读取；缺少或格式无效时，进程启动失败并点名配置错误。生产配置与密钥轮换说明在实施时写入运维文档，不把密钥写进仓库、日志或响应。

## 6. 取舍与风险

维持单页标签页可以少改路由，但账单汇总、调用明细与资金流水仍会在同一默认视图里变成长列表，日期和翻页状态也难以独立保存。客户需要反复查历史，所以选独立地址和页面级取数；相比管理员账户页的短操作，客户历史不放入侧边栏。代价是增加导航和深链守卫，必须核对开发与生产两种静态托管方式。

历史记录使用按 `(时刻, id)` 定位的游标，而不是 offset：新记录插入首页时不会把已结束历史的后续页推移。游标可在服务器保存映射，或加密后由客户端回传；选后者是为了不增加持久游标表与清理任务，代价是部署时要提供稳定的环境密钥，并接受密钥轮换时旧游标失效。处理中请求会变化，因此单独刷新，不以它承担稳定的账单历史。资金方案尚未落地时，余额字段和 `terminal_at` 不能用当前代码的旧口径代替；整体交付需与其验收相接。

## 7. 验证切入点

客户接口合同用例覆盖：多于一页的资金记录和已结束请求，游标无重复漏项、类别筛选、错误游标、账户隔离、跨天终态与入账区间、旧参数和旧响应兼容。浏览器用例覆盖：未登录直达与登录回跳、五页地址的刷新和前进后退、区间 URL、只在打开页面时取对应数据、会话失效清屏、账单错误不显示零、API Key 吊销确认及明文关闭后消失。人工查看桌面与窄屏布局、首屏余额和长列表滚动体验；不以快照测试代替人工判断。
