# 客户公开认证页面与找回导航

本 RFC 拥有认证页面组件、路由分类、回跳存储、请求生命周期、错误映射与公开鉴权端点的尝试计数。受保护页面取数和历史查询由客户导航设计拥有；身份 API、密码重置码签发和服务端会话失效机制由身份设计拥有。本次不需要数据迁移或新接口，账户名称提案也不是前置。

## 1. 路由与组件职责

[地址定义](../../apps/web/src/portal/paths.ts)区分受保护页面与公开认证页面，公开地址以[Spec §2](../specs/0004-customer-authentication-pages.md#2-页面内容)为合同；所有客户深链集合仍从同一份定义派生，避免开发回退遗漏认证地址。`/portal.html` 沿用概览别名。路径归一化规则由[路由模块](../../apps/web/src/portal/routes.ts)拥有，公开页与受保护页共用尾斜杠归一化。

[客户外壳](../../apps/web/src/portal/App.tsx)在会话守卫前识别公开地址。无会话访问受保护地址时仍在原地址显示登录；公开认证地址按地址挂载对应页；有会话访问登录或忘记密码使用 `replace` 回概览，重置页则挂载独立页面，不挂载客户账户外壳和取数组件。未知地址沿用未认证先登录、认证后 404 的行为。路由类别进入同一分类结果，不能由认证组件各自比较字符串。

[认证组件](../../apps/web/src/portal/auth/)拆为共享认证布局、登录/注册页、忘记密码页、重置密码页。共享布局只负责标题、内容宽度与导航呈现，各页面拥有自己的表单、错误和提交状态。注册模式仍是登录页局部状态，不增加注册地址；路由改变时卸载表单，重新进入默认登录。表单设置为卸载不保留值，密码和重置码不进入父级状态或路由对象。

[会话模块](../../apps/web/src/portal/session.tsx)仍独立管理客户会话。重置确定成功与“返回登录”动作调用本地 `signOut`，再按需要 `replace` 到登录地址；不调用服务端退出去干扰持有其他客户重置码的情形。登录/注册成功按当前地址类别决定去向：当前为受保护或未知地址时保留原地址并清除旧回跳记录，分别由客户页面和客户 404 接管；当前为公开登录页时消费校验后的回跳目标，缺失时使用概览。公开登录成功先 `replace` 到确定目标，再写会话，使会话守卫不会抢先带回概览。主动退出沿用现有流程，额外清除找回目标；重置页的本地清会话保留本次回跳记录。

## 2. 回跳目标与敏感数据

回跳目标保存在当前标签页 `sessionStorage` 的独立客户键中，只保存经校验的路径和认可的日期区间参数（`since`/`until`）；认证 URL 不增加 `returnTo` 或其他目标参数。识别目标、保存、读取、消费、清除由路由辅助函数统一拥有，客户页面和认证页不分别实现。没有目标时不创建默认记录，消费后必须清除。

从受保护地址进入忘记密码前，以当前路径与日期区间覆盖旧目标；从公开页之间切换或刷新则读本次目标，不覆盖。无会话进入新的受保护地址、会话失效时清除旧目标；若此后进入找回，才从当前地址重新捕获。未知地址不捕获。浏览器历史返回受保护地址时仍按当前地址直接登录；继续找回则重新捕获它，避免旧账单目标覆盖后来打开的设置页。

校验只接受[客户受保护地址集合](../../apps/web/src/portal/paths.ts)，拒绝外部来源、协议相对地址、管理端、API 和公开认证地址。任一查询参数涉及凭据时拒绝整个候选，不将其清洗成合法目标；识别会话凭据、API Key、密码、重置码的常用字段及大小写变体。认可筛选只取调用记录与账单现有的 `since`、`until` 日期对，按[日期模块](../../apps/web/src/portal/dates.ts)校验并规范化；无有效日期对时只保留页面路径，重复日期参数或普通未知筛选不保留。`view` 与 `kind` 只活在组件内——[调用记录页](../../apps/web/src/portal/pages/Usage.tsx)的 `view` 是同一页两个面板的固定取数分支，[账单页](../../apps/web/src/portal/pages/Billing.tsx)的 `kind` 是页面状态——从不进入页面 URL，因此回跳只认日期区间与既有行为一致，不是削减能力；本次不增加它们的持久化。目标片段不保留。读取存储也重新校验，不能信任同源存储中的原值；缺失、损坏或存储读写失败均退化为无目标，并继续显示页面。会话存储自身的既有故障行为不由本设计扩大。

表单字段仅存在当前页面内存。重置码去首尾空白，密码按原值传递；不加入 URL、history state、缓存、存储、日志或截图 fixture。浏览器前进后退重挂载页组件，刷新为空白表单；浏览器密码管理器的用户授权行为不由应用写存储实现。

## 3. 请求状态与错误

重置页状态为 `editing`、`submitting`、`succeeded`、`terminal-error`、`unknown-result`。前端表单校验完成后同步占有请求锁，再切为提交态，冻结字段和按钮；单靠 React 的下一次渲染或按钮 loading 不能阻止同一帧的连续提交。确定参数错误释放锁回编辑态；确定成功清字段进入结果页；尝试超限释放锁回编辑态并保留字段；其余结果按[Spec §4](../specs/0004-customer-authentication-pages.md#4-表单与反馈)进入终态并清字段，不能自动重试。

兑换沿用[CustomerClient](../../apps/web/src/portal/client.ts)的无认证请求和 `reset_token`、`new_password` 请求字段。确认密码不传送。[共享传输](../../apps/web/src/shared/api.ts)增加可选成功状态校验 `expectedStatus`，默认行为保持原义；兑换调用传入 `204`，传输在成功响应返回前检查实际状态，其他 2xx（包括 200 的空体或 JSON）抛异常响应错误并由认证页映射为结果未知。非 2xx 继续保留既有状态和错误码。认证错误映射限定在客户认证操作中，使用 HTTP 状态与已有 `ApiError` 信息，不让共享管理错误翻译改变管理端行为，也不将共享的“邮箱或口令不对”直接展示为重置结果。现有 `400 invalid_parameter` 无法精确区分服务端密码规则与无效码，因此映射为 Spec 的组合提示；404 映射为客服协助；429（尝试超限）是确定的拒绝，按响应的 `Retry-After` 显示等待提示并保留输入，不归入结果未知；5xx、无法读取响应和未识别错误保守映射为结果未知。204 才是确定重置成功。

登录与注册各自使用同样的同步锁与页面存活标识，遵循基础身份错误语义和 Spec 的客户措辞；尝试超限与重置页共用同一等待提示映射。每次请求捕获页面实例标识，卸载后结果不得更新表单、发成功通知、导航或写清会话；网络请求即使中止也不能证明服务端未处理。重置请求未得到确定结果而页面离开时，不能在其他页面补报成功；重新打开重置页从空白编辑态开始。

重置码的消费与密码写入在[现有应用实现](../../crates/application/src/lib.rs)中分两步完成，因此服务端失败也可能已经消费重置码。本设计不调整后端事务，不能向用户保证失败可继续使用旧码；结果未知反馈让用户先验证新密码或取得新码。该既有机制的权衡与后果由[本次记录](../../.agents/notes/implemented/platform/2026-10-03-customer-authentication-pages.md)保留。

公开鉴权端点的有界尝试限制（Spec S5）复用加速层计数：固定窗口、`CacheStore` 的读写与 TTL、读不到就当这一窗口还没数过、写失败只记日志，不新建计数设施。计数键沿用既有“命名空间 + 窗口号”的形状，形如 `rate_limit:auth:{endpoint}:{scope}:{digest}:{window}`：`endpoint` 取 `register`、`login` 或 `redeem`（三个端点各自计数，互不占用额度），`scope` 取 `source`（来源）或 `identity`（身份），`digest` 是来源地址与规范化身份的摘要——键里不出现邮箱或地址原文，与凭据不进存储同一道理。计数落在认证用例这一层：[认证用例](../../crates/application/src/lib.rs)在受理前读键判定（已到上限直接返回 429 与剩余等待时长，不再做密码校验或兑换），在服务端判定失败后写同一键，成功尝试不写。

失败尝试限制计的是**失败次数而不是请求数**，判定与写入分处一次请求的两端；它只用缓存这一层原语，与客户请求速率无关。三个端点的身份口径：注册与登录用提交的邮箱，兑换用重置码所属客户；重置码不存在或已用时没有身份维，该次失败只计来源维。拒绝结果与计数都不区分邮箱是否存在、重置码是否存在或已用，因此计数不能按“这个身份是否存在”分流。等待时长按当前窗口剩余时间给，沿用既有 `Retry-After` 头与 `rate_limit_exceeded` 错误码；`CacheStore` 没有 `INCR`，读改写仍不是严格原子，沿用既有取舍——要挡的是数量级异常，不是精确的第 N 次。三个端点各自的上限与窗口是运维取值，读法是整数环境变量加缺省值：`AUTH_ATTEMPT_LIMIT_<ENDPOINT>_FAILURES_PER_WINDOW` 与 `AUTH_ATTEMPT_LIMIT_<ENDPOINT>_WINDOW_MS`，`<ENDPOINT>` 取 `REGISTER`、`LOGIN` 或 `REDEEM`。降级沿用既有规则：缓存不可用或读到不可读的值时不拒绝请求，按“这一窗口还没数过”继续；`REDIS_URL` 为空时这层不生效，这是部署期可见的事实，不写成“无缓存也强制”。

来源维需要一个权威的客户端地址：连接层把**连接对端地址**挂进请求扩展，这是唯一不能由调用方自带的来源；生产在 nginx 之后时对端是代理本身，因此在 API 进程配 `AUTH_SOURCE_HEADER`（例如 `x-real-ip`，[反向代理配置](../operations/deployment.md#5-反向代理与-tls)已用 `$remote_addr` 覆盖写它）后采信该头，未配置时退回对端地址。`X-Forwarded-For` 的最左值可以由客户端自带，不采信。采信头的前提是 API 不能被绕过代理直连（否则同一个头同样可伪造），这是部署期边界。该信任边界的取舍与备选由[本次记录](../../.agents/notes/implemented/platform/2026-10-05-public-auth-attempt-limits.md)保留。

## 4. 静态托管与兼容边界

[开发配置](../../apps/web/vite.config.ts)使用扩充后的客户深链集合返回客户入口；归一化后的认证地址和尾斜杠形式都必须回退，不能只有运行中的客户端支持。生产继续使用 API 的按主机名分发和无扩展名静态回退。客户入口不会导入管理端认证模块；未知 `/api`、`/v1` 地址仍返回 JSON 404。

既有[客户导航设计 §4](0014-customer-console-navigation-and-history.md#4-api-key设置与会话)中的“无会话只挂载登录/注册”限定为受保护页面；本设计接管公开认证地址，该澄清已同步到既有设计。共享[提示常量](../../apps/web/src/portal/notices.ts)由账户设置页继续引用：认证页移除自己的调用，设置页与三个认证页一起把客户可见的“口令”统一为“密码”、“重置令牌”统一为“重置码”；这条常量承载的“重置要走运营签发”含义不变，管理端与管理端文案不随之改版。共享传输里带“口令”的凭据错误文案供管理端继续使用，客户面由认证页与设置页自己映射成“密码”措辞，不靠改共享常量达成统一。

## 5. 验证承接

| Spec 范围／验收 | 验证切入点 |
| --- | --- |
| A1–A2 | 浏览器观察各页内容、注册入口、页面切换及网络请求，断言登录页无重置字段、忘记密码无签发请求。 |
| A3、A10 | 生产构建托管测试直接刷新、前进后退和尾斜杠；开发服务检查同一地址集合；桌面和窄屏人工查看任务分离、标签、键盘操作与溢出。 |
| A4–A5 | 从受保护账单地址贯穿找回、刷新和重新登录；另验证不经找回的直接登录和注册保留账单日期、未知地址直接登录后为客户 404；验证退出后目标清除、损坏存储和非法目标退回概览，混合合法日期与凭据参数的候选整体拒绝。 |
| A6 | 用真实浏览器覆盖前端校验、请求载荷、连续点击和回车，不用界面快照代替表单行为。 |
| A7、A9 | 保留真实 API 签发和兑换主路径，验证成功不自动登录、旧密码拒绝以及有会话直接重置；已有身份合同用例拥有服务端会话撤销和单次使用规则。 |
| A8 | 网络拦截注入参数错误、404、429、5xx、响应丢失、200 空体、200 JSON 和 202 JSON；非约定成功响应不能显示成功或自动重提，429 显示等待提示并保留输入；延迟响应期间切页或重新登录，检查晚到响应不污染新页面和会话。 |
| S5（A11） | API 契约用例对注册、登录与重置码兑换分别连续失败到上限：断言 429 带 `Retry-After`、等待结束恢复、等待期内正确凭据同样被拒、成功尝试不累计失败；同一邮箱存在与不存在时响应一致，重置码不存在与已用时响应一致；来源与身份两维各自都能触发上限；关掉缓存时按既有无缓存行为放行，不断言“已限制”。 |

浏览器实施先新增能在旧实现上失败的页面分离及导航用例，再实现，并将[客户自助用例](../../apps/web/e2e/portal-self-service.spec.ts)和[运营开户用例](../../apps/web/e2e/admin-opens-a-customer.spec.ts)从“登录页直接填重置码”迁移为找回、重置、返回登录路径，补确认密码输入。尝试限制的证据落在 [API 契约用例](../../apps/api/tests/http_contract)（状态码、`Retry-After`、两维计数与无缓存放行）上，浏览器只断言页面把 429 显示为可读的等待提示。精确测试命令在实施时根据最终用例集合确定，按[Web 规则](../../apps/web/AGENTS.md)使用同一命令连续两次通过、不靠重试；本设计稿没有执行测试证据。若不改后端，不重复运行全量 Rust 测试。
