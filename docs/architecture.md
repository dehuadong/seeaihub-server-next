# 架构治理

本文拥有本仓库的架构治理：分层、每层的职责与更新方式、依赖方向、层间边界规则与扩展纪律。它陈述当前生效的约束，不承载文件、数据表、端点与迁移的清单——那些落点由源码、`migrations/` 与各模块自己的文档承载；行为合同与持久决定也不在这里。

## 1. 分层与依赖方向

```text
① Model Protocol  对外路由、请求与响应外壳、对外生命周期
② Adapter Driver  一个渠道一族：调用路径、封装格式、响应解析、证据提取、错误分类、轮询与取图
③ Model Profile   型号的调用方参数合同，与该供给能承载的参数面
④ Offering        把合同绑到可售供给：渠道、上游模型名、用哪个 Driver、渠道限制、路由档位与档内权重
⑤ Price           计价形态、费率与单价、币种、折算率、保底与结算口径
```

依赖方向是单向的：进程依赖应用层，应用层依赖领域层；基础设施反向实现应用层声明的端口，应用层不认识任何具体基础设施。领域层只有稳定类型与状态规则，不依赖数据库、HTTP 与渠道。因此换数据库、加渠道都不牵动领域层。

层与目录的对应：① 在 `apps/api` 的 HTTP 层，② 在 `crates/adapter-*`，③④⑤ 是运行时发布物，应用层与领域层在 `crates/application` 与 `crates/domain`，基础设施实现与异常对账外壳在 `crates/persistence`、`crates/cache-redis`、`crates/alert-webhook` 与 `apps/worker`。

## 2. 每层拥有什么、怎么更新

| 层 | 拥有什么 | 更新方式 |
| --- | --- | --- |
| ① | 对外路由与请求/响应外壳、对外生命周期 | 代码发版 |
| ② | 一个渠道一族的全部渠道差异 | 代码发版 |
| ③ | 型号的调用方参数合同与该供给的承载面 | 运行时版本发布 |
| ④ | 供给、路由档位与档内权重 | 运行时发布 |
| ⑤ | 计价形态、费率与单价、折算率、保底 | 运行时发布与动态配置 |

③④⑤ 是数据，随不可变运行时修订发布；请求与执行固定受理时的版本。① 的对外形状不随渠道变化。

## 3. 边界规则

**R1 · 上游的传输与响应形态全部封装在 ②。** 上游是同步响应还是任务式轮询、回 Base64 还是 URL、回 token 还是金额，都是 ② 的内部实现：不产生领域类型分支、不改状态机、不改表结构。调用方可见的参数名与布局不属于 ②，那是 ③ 的合同与供给参数映射的职责；② 只按已经定形的参数装载传输。

**R2 · 对外生命周期只有一种。** 上层只认平台自己的生命周期与查询方式；上游是同步还是任务式都不改变它。

**R3 · 型号与供给是数据，不是代码。** 新增渠道或型号不触发领域模型与数据面的编译或迁移，发布新的 ③④⑤ 即可。

**R4 · 钱的形态由 ⑤ 声明，证据由 ② 归一提取。** ② 把上游响应归一成该供给声明的计价形态所需的证据；计价规则不写进 ② 的代码，上游声明的金额是证据，不是平台自算的替代。

**R5 · 厂商身份与渠道调用身份分开。** 型号的稳定身份用于合同与执行固化；供应商实际调用的模型字符串由 ④ 携带、只有 ② 使用，渠道调用身份不回显到对客面。

## 4. 外部服务适配器

平台自己调用、但不供应任何型号的外部服务（对象存储等）落成独立实现：实现应用层声明的端口，自己拥有该服务的协议、签名与传输的有界性，不读环境变量、不认数据库。这类适配不进运行时修订、不参与选路，与 ② 并列而不属于 ② 的一支。判定看事实属谁：上游的调用路径与响应形态属 ②；平台自选外部服务的协议与凭证属这一类。

## 5. 执行与事实的不变量

- PostgreSQL 是业务事实权威；缓存不是事实来源，缓存不可用只算降级。
- 执行事实与账务入 PostgreSQL，业务载荷只在内存；图片不落盘，请求里的图就是参数值，结果按渠道原形回。
- 创建请求绝不重发；上游创建结果不确定时进对账态由人处置，不自动重提。
- 执行期间不持有数据库连接与事务；跨进程恢复只由异常对账承担，它不领取生成任务、不重发生成请求。
- 模型、供给、渠道与价格经不可变修订发布；请求与执行固定受理时的版本。
- 渠道凭证只从环境变量读取，不进配置、日志、响应与测试夹具。

## 6. 扩展纪律

- 新增一个渠道族：加 ② 的 Driver，发布 ③④⑤，① 与领域层不动。
- 新增型号或调整参数面：只发布运行时素材，不重新编译。
- 上游对参考图等素材的形态要求，在 ② 内部吸收。
- 改动落到 ① 或领域模型时，必须逐项说明理由。允许的例外只有三类：平台侧的新能力（平台自己新增的约束与索引）、上游事实带来的形态扩展（新事实需要新形态，形态待实测后定）、装配点（按渠道派发的组合工厂）。三类之外不得就地扩模型，应回到规划说明理由。

## 7. 清单与落点

端点由路由与 handler 定义，表结构与写入方由 `migrations/` 与持久化实现的模块文档承载，文件职责由各 crate 自己的文档承载。本文不手抄这些清单。
