# 模型使用文档

本 Spec 拥有模型目录中的说明链接、独立模型使用文档、公共使用文档及其公开访问与版本保证。模型参数规则仍由各模型发布的 `contract` 拥有；生成、上传、收费和重复调用的行为不由本 Spec 改写。

## 1. 范围与读者

读者是使用平台 API 的客户端开发者和读取接口说明的程序。文档回答模型属于哪家厂商、是哪种类型、怎样调用、怎样填写参数、怎样处理素材、成功和失败时怎样处理响应。

模型目录适用于不同厂商及 `image`、`video`、`chat` 类型。首批模型正文覆盖 OpenAI GPT-Image-2.5 的两款现有厂商模型及其平台名称；其他模型按相同结构接入，不新增视频或对话执行端点。

对客使用文档源码放在 `public-docs/`，与 `docs/specs/`、`docs/design/`、`docs/facts/`、`docs/research/` 和 Agent Notes 分开。对客正文不出现这些内部目录、工作项、开发流程、数据库与发布机制、供应商渠道名称或渠道请求示例，也不列内部与渠道资料作为“依据”。客户需要知道的参数含义、调用行为、限制和收费后果在正文直接写清楚。技术依据与上游取证仅由开发工件引用。

## 2. 目录与公开读取

`GET /v1/models` 每条模型增加 `documentation_url`，为同源根相对地址：`/v1/models/{按路径段编码的 name}/llms.txt?version={不透明文档版本标识}`。地址中的名字取同条记录的 `name`；客户端使用返回的地址，不拼路径。既有字段、模型可见性与顺序不变；`revision` 仍是参数合同修订号，不改成文档版本。

`GET /v1/models/{name}/llms.txt?version={version}` 公开读取该名字对应的不可变文档；没有 `version` 时读取当前可调用模型的当前说明。两种请求均无需 API Key。成功返回 `200`，`Content-Type: text/plain; charset=utf-8`，正文为简体中文 Markdown，示例与字段保留协议规定的原文标识。

显式版本读取不以模型当前是否启用为条件：停用、无可用供给或重新发布后，原版本仍可读取。无版本请求沿用目录当前可调用的判据；不可调用或不存在时返回 `404 not_found`。未知或无效版本、版本与名字不匹配同样为 `404 not_found`；读取失败为 `500 internal_error`。错误沿用平台的 `{"error":{"code","message"}}` 结构，不重定向到第三方，不回退到当前版本。

公共文档公开读取：`GET /v1/docs/README.md`（对客入口：怎么查询模型、目录各字段的含义、JSON Schema 怎么读，并索引下面三份）、`GET /v1/docs/authentication.md`、`GET /v1/docs/uploads/images.md`、`GET /v1/docs/http-errors.md`，使用相同正文编码。它们说明平台当前公共规则，不使用模型文档版本，也不承诺历史正文；不存在的文档返回 `404 not_found`，读取故障为 `500 internal_error`。

本节扩展[控制台 Spec](0001-admin-and-customer-consoles.md) V-C11 对公开端点的枚举：模型说明和公共使用文档属于公开只读资源。该条的身份操作与重置凭证保护仍保持不变。

## 3. 模型正文

每个返回的文档只解释对应平台模型。至少包含：平台 `name`、`vendor_id`、`type`、合同修订；实际调用端点、方法、请求编码、同步或异步与流式支持；参数释义和规则；该模型适用的素材处理；最小与典型请求；成功响应；适用状态码与错误处理。

厂商与模型类型不替代调用方式。文档只能给出该模型真实提供的端点与模式；图片说明不用于解释视频或对话。模型族可以共享文档素材，但公开正文中的模型身份、`model` 示例值和参数表必须来自同一次发布。

参数结构与限制从对应 `contract` 生成，包括嵌套属性、必填、枚举、类型、默认声明、数量和长度限制，以及存在的组合约束；有自然语言描述的约束保留原义。文字释义按合同字段路径绑定，不声明合同以外的参数或改变合同范围。默认声明不被写成服务端必然注入的值；不夸大执行期校验保证。

模型需要本地参考图片时，正文说明先调用平台图片上传端点换取公网 URL，再填写该模型实际参数，并链接公共上传文档。仅给该模型支持的素材要求；上传数量、大小、类型与保留语义沿用图片上传 Spec。

正文中的链接可访问对应的公共使用文档与对客入口 `GET /v1/docs/README.md`。错误说明指向平台错误码与实际后果，不要求客户理解渠道内部协议。原请求可能已收费、结果不可重放或结果未知时，保留原幂等键的处理不得省略。

## 4. 版本、发布与兼容

模型说明随同一 Runtime Revision 发布，目录合同和文档地址原子切换。每次发布使用一个新的不透明文档版本标识，最终正文不可原地修改。仅修正文案可以沿用参数合同修订，但仍发布新的说明版本；渠道调整不会向正文增加渠道事实。

历史文档可读取不表示历史模型修订可指定执行。生成请求仍按现有受理规则执行，本文不增加按文档版本或合同修订调用的功能。

首次开放新字段之前，所有当前可调用模型须有匹配文档；覆盖不足时不得隐藏模型、返回伪造正文或改变原模型集合，应补齐实际范围后再切换。新发布缺少文档素材、字段释义不完整、字段名与合同不一致或模板无法生成最终正文时，发布在生效之前被拒绝，旧发布保持有效。素材准备属于工程侧，不给运营发布表单增加技术字段。

本次不建立文档网站、运营编辑器、多语言、全局文档全文接口或第三方文档代理；不发起计费验证、不改参数校验、选路、价格、结算、生成和上传接口。

## 5. 验收条件

| 编号 | 判据 |
| --- | --- |
| A1 | 同一目录响应中每条模型有可读的 `documentation_url`；既有字段、模型集合与顺序不变，目录仍无需鉴权。 |
| A2 | 按 URL 无鉴权读取成功，状态和编码符合 §2；正文身份、合同修订与对应目录记录一致。平台别名出现在标题、`model` 示例及身份字段中，不额外暴露厂商原生名。 |
| A3 | 文档参数表与同版合同一致；嵌套字段、必填、默认声明、枚举、范围、数组与组合约束均能读到。缺少释义或引用不存在字段的素材发布失败。 |
| A4 | 同一模型经不同渠道供应时，对客正文不出现渠道名称、字段包装、地址或任务流程。公开正文及全部公开文档链接中没有内部 Spec、RFC、ADR、Agent Note、源码、测试、工作项或渠道取证。 |
| A5 | 图片文档能按公共上传说明先取得 URL，再按模型字段提交；上传、认证与错误说明齐全，无须读取开发文档即可完成调用。 |
| A6 | 目录读取后重新发布，原 URL 仍返回原正文；新目录返回新 URL；合同修订未变的文案修正也产生新文档版本。 |
| A7 | 停用模型后，无版本读取为 404，已知旧版本仍为 200；错误名字、未知/无效版本和错配名字为 404，不回退到新正文。 |
| A8 | 发布失败不改变目录或旧正文；素材文件后续修改不改变已发布正文；全部读取不调用 Provider。 |
| A9 | 使用离线夹具分别验证不同厂商和 image/video/chat 的身份与文档隔离，不把类型推导成未经提供的调用端点；验证含空格、斜杠、中文及 URI 保留字符的合法模型名的链接往返。 |
| A10 | 旧模型全部补齐说明后，切换前后目录模型集合一致；缺少正文时阻止切换，不靠隐藏模型通过 A1。 |
