# 账户名称与客户邮箱登录

本文补充[控制台 Spec](0001-admin-and-customer-consoles.md) 的 M5、C1、C13–C15 与[客户控制台设计](../design/0014-customer-console-navigation-and-history.md) §1 的账户设置页；该 Spec 同时以 **v17** 修订把名称加进它的既有读与账户设置页清单，本文只定名称本身的规则。其余认证、资金、密钥、详情导航与一账户至多一个邮箱登录身份的合同不变。本文件的账户名称、开户表单和查找规则在接受前不覆盖既有行为。

## 1. 概念与范围

账户承载资金、API Key 与使用历史，可以没有邮箱登录身份。账户名称是识别该账户服务对象的名称，可以是个人、工作室、公司或项目名称，不代表经验证的法律主体；它是账户资料，**每个账户始终有一个名称**：创建时由调用方给出或由服务端自动生成，之后由运营或客户本人修改。登录邮箱用于登录；账户标签用于既有 `user_tag` 路由策略；两者均不代替账户名称。

## 2. 账户名称规则

| 编号 | 行为 |
| --- | --- |
| N1 | 名称属于账户，独立于邮箱身份与路由标签，**在全部账户里唯一**（含平台账户）：唯一性**区分大小写**，`Star` 与 `star` 是两个不同的名称，只有逐字符完全相同的名称才算同一个。账户 id 仍是唯一定位标识。运营与**该账户的客户本人**都能把名称改成另一个**未被占用**的名称。名称不参与认证、授权、路由或金额计算。 |
| N2 | 名称去掉首尾 Unicode 空白后必须为 1–100 个 Unicode 字符。字符集是**除了 Unicode 控制字符（`Cc`，含换行、制表与 `U+007F`）与格式字符（`Cf`）之外的一切**——中文、各语种文字、emoji、内部空格、数字与标点都允许；`Cf` 里只给两个例外：emoji 组合要用的零宽连接符 `U+200D` 与零宽非连接符 `U+200C`。显式提供空白、空串或 `null` 返回参数错误；**不能清空已有名称**；内部连续空格原样保留，不压缩。 |
| N3 | **名称留空时由服务端自动生成**（生成在创建事务内、只此一处），并按顺序尝试候选，取第一个**未被占用**（N1）的结果：① 有登录邮箱且本地部分可用时，取 `@` 之前的本地部分并去掉首尾空白，截到不超过「100 减去后缀长度」个字符（保留前若干字符），拼 `_` 与账户 id 前 4 位（小写十六进制），例：`zhangsan@example.com` → `zhangsan_3f9a`；这一形式撞名时，把 id 片段依次加长为 6、8、12、16 位再试。② 上述形式全部撞名（或没有邮箱、本地部分为空或含 N2 拒绝的字符）时，用 `账户_` 与账户 id 前 8 位，例：`账户_3f9a2b1c`；撞名时同样依次加长为 12、16 位。候选全部撞名（实际不可能）时创建失败并报冲突。生成结果必须满足 N2。自动生成的名字与手填的名字没有任何区别，可以随时改。生成不使用路由标签，也不使用日期或序号。邮箱先按仓库既有规则小写化。 |
| N4 | 管理端新建账户与“新建账户并开通邮箱登录”表单的名称是**可选**字段，留空即用 N3 的生成值；输入框提示留空将自动生成。客户邮箱自助注册不给名称输入，服务端按 N3 生成。因此**不存在“未命名账户”状态**，任何读接口都不返回空名称。 |
| N5 | 修改名称成功后，账户列表、账户详情、客户登录列表与详情、以及客户控制台都显示当前值；不改变账户 id、标签、余额、资金流水、密钥、登录凭据和使用历史。修改失败时保留原值并给出可重试错误。运营与客户本人同时改同一个账户时按**后写覆盖**处理，不引入版本协商，也不把这种并发当成失败。 |

| N6 | **撞名是冲突，不是校验错误**：创建或改名时给出的名称与**另一个账户**的名称逐字符完全相同（区分大小写）时，服务端返回冲突（`409`），且**不产生任何写入**（账户、身份、资金、名称都保持原状）。自动生成的路径不把冲突交给调用方：服务端按 N3 自己换更长的 id 片段，只有候选全部撞名才失败。改名成自己当前的名称等于没改，不算冲突。生成名称撞名重试与唯一性判定都在服务端同一处完成，前端只如实呈现结果。 |

“Unicode 字符”按 Unicode scalar value 计数，前后端遵守同一规则。

## 3. 创建与开通登录

### 3.1 创建账户，暂不开通邮箱登录

管理端“创建账户”表单包含可选账户名称、可选路由标签和可选初始充值；空充值按零处理，金额继续遵循既有规则。说明文字为“创建账户，暂不开通邮箱登录；可先充值、签发 API Key，之后再开通登录”。

| 编号 | 行为 |
| --- | --- |
| F1 | 取消不产生任何写入。确认后，名称（给予的或生成的）、可选标签、账户及初始充值作为一次创建成立；确定的校验或事务失败不留下部分账户或充值。成功进入账户详情，并能按名称查到。 |
| F2 | 提交过程中禁止重复点击。响应未知时不得显示“创建失败，重新创建即可”，应提示先查找确认；不承诺网络重试的创建幂等性。 |

### 3.2 开通邮箱登录

管理端身份页面标题、导航和入口用“客户登录”“开通邮箱登录”，内部地址不变。表单显式选择下列模式，初始选择“新建账户”：

| 模式 | 输入与说明 |
| --- | --- |
| 新建账户并开通邮箱登录 | 必填登录邮箱，可选账户名称与初始口令；名称留空即按 N3 用该邮箱生成。新账户初始余额为零。账户与邮箱身份一起创建。 |
| 为已有账户开通邮箱登录 | 必填已有账户 id 与登录邮箱，可选初始口令；不显示可编辑的账户名称或初始充值。 |

已有账户模式按完整 id 读取账户摘要，显示名称、完整 id、当前登录邮箱状态，并明确告知绑定保留余额、API Key 与历史。

| 编号 | 行为 |
| --- | --- |
| F3 | 已有账户必须存在且尚未绑定邮箱身份；预览未成功或显示已绑定时不能提交。换 id 立即清除旧预览，只有当前 id 的成功响应可用于确认。提交时服务端重新校验，不以预览代替最终校验。 |
| F4 | 绑定已有账户只增加邮箱登录身份，不创建第二个账户，**不覆盖已有名称或标签**，也不改动资金、密钥与历史。若请求同时提供已有账户 id 与账户名称，返回参数错误。 |
| F5 | 邮箱重复或目标账户已绑定返回冲突；不存在返回找不到。两个管理员同时绑定同一账户，至多一个成功；失败不留下游离身份或新账户。 |
| F6 | 初始口令与重置令牌仍遵循控制台 Spec C12/C14；不填口令不等于无口令可登录，不自动签发令牌。成功进入对应客户登录详情，保留现有人工签发和转交重置令牌方式。 |

## 4. 管理端与客户端的展示与查找

| 编号 | 行为 |
| --- | --- |
| U1 | 账户列表和详情同时展示账户名称、账户 id、登录邮箱、路由标签；无邮箱时显示“未开通邮箱登录”。账户名称是主要识别文字，完整 id 仍可查看与复制。标签保留独立编辑与清空能力。 |
| U2 | 账户列表增加名称筛选，按大小写不敏感的字面子串匹配；`%`、`_` 作为普通字符。查询首尾空白忽略，空查询不筛选；非空查询最长 100 个 Unicode 字符且不含控制字符。名称、原有精确邮箱筛选、原有精确标签筛选同时给出时按“与”处理；完整账户 id 直达继续有效。 |
| U3 | 沿用现有列表顺序与条数上限，不增加分页承诺。名称唯一（区分大小写），但子串查询仍可能命中多个不同的账户（例如都含“工作室”，或只差大小写）；搜索结果始终显示 id 与登录邮箱，运营须确认对应账户后操作。返回列表和刷新沿用既有筛选恢复规则，名称筛选不进入页面 URL。 |
| U4 | 客户登录列表及详情同时展示登录邮箱、关联账户名称和账户 id；名称取自关联账户当前值（含客户刚改过的值），不另存“客户姓名”。关联账户入口与既有详情地址继续有效。客户登录页仍按邮箱查找。 |
| U5 | 账户详情增加独立的名称编辑操作；保存后重取摘要，保存过程禁止重复提交。名称展示按文本渲染，不解析 HTML。管理认证、找不到状态与撞名冲突（`409`）沿用既有错误呈现：留在原页、显示冲突原因、保留原名称让运营换一个。 |
| U6 | 客户控制台的“账户设置”页展示**自己的账户名称**并可修改：字段为普通文本输入，说明文案固定为“账户名称用于识别与账单，可随时修改”；保存成功后页面显示新值，保存失败（含撞名冲突 `409`）保留原值并可重试，输入框回到已保存的那一份。页面只呈现名称本身，**不解释自动生成的规则**（不提账户 id 片段、不提邮箱拼接），也不区分“系统生成的”和“自己改的”。客户只能改自己账户的名称，改不动别人的账户；名称不参与登录，改名称不影响会话与凭据。 |

## 5. 接口与兼容边界

| 接口 | 增量合同 |
| --- | --- |
| `POST /api/v1/accounts` | 保留必填 `initial_credit_microusd` 与既有响应，增加可省略 `name` 和 `tag`。省略 `name` 时按 N3 生成（生成名撞名由服务端自己换候选，不返回冲突）；提供的标签遵循既有规则。名称与标签同创建提交。提供的名称已被占用时返回 `409`。 |
| `POST /api/v1/customers` | 增加可省略 `account_name`。省略 `account_id` 时为新建账户的名称，留空即按 N3 用该邮箱生成（生成名撞名自动换候选）；提供 `account_id` 时不能提供 `account_name`。提供的名称已被占用时返回 `409`，不留下任何身份。 |
| 账户列表与账户摘要 | 增加 `name: string`（非空）。账户列表增加可选 `name` 查询参数。 |
| 管理端客户视图 | 开户、按邮箱查找、列表、按 id 读取均增加 `account_name: string`（非空，关联账户名称的当前读数）。 |
| `GET /v1/customer/account` | 增加 `name: string`（自己的账户名称）。余额字段与形状不变。 |
| `PUT /api/v1/accounts/{account_id}/name` | 仅管理员可写，正文 `{ "name": "名称" }`；成功返回 204，账户不存在返回 404，名称非法返回 400，名称已被别的账户占用返回 `409`，未认证沿用 `403 admin_forbidden`。 |
| `PUT /v1/customer/account/name` | 仅客户会话可写，正文 `{ "name": "名称" }`，只作用于会话自己的账户；成功返回 204，名称非法或试图清空返回 400，名称已被别的账户占用返回 `409`，没有会话沿用既有未认证行为。 |

名称唯一性是**合同要求**（区分大小写、覆盖全部账户），并由服务端在每次创建与改名时判定；撞名的错误码是 `name_taken`，与邮箱、账户绑定冲突的 `conflict` 分开——界面据此说对要换的是哪一个参数。唯一性的落地方式（约束、迁移与开发库已重名行的处理）归[设计 0015](../design/0015-account-names-and-login-identities.md) §2.1/§2.3。名称只在账户资料读里出现，不进入登录、会话或图片生成请求；对客余额读、凭据响应与资金响应形状除客户账户读新增 `name` 外保持不变。所有新增管理读写均使用既有管理认证，对客改名使用既有客户会话认证；审计记录名称的创建者与修改者（管理员或客户）、账户 id、旧值与新值，不记录口令或令牌。

## 6. 验收条件

| 编号 | 可观察判据 | 对应规则 |
| --- | --- | --- |
| V1 | 新管理表单不填名称也能提交，创建后详情显示 `账户_<id 前 8 位>` 形式的名称；填了名称则用填的。取消不创建；提交中不能重复点击；响应丢失时提示先查找确认；确定的事务失败没有账户或资金残留。 | N3/N4、F1/F2 |
| V2 | 无邮箱账户可按名称子串查到；含 `%`、`_` 的搜索只作字面匹配；大小写不敏感；命中多个不同名账户时都列出并可凭 id 区分。邮箱／标签与名称组合按“与”筛选。 | N1、U1–U3 |
| V3 | 名称首尾空白被去掉；空白、超过 100 字符、`Cc`（如 `U+0009`、`U+000A`、`U+007F`）与 `Cf`（如 `U+202E`）被拒；中文、韩文、emoji 组合序列（含 `U+200D`）与内部连续空格被接受且前后端判定一致。自动生成的名称同样满足这些规则；邮箱本地部分超长时按“100 减去后缀长度”截断（首选后缀留 95 个字符位，id 片段加长则更短），含被拒字符时回退为 `账户_<id 前 8 位>` 形式。 | N2/N3 |
| V4 | 新账户模式：名称留空时按登录邮箱生成 `<本地部分>_<id 前 4 位>`；同时建立零余额账户和邮箱身份。绑定已有账户模式预览当前对象并保留原名称、标签、余额、Key 和历史。提交旧预览或已绑定对象被阻止。不填初始口令时不自动签发重置令牌，客户仍按 C12/C14 由运营签发并转交后自行设置口令。 | N3、F3–F6 |
| V5 | 重复邮箱和并发绑定产生明确冲突；失败不留下新账户或身份；已有 id 与名称同时提供返回参数错误。 | F4/F5 |
| V6 | 客户在“账户设置”里改自己的账户名称，保存后客户页面与运营台的账户列表、账户详情、客户登录详情都显示新值；运营改名称后客户页面也显示新值。两处改名都不改变路由标签、余额、资金、密钥与凭据；名称不能被清空。 | N5、U4–U6 |
| V7 | 客户邮箱自助注册后账户即有一个按邮箱生成的名称（无需运营补录）；任何账户读接口都不返回空名称；迁移已存在的开发库行后，账户数量、邮箱绑定、标签、资金、密钥和历史不变且每行都有名称。 | N3/N4、§5 |
| V8 | 新管理接口未认证被拒、不存在为 404；客户会话只能改自己账户的名称，改别人的账户被拒且不产生写入；新筛选可恢复，列表与详情地址、一次性明文和资金操作维持现有行为。 | U3/U5/U6、§5 |
| V9 | 管理端称谓与提示按 §3 固定：身份页面标题、导航与入口用“客户登录／开通邮箱登录”，“创建账户”表单的说明文字包含“暂不开通邮箱登录”，名称输入框提示留空将自动生成；客户控制台账户设置页的名称说明是“账户名称用于识别与账单，可随时修改”，页面上没有解释生成规则或内部机制的文案。 | N4、U6、§3 |
| V10 | 名称唯一（**区分大小写**）：创建或改名撞上另一个账户**完全相同**的名称返回 `409` 且不产生任何写入；只差大小写的名称是**两个**名称，可以并存；改成自己当前的名称等于没改，不算冲突；自动生成的路径在首选名称被占用时自己换更长的 id 片段并创建成功（含两个同本地部分邮箱的账户各得一个唯一名称）；迁移落地后开发库里不存在完全相同的名称。 | N1、N3、N6、§5 |

## 7. 非目标

不增加独立 CRM 客户主体、组织成员、多邮箱登录、登录邮箱修改、账户合并、在线支付、账户搜索分页或创建幂等协议；不做名称内容审核、名称历史版本、名称预占或改名冷却；不改平台账户是否出现在账户列表的现状；不将标签转换为名称；不提供按名称登录或按名称认证；不调整余额口径、路由策略或历史游标密钥配置。
