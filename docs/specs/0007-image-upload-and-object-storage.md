# 图片上传与对象存储

本 Spec 拥有上传端点对调用方的行为合同、上传素材的公网 URL 语义，以及对象存储渠道的公开配置、健康判据、激活语义与管理端端点。生成请求内图片值的形态、载荷边界与执行合同由[同步图片网关 Spec](0005-synchronous-image-gateway.md)拥有；金额、余额与计费由[账户资金 Spec](0002-account-funds-and-reservations.md)拥有。技术实现由[对象存储上传设计](../design/0021-object-storage-upload.md)承接。

## 1. 范围与边界

上传端点解决的是"调用方手上是本地文件、而生成接口只收公网 URL"这件事：调用方先把文件交给平台写入对象存储，拿到公网 URL，再用它调生成接口。

上传与生成是两次独立调用。上传不绑定后续生成请求、不接受 `model` 或生成参数、不校验素材会被哪个模型接受，也不产生执行记录、资金占用与账单：不计费、不计量、不限配额。生成接口不替调用方上传：本平台没有隐式上传，只有调用方显式发起的上传。

生成接口侧的形态与它一致：参考图与遮罩只收 `http(s)` 公网 URL，`data:` URL 与 multipart 文件部件在受理前被拒（[同步图片网关 Spec](0005-synchronous-image-gateway.md) §3）。

平台不提供预签名读取、私有桶读取、保留期与过期删除、批量上传、视频与音频上传，也不把上传结果做成异步任务。上传只有客户 API 端点与管理端的渠道页，客户控制台没有上传页面。对象在对象存储里的保留与删除由对象存储控制台管理：平台既不承诺保留期，也不代调用方删除或续期。

## 2. 上传端点

调用方提交 `POST /v1/uploads/images`。

### 2.1 鉴权与准入

用平台客户 API Key 鉴权，与生成接口同一套凭证与校验；无效凭证返回 `401 invalid_api_key`，且发生在读取正文之前。认证之后、消费正文之前取本机上传读取许可，取不到返回 `429 upload_busy`，不排队等待。请求级速率沿用既有口径，超限返回 `429 rate_limit_exceeded`。

### 2.2 请求

请求体是 `multipart/form-data`，恰好一个文件部件，字段名 `file`。缺少 `file`、出现除 `file` 以外的部件、或 `file` 没有文件名时，返回 `400 invalid_multipart`。一次请求一个文件，本端点不做批量。

声明的 `Content-Length` 超过请求体上限即在零正文读取的情况下返回 `413 request_too_large`；流式读取的同一上限同样返回 `413`；正文慢读超时是受理前的 `408 request_timeout`。

### 2.3 成功响应

成功返回 `200` 与一个对象：

| 字段 | 含义 |
| --- | --- |
| `url` | 平台写入该素材后的公网可读 URL（§6） |
| `media_type` | 服务端按内容判定的规范 MIME，不取调用方声明的值 |
| `byte_length` | 实际写入对象的字节数 |

响应没有 `expires_at` 一类字段：返回的 URL 不带签名、不带过期参数。`200` 表示对象已写入当前激活渠道的桶，且写入内容与服务端提交的字节一致。

## 3. 大小与类型上限

| 项 | 判据 | 失败 |
| --- | --- | --- |
| 单文件字节 | 严格小于 20 MiB（20971520 字节） | `413 image_too_large` |
| 请求体字节 | 单文件上限加 multipart 协议余量，上限值由服务端配置 | `413 request_too_large` |
| 文件类型 | JPEG、PNG、WebP | `400 unsupported_media_type` |
| 声明与内容一致 | 文件部件声明的 `Content-Type` 等于内容魔数判定的规范 MIME | `400 media_type_mismatch` |

扩展名只用于白名单与类别判定，规范 MIME 由内容魔数决定；调用方的文件名与扩展名不决定对象类型。0 字节文件因魔数无法识别，按 `400 unsupported_media_type` 拒绝。

单文件上限是固定值，不随部署配置变化。

校验在写入之前完成：被判不合规的文件不写入对象存储。视频与音频不在本端点受理，即使它们的字节形态能被识别。

生成侧对输入参考图的数量限制（`max_reference_images`）不约束上传：上传不校验张数，也不判断素材会被哪条供给接受。

## 4. 对象键与写入

对象键是 `reference-media/{YYYY-MM-DD}/{uuid}.{ext}`：日期取写入时的 UTC 日期，`uuid` 是随机 v4，`ext` 由规范 MIME 反推。调用方给的文件名不进对象键、不进对象元数据。

写入禁止覆盖同名对象，键按随机唯一构造，正常不会相撞。相撞是平台侧异常，按 §5 的平台侧错误回应：不换键重写、不覆盖既有对象。

写入请求必须签名，签名材料由服务端生成；签名密钥只从部署侧环境变量读取，不入库、不进日志、不进响应、不进测试夹具。

写入之后按对象元数据核验字节长度与内容类型，与提交的字节不一致即失败关闭，不返回 URL。平台不读回、不修改、不删除已写入的对象。

## 5. 失败、错误码与重试

| 情况 | HTTP | 错误码 |
| --- | --- | --- |
| 凭证无效或缺失 | `401` | `invalid_api_key` |
| 非 multipart、缺 boundary、部件不符 §2.2 | `400` | `invalid_multipart` |
| 类型不在允许范围、0 字节、魔数无法识别 | `400` | `unsupported_media_type` |
| 声明的 `Content-Type` 与魔数不一致 | `400` | `media_type_mismatch` |
| 单文件达到或超过 20 MiB | `413` | `image_too_large` |
| 请求体超过上限 | `413` | `request_too_large` |
| 正文慢读超时（受理前） | `408` | `request_timeout` |
| 请求级速率超限 | `429` | `rate_limit_exceeded` |
| 本机上传并发满 | `429` | `upload_busy` |
| 没有激活渠道，或渠道配置不可用 | `503` | `upload_channel_unavailable` |
| 对象存储不可达、超时、`5xx`、限流重试耗尽、对象键相撞 | `503` | `upload_storage_unavailable` |
| 客户端断开 | `499` | `client_disconnected` |
| 其他服务端故障 | `500` | `internal_error` |

只有可重试失败才重试写入：网络错误、`408`、`429` 与对象存储 `5xx`。总尝试次数有上限；对象存储给出有界整数秒 `Retry-After` 时按它等待，否则按固定退避。上限与退避基准由服务端配置，具体取值在实施时定，取值不改变本节的语义。已确认写入成功的对象不再重复写入。

重试用同一个对象键，因此一次调用至多有一个成功写入的对象。写入超时且对象实际已经落盘时，那个对象成为无人引用的孤儿，按 §1 由对象存储控制台管理——平台不为它返回 URL，也不删除它。

上传失败不改动调用方账户：不计费、不占资金、不建执行记录。错误响应只给稳定错误码、HTTP 状态与有界的脱敏诊断（阶段、对象存储状态码、请求标识）；密钥、签名与对象字节不进响应、日志、trace 与告警。

## 6. 公网 URL 的语义与有效性

返回的 URL 形态是 `https://{bucket}.{endpoint-host}/{object-key}`，不带签名参数、不带过期时间。任何持有该 URL 的一方都能匿名读到对象；URL 本身不含凭证，分享 URL 等于分享图片内容。

平台承诺的有效性边界是：对象未被删除、桶保持公网可读、渠道公开配置（region、bucket、endpoint）未改动时，该 URL 继续可读。桶的匿名可读是激活判据的一部分：§7.2 健康检查的最后一步用不带凭证的客户端读探针对象，读不到就不激活该渠道。因此桶配错时不会出现"上传返回 `200`、返回的 URL 却读不到"这种组合——渠道根本进不了激活态。

平台不承诺 URL 长期有效、不承诺对象保留期、不提供删除与刷新；需要长期保存素材的调用方自行留档。改动渠道公开配置（换桶或换 region）不迁移既有对象：旧 URL 指向旧桶，其可读性由旧桶的配置决定。

## 7. 上传渠道的公开配置、健康判据与激活

### 7.1 公开配置与密钥

渠道的公开配置是 region、bucket 与 endpoint，由管理员在管理端填写并入库；endpoint 省略时按 region 派生官方公网端点，显式给出时必须等于派生值。公开配置里出现白名单之外的字段或取值不合法时，写入被拒并返回 `400 invalid_public_config`。

密钥（访问密钥标识与访问密钥）只从部署侧环境变量读取。公开配置或密钥不完整时该渠道不可激活，管理端按"未配置"展示。

### 7.2 健康判据

健康检查对不可变的配置快照执行，用服务端生成的最小合法 PNG 探针对象，不读取调用方文件：

1. 向目标桶写入探针对象，同样禁止覆盖；
2. 读取探针对象的元数据，核验字节长度与内容类型与写入一致；
3. 用 header 模式签名的 GET 读回探针对象，返回的字节与写入的字节逐字节相同；
4. 用不带任何凭证的客户端 GET 探针对象的公网 URL，必须成功且返回的字节与写入的字节逐字节相同。

四步全过才算健康。任一步失败即判不健康，并给出脱敏的失败说明（阶段、对象存储状态码、请求标识）。探针对象使用独立对象键，不复用调用方素材的键。第 4 步判的是对外返回的那个公网 URL 真的匿名可读，不是桶的权限配置本身。

### 7.3 激活语义

激活按检查所依据的配置快照原子提交：检查通过、且该渠道行在检查期间未发生变化才切换；行已变化返回 `409 upload_channel_conflict` 且不切换。切换后任意时刻恰好一个渠道处于激活，没有零激活的窗口。

检查不通过返回 `409 upload_channel_activation_failed`，原来的激活渠道与它的配置不变。停用唯一激活渠道被拒（`409`），服务端不进入"没有可用渠道"的状态。

上传只走激活渠道。没有激活渠道时上传返回 `503 upload_channel_unavailable`，不写任何对象。健康结论只在激活时产生：平台不按周期自动探测，也不因健康结论自动停用渠道。

## 8. 管理端端点

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/v1/upload-channels` | 列出渠道：公开配置、密钥是否配置、是否激活、最近一次健康检查的结论与时刻 |
| PUT | `/api/v1/upload-channels/{id}` | 写入公开配置（region、bucket、endpoint）与名称 |
| POST | `/api/v1/upload-channels/{id}/activate` | 按不可变配置快照做健康检查，通过则原子激活 |
| POST | `/api/v1/upload-channels/{id}/deactivate` | 停用；唯一激活渠道被拒 |

这些端点认管理员，响应永不包含密钥或签名材料。渠道行由迁移种下一行 `aliyun_oss`，管理端只改它的公开配置与激活状态，不提供新建渠道。

## 9. 验收条件

| 编号 | 可观察判据 |
| --- | --- |
| A1 | 没有激活渠道时上传返回 `503 upload_channel_unavailable`，对象存储没有新对象；渠道公开配置或密钥不完整时不能被激活。 |
| A2 | 激活后上传一张合法 PNG 返回 `200`，`media_type` 是服务端判定的 `image/png`；用无凭证的客户端读返回的 `url` 能取到与上传一致的字节。 |
| A3 | 单文件字节严格小于 20 MiB 通过、等于 20 MiB 返回 `413 image_too_large`；声明长度超过请求体上限时零正文读取返回 `413 request_too_large`。 |
| A4 | 白名单外的类型、0 字节文件、魔数与声明 `Content-Type` 不一致都在写入前被拒（`400`），对象存储没有新对象。 |
| A5 | 对象键形如 `reference-media/{UTC 日期}/{uuid}.{ext}`，不含调用方文件名；同一次上传的两次调用产生不同的键。 |
| A6 | 无效 API Key 返回 `401 invalid_api_key` 且不读正文、不写对象；速率超限与本机并发满分别返回 `429 rate_limit_exceeded` 与 `429 upload_busy`。 |
| A7 | 健康检查四步中任一步失败都不激活（含不带凭证的客户端读不到探针对象），原激活渠道与配置不变；检查期间渠道行变化返回 `409 upload_channel_conflict`；通过后原子切换，任意时刻只有一个激活渠道。 |
| A8 | 停用唯一激活渠道被拒；公开配置写入含白名单外字段或非法 endpoint 返回 `400 invalid_public_config`；`GET /api/v1/upload-channels` 的任何响应都不含密钥。 |
| A9 | 上传前后账户余额、资金占用、执行记录条数与账本条目不变：上传不计费、不计量、不限配额，也不产生执行记录与账目。 |
| A10 | 对象存储返回可重试错误时按同一对象键重试；重试耗尽返回 `503 upload_storage_unavailable`，日志、trace 与响应不含密钥、签名与对象字节。 |
