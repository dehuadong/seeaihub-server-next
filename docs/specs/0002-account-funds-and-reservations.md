# 账户余额、预授权与实际收支

本文件规定消费者账户的余额、预授权、扣费与账务查询行为。对客价格和计量证据仍按[定价与结算设计](../design/0007-pricing-floor-and-settlement.md)及[结算证据门槛](../adr/0006-no-settlement-without-metering-evidence.md)确定；本文件只规定金额何时改变、占用如何判定以及用户和运营看到什么。

## 1. 金额语义

| 名称 | 定义 |
| --- | --- |
| 已结算余额 | 账户已经确认的资金结果。充值增加它，实际扣费减少它，正式资金调整按金额改变它；预授权不改变它。 |
| 持有中 | 已受理但尚未结清的请求所占用金额之和。它不是扣费，也不是退款。 |
| 可用额 | 已结算余额减去持有中。受理请求只用它判断能否占用本次保底额。 |

对客金额单位是**积分**：1元 = 1000积分（1积分 = 0.001元），对客的已结算余额、持有中、可用额、保底额与实收恒为整积分。平台内部以 CNY 微单位记账，1积分 = 1000 微单位，账上的对客金额因而恒为 1000 微单位的整数倍。预授权额与实收在算定后按绝对值向上取整到整积分再落账；充值、初始充值与正式调整的入账金额也是整积分，写入口收到不是整积分的金额时按绝对值向上取整到整积分。对客读遇到不是整积分的金额时同样按绝对值向上取整，不静默截断；它不是第二套取值面，账上金额仍以 1000 微元的整数倍为准。已结算余额与可用额可以为负：实际扣费高于保底额时允许透支；持有中不得为负。账户创建时三个金额均为零，带初始充值的开户视为同一次真实入账。

## 2. 受理、结算与失败

1. 受理时按命中供给的保底表与请求张数算定本次预授权额（向上取整到整积分），并随 Job 冻结。仅当受理瞬间的可用额不低于该额，才建立请求并增加持有中；不足返回 `402 insufficient_balance`，不建立 Job、不增加持有中、不改变已结算余额。预授权额为零时，已有负可用额仍不能受理新请求。
2. 同一账户的并发受理必须共同遵守同一可用额，不能因同时看见旧余额而超额占用。同一幂等键的重放返回原请求，不再次占用。
3. 成功结算必须先取得可核验计量证据，并按受理时冻结的价格算实际扣费（向上取整到整积分）；随后解除该请求的全部占用，只按实际扣费减少已结算余额。实收可以高于预授权额，差额导致透支；实收低于预授权额时，未花的部分只恢复可用额，不产生退款。实收为零时不产生零金额收支流水。
4. 能确定无需向消费者收费的失败，解除该请求的全部占用；已结算余额不变，不产生消费者收支流水。结果或上游受理状态不确定时，继续占用并进入 `reconciliation_required`，不得自动重提或扣费。人工对账在没有可核验计量证据时只能解除占用并结束请求，不得凭备注或金额确认扣费。
5. 重试、租约恢复、重复收尾及对账操作不得使同一请求重复占用、重复扣费或重复释放。平台已经承担的上游成本归平台账户，不改变消费者的已结算余额。

## 3. 资金流水与请求记录

资金流水只记录实际发生的资金变动：充值、实际扣费、正式调整及平台自担成本。入账金额为正、扣费金额为负，正式调整按资金增减带符号；账务接口继续返回有符号金额。预授权的建立、保留、结清和释放只留在请求与预授权记录中，不作为资金流水。资金流水中的实际扣费必须能关联对应的模型请求；失败且未收费的请求仍能在用量记录中查到，扣费为零。

对账处置若只解除尚未结清的预授权，运营处置记录应写为“解除预授权”，不称为退款，也不产生退款流水。客户资金流水不展示该动作。已经实际扣费后的退款属于正式资金调整，必须改变已结算余额并留下调整流水。

## 4. 查询与缓存

管理员账户读接口返回 `balance_microusd`（已结算余额）、`held_microusd`（持有中）和 `available_microusd`（可用额），三者以 CNY 微单位计，在同一时点满足 `available = balance − held`。对客账户读接口返回同一三个数的积分值（`balance_points`、`held_points`、`available_points`），在同一时点满足 `available_points = balance_points − held_points`。管理员查询可分别显示三个金额。客户控制台只显示**一个**余额数字，标题为「余额」，取 `available_points`（= `balance_points` − `held_points`）：请求受理时按占住的额度减少，结算后按实际扣费多退少补。已结算余额与账户持有中合计不在客户页面分别展示，单笔预授权额与解除预授权的金额也不出现。实际收支以资金流水为准。页面余额不承诺本次请求必能受理，受理仍按扣除处理中占用后的可用额判定，不足沿用 `402 insufficient_balance`。管理员查询与消费者查询读同一份金额事实，单位不同（管理员 CNY 微单位、客户积分）；平台账户不参与消费者预授权与对客余额缓存。

Redis 可以缓存当前金额供预检和非资金判定的读取；不可用或值过期时回源 PostgreSQL。缓存显示充足不能代替数据库最终受理判定；缓存显示不足也不能单独产生 `402`，必须由数据库确认。充值、占用、结算或释放在数据库提交后刷新缓存；缓存写入失败不得改变已提交的资金结果。资金核对直接读数据库，不以缓存为证据。

## 5. 限额、账单与核对

每账户每日消费限额**不设即不限**：设了才按 UTC 自然日的**已完成实际扣费**判定，不把预授权计为消费；达到上限后新请求按既有 `429 daily_spend_limit_exceeded` 拒绝。它是运营可配置的护栏，不是产品档位，也不是单笔扣费上限——正在执行的请求及单笔结算仍可能使当日实际扣费超过该限额。受理检查不得逐次汇总历史资金流水。

区间账单采用 `[since, until)` UTC。扣费与正式调整归属其实际入账时刻；已完成请求和产出张数归属其终态时刻。待完成请求可在用量明细显示为处理中，但不计入已完成请求数和已扣费额。用量明细须区分请求时刻与终态时刻，使跨天结算的扣费能在对应账单区间查到。区间内已完成请求的逐笔有符号扣费合计应等于该区间实际扣费流水合计；正式调整单独列示，对客账单 `charged_points` 等于实际扣费与正式调整的有符号金额之和（积分），负数表示净支出，预授权不参与求和。

账务核对是独立的异常检查，不参与充值、受理、结算或余额读取。核对发现不一致时记录对账案例并告警，不自动改余额；不得默认每 15 分钟对所有账户的全部历史流水重新求和。缓存与数据库之间的副本校正属于另一项检查，不替代账务核对。

## 6. 非目标

- 不改变保底表、对客费率、计量证据、可透支结算与平台自担成本的既有口径；新增的只是落账金额取整到整积分。
- 不引入自助在线支付、账户合并、账户间转账或对结果不确定的请求自动重提。
- 本次没有已上线账务数据的兼容、回填或历史流水转换要求。

## 7. 验收条件

| 编号 | 可判定结果 |
| --- | --- |
| A1 | 充值 100、预授权 30 后，已结算余额为 100、持有中为 30、可用额为 70；实收 20 后依次为 80、0、80。预授权和释放均不产生资金流水。 |
| A2 | 同一账户可用额 100 时两个不同请求并发各预授权 60，最多一个受理；同一幂等键重发不重复占用。 |
| A3 | 实收高于预授权额时只扣实际金额，允许负余额；下一笔即使预授权额为零，负可用额仍返回 402。 |
| A4 | 确定失败和人工对账释放只减少持有中；结果不确定时持有中保持不变；重复收尾不重复释放。 |
| A5 | 成功请求只有一条非零实际扣费流水并指向该请求；零扣费或未收费失败请求仍有用量记录，无零金额资金流水。 |
| A6 | Redis 不可用、过期、乱序或落后于充值时，资金结果仍由数据库决定；缓存不足不得导致未经数据库确认的 402。 |
| A7 | 管理员读到同一时点自洽的已结算余额、持有中、可用额（CNY 微单位）；客户控制台只显示一个标题为「余额」的数字（取可用积分），所有客户页面都不分别显示已结算余额、持有中或单笔预授权金额。充值 100元（100000积分）后客户看到 100000，预授权 30元（30000积分）后为 70000，实收 20元（20000积分，持有中归零）后为 80000；仅释放预授权后回到 100000。实收超过已结算余额时客户看到负数（照实显示，不截断成 0）。 |
| A8 | 每日限额**不设即不限**；设了时检查不扫描历史流水；跨 UTC 日结算的扣费计入结算日。相同区间的已完成用量逐笔扣费与实际扣费流水相等，正式调整单独列示后与账单净额相等。 |
| A9 | 账务核对不在请求路径运行；发现账户金额或占用不一致时只建案和告警，不自动改账，也不默认全库每 15 分钟重算。 |
| A10 | 对客金额恒为整积分：对客账户读返回 `balance_points`、`held_points`、`available_points`，三者是整数且 `available_points = balance_points − held_points`；算定的预授权额与实收按绝对值向上取整到整积分后才落账，充值、初始充值与正式调整的入账金额也是整积分，账上的对客金额是 1000 微单位的整数倍；对客读遇到不是整积分的金额时按绝对值向上取整（`-1500` 微元是 `-2` 积分，不是 `-1`）；管理端读仍返回 CNY 微单位。 |
