# 模型类型与用量记录

本 Spec 拥有模型类型（`type`）的取值、声明位置与对客暴露方式，以及客户与管理员用量记录、账单汇总按类型展示用量的口径。用量事实的产生、结算与金额口径由[定价与结算设计](../design/0007-pricing-floor-and-settlement.md)与[账户资金 Spec](0002-account-funds-and-reservations.md)拥有；控制台页面结构与区间取数由[控制台 Spec](0001-admin-and-customer-consoles.md) C9、C10 拥有。

## 1. 范围与边界

每个 Vendor Model 声明一个类型，取值为 `image`、`video`、`chat`。类型是模型自身的事实，随发布素材声明、随发布物落库，不由运营在发布页填写，也不随渠道、候选或定价变化。

客户控制台的页面名是「调用记录」；它展示的记录、读取端点与响应字段用「用量记录」。本 Spec 描述记录与接口时用后者。

用量按类型给出：图片是本次产出的张数，视频是本次产出的秒数，对话是本次的输入与输出 token 数。不同类型的量不合并、不相加。

展示的仍是本次执行的量，不含结果、原始参数或请求正文，与[同步图片网关 Spec](0005-synchronous-image-gateway.md) A10 的最小用量口径一致。

## 2. 产品范围

- 对客目录 `GET /v1/models` 的每条模型带 `type`，取值是三种之一；客户端据此判断该模型的用量单位与表单参数面。
- 客户用量记录 `GET /v1/customer/usage` 与管理端账户调用明细的每条记录带 `type`，并用 `usage` 对象给出按类型的量。
- 这两条是控制台自己的端点（对客那条只认客户会话，没有 API Key 通路，也没有对外字段承诺）：它们的响应行把 `image_count` 换成 `usage`，不构成对公开 API 的兼容破坏。公开的 `GET /v1/models` 只增字段。
- 客户账单汇总把现有的 `images` 换成同一个 `usage` 对象，按类型分别给出区间内的量：图片是产出张数合计，视频是秒数合计，对话是输入与输出 token 合计；请求数与扣费净额仍按现有口径全量计算。
- 素材未声明 `type`、或声明了三种之外的取值时，导入与发布失败并点名。
- 同一 Vendor Model 修订的类型与它的合同一样不可变：内容不同的重发被拒。

## 3. 非目标

- 不新增视频与对话模型的执行路径、驱动、承载面、计价形态与用量落点。
- 不按类型限制发布、受理或路由；类型不参与目录可见性与"这个模型能不能调"的判据，该判据仍按供给与渠道的启用状态。
- 不把类型当作计费口径：收费仍按发布的对客计价形态与受理时冻结的快照计算。
- 不把不同类型的量相加成单个数：用量记录与账单汇总都按类型分开给出。
- 不因为类型改变 `/v1/images/generations`、`/v1/images/edits` 的请求与响应形状。

## 4. 可观察行为

### 4.1 目录

- 公开目录的每条模型都带 `type`，取值 `image` / `video` / `chat`；既有字段（`name`、`vendor_id`、`revision`、`contract`）的名称与含义不变。
- 目录里的类型来自该模型发布时引用的 Vendor Model。

### 4.2 用量记录

- 每条记录带 `type`，与本次请求受理时引用的 Vendor Model 一致；模型后来重新发布、改绑到别的 Vendor Model，不改变已经受理的记录。
- 用量按类型给出：图片给出本次产出的张数；视频给出本次产出的秒数；对话给出本次输入与输出 token 数。
- 用量放在 `usage` 对象里，键是 `images`、`seconds`、`input_tokens`、`output_tokens`；只有有值的键出现，对象可以为空。
- 某类型还没有对应的量落点时，该条记录的 `usage` 为空，界面显示占位；不用 0 或别的量顶替。
- 图片模型未产出（处理中、未产出、未收费）时，张数沿用现有口径显示 0。

### 4.3 账单汇总

- 选定区间内已完成的请求按类型分别汇总量：图片的产出张数合计、视频的秒数合计、对话的输入与输出 token 合计。
- 汇总把这些量放在 `usage` 对象里，键与用量记录相同；只有有值的键出现。
- 汇总按三种类型（图片、视频、对话）列出项；某类型的量没有值时（区间内没有该类型的请求，或该类型的量落点还没有值），`usage` 里没有该键，界面显示占位（如「—」）而不是 0，也不隐藏该项。
- 请求数是区间内到达终态的执行记录条数，扣费净额是实际扣费与正式调整的有符号金额之和；两者与量分开计算，不随类型的多少变化。

### 4.4 声明与校验

- 素材（`config/bootstrap/*.json`）在顶层声明 `type`。
- 未声明或取值不在三种之内，导入失败并点名文件与型号，库里不产生该 Vendor Model 行。
- 内联发布命令（`offerings`）在顶层声明 `type`；未声明或取值不在三种之内，发布失败并点名 `native_model_id` 与修订。引用式发布不给，类型由被引 Offering 所属 Vendor Model 决定。
- 同一 `(vendor_id, native_model_id, native_revision)` 重发时类型不同，导入与发布失败并点名；与合同内容不一致同一条处置。

### 4.5 失败与空态

- 用量为空时界面显示占位（如「—」），不显示 0，也不隐藏该项。
- 目录、用量记录或账单汇总读取失败时显示错误，不把缺失画成 0。

## 5. 验收条件

| 编号 | 可观察判据 |
| --- | --- |
| A1 | 素材声明 `type: "image"` 导入后，`GET /v1/models` 每条返回 `type`，两个已发布图片模型都是 `image`；既有字段与取值不变。 |
| A2 | 客户登录后 `GET /v1/customer/usage` 每条返回 `type` 并按类型给出用量；管理端同一账户的用量记录类型与之一致。 |
| A3 | 素材缺 `type`、写成三种之外的值，或内联发布（`offerings`）不带 `type`：导入与发布失败，报错点名文件与型号（发布点名 `native_model_id` 与修订），库里不产生该 Vendor Model 行。 |
| A4 | 同一 Vendor Model 修订第二次导入或发布时改变 `type`，被拒并点名；类型与合同都不变时重复导入不产生第二行。 |
| A5 | 已受理的用量记录在网关模型重新发布、改绑到另一个 Vendor Model 之后，仍返回受理时的 `type`。 |
| A6 | 一条类型为 `video` 或 `chat` 的记录在其量落点缺失时，`usage` 为空、界面显示占位，不显示 0。 |
| A7 | 类型为 `image` 的处理中与未产出记录，张数仍按现有口径显示 0，状态与扣费列不变。 |
| A8 | 同一区间里有图片与视频请求时，账单汇总的 `usage` 只按类型给量：`images` 等于 image 类型记录的产出张数合计（video 记录即使经图片路径产出了图也不计入）；视频因秒数落点缺失，`usage` 里不出现 `seconds`，界面显示占位而不是 0；两者不相加；请求数与扣费净额仍与该区间的执行记录、账本一致。 |
