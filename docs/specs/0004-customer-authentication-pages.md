# 客户登录与密码找回页面

本 Spec 拥有客户公开认证页面的内容、导航、表单状态与验收。身份接口、重置码签发、失效及会话规则由[控制台 Spec](0001-admin-and-customer-consoles.md)拥有。本修订待接受；接受后补充其 C11、C12、D5 的页面行为，并为 C1、C3、C12 对应的公开端点加有界尝试限制，不改变密码重置接口的兑换结果语义。

## 1. 范围与边界

登录、忘记密码、重置密码分别提供独立页面。登录页保留注册入口和既有注册能力；注册与登录可以在同一地址切换，两者均不得展示密码重置表单。客户面统一使用“密码”“重置码”，后端字段不由本 Spec 改名；运营侧与管理端沿用“重置令牌”，这处措辞落差是有意接受的——本 Spec 明确排除管理端改版，客服对客户念“重置令牌”而客户页面写着“重置码”不构成缺陷。

账户设置页的客户文案统一属于本 Spec 的范围：三个认证页与客户控制台的账户设置页一律把“口令”改为“密码”，设置页引用的共享重置说明只改措辞，“重置必须由运营签发重置码”的原义不变；账户设置页的结构与功能不在范围内。

客户凭客服转交的重置码设置新密码。忘记密码页面仅指导联系客服，不能提交邮箱申请重置码。没有配置的客服电话、邮箱、即时聊天或跳转地址不得凭空展示。邮件发送、客服系统接入、管理端改版、账户设置页的结构与功能改版、名称与登录身份调整均不在范围内。

**S5 公开鉴权端点的有界尝试限制。** 注册、登录与重置码兑换三个公开端点各自有按来源与按身份的有界失败尝试限制：同一来源或同一身份的连续失败达到上限后，端点拒绝后续尝试并给出可等待的时长，等待结束后恢复；上限与等待时长是运维可配置的取值，有可直接使用的缺省值。成功的尝试不累计失败次数；拒绝结果不区分邮箱是否存在，也不区分重置码是否存在或已用。计数按既有加速层的降级规则处理：缓存不可用时按既有无缓存行为放行。三个端点都要求这套保护，缺一个即不满足本 Spec；其中若某项机制（多副本下的来源识别、按失败次数的退避曲线）需要独立设计，该设计必须独立成篇承接，不得静默省略。本条目约束这三个端点的对客保护，不改变身份与重置接口本身的签发、失效与错误语义，那些仍由[控制台 Spec](0001-admin-and-customer-consoles.md)拥有。

## 2. 页面内容

| 页面地址 | 页面内容 | 可用动作 |
| --- | --- | --- |
| `/login` | 标题“登录”、邮箱、密码、登录按钮；注册模式显示注册表单 | “注册账号”、登录模式下的“忘记密码？”；注册模式的“返回登录” |
| `/forgot-password` | 标题“忘记密码”；说明“请联系平台客服获取重置码。” | “已有重置码，设置新密码”、“返回登录” |
| `/reset-password` | 标题“重置密码”；重置码、新密码、确认新密码、提交按钮；提示“请输入客服提供的重置码。” | “重置密码”、“如何获取重置码？”、“返回登录” |

每次进入 `/login` 默认显示登录模式。页面通过清楚的文字链接切换，不在登录表单下堆放找回说明或重置表单。认证页不展示服务探活、充值与在线支付说明、内部令牌签发或会话存储机制。密码重置成功的可见结果见 §4。

三个页面共用窄内容区、单列布局和一致的标题层级；桌面不并排展示不同认证任务，窄屏不横向滚动。输入框有可见标签，密码字段可显隐；可通过键盘操作，错误与成功状态以文字表达，不能仅依赖颜色或短暂通知。

## 3. 导航与登录回跳

公开认证地址可直接打开、刷新，并可用浏览器前进后退恢复对应页面。重置码、密码、会话凭据和 API Key 明文不得进入 URL、浏览器历史、应用存储或诊断日志；已经约定的会话存放规则除外。刷新、离开页面或浏览器历史切换清除当前页面表单中的密码与重置码，不恢复明文。

未登录直达受保护的客户页面时先显示登录，保持原目标地址，不挂载账户组件或请求账户数据。进入忘记密码、重置密码以及返回登录时保留这个目标，刷新找回页面后仍能回跳；登录或注册成功后返回目标页面及其日期区间（`since`/`until`）。直接打开公开认证页且无本次保留目标时，登录或注册成功进入概览。

回跳仅允许客户侧已知受保护地址和认可的日期区间（`since`/`until`）；`view`、`kind` 这类页面内筛选不由回跳恢复。外部地址、协议相对地址、管理端、API、认证页面以及凭据查询参数均不能作为回跳目标。目标失效或不合规则时进入概览。直接打开未知客户地址沿用既有登录守卫与登录后的客户 404 行为；从未知地址进入找回流程不保存该地址。

本次目标在成功登录或注册、主动退出后清除。会话失效仍按既有规则清屏；用户再次进入找回流程时以这次受保护地址为目标，不能沿用更早的目标。新开标签页直接访问认证地址不承诺继承其他标签页的回跳目标。

已有本地客户会话访问 `/login` 或 `/forgot-password` 时进入概览，不请求新的登录会话。`/reset-password` 始终可打开，重置期间不展示账户数据；确定重置成功后清除该浏览器当前客户会话，即使重置码属于另一客户，也要求重新登录。客户主动从重置页返回登录时同样清除本地客户会话，确保登录表单可见；这不额外调用服务端退出接口，也不声称撤销其他客户的服务端会话。

## 4. 表单与反馈

重置码必填，去除首尾空白后提交。新密码至少 8 个字符，保持输入原值，不去除密码空白；确认新密码必填且必须与新密码一致。任一前端校验未通过时不发送请求；确认新密码仅用于浏览器校验，不进入接口请求。服务端继续拥有最终密码校验权。

提交时冻结表单并阻止重复提交；一次页面实例只能有一个进行中的重置请求。进行中允许离开页面，但导航不代表服务端取消；旧页面请求的晚到结果不能改变当前页面、跳转或清除后来建立的会话。页面说明“正在重置，请稍候；离开页面不会取消本次操作。”。

确定成功后清除重置码与两个密码字段，停止展示可提交表单；页面显示“密码已更新，请重新登录”和“返回登录”按钮，不自动创建会话，不倒计时跳转。点击后显示登录表单，再用新密码登录；成功前不能显示该成功状态。

| 结果 | 客户反馈及可继续动作 |
| --- | --- |
| 前端缺项、密码过短或两次输入不同 | 对应字段显示“请输入重置码”、“新密码至少 8 个字符”或“两次输入的密码不一致”，允许修改后提交 |
| 服务端返回重置参数错误 | 显示“重置码无效或已过期，或新密码不符合要求，请检查后重试；仍无法重置请联系平台客服。”；保留当前输入，允许用户修改后主动提交，不区分重置码不存在、过期与已用 |
| 对应客户不存在 | 显示“无法完成重置，请联系平台客服获取新的重置码。”；清除输入，不允许再次提交本次表单，保留找回与登录入口 |
| 服务端返回尝试超限 | 显示带可等待时长的“尝试过于频繁，请稍后重试。”（时长取自响应的 `Retry-After`）；保留当前输入与重置码，等待结束后允许再次提交，不归入结果未知，也不显示成功 |
| 网络断开、无法判定的服务端失败或异常响应 | 显示“暂时无法确认密码是否已更新，请返回登录尝试新密码；若无法登录，请联系平台客服获取新的重置码。”；清除输入并禁止本次表单重提，不自动重试，不宣称密码未变或重置码仍可用 |

错误反馈不透出 HTTP 错误体、内部错误码、堆栈或签发机制。未知结果状态允许返回登录或重新进入找回流程。刷新或重新打开重置页显示空白表单，用户只能重新输入客服提供的重置码，不自动恢复或重放之前的请求。

登录错误仍保持不存在邮箱与错误密码同一句“邮箱或密码不正确”；注册冲突可明确提示邮箱已注册，其余认证错误使用客户能理解的中文。登录、注册与重置码兑换被尝试限制拒绝时，页面显示可读的等待提示（时长取自 `Retry-After`），保留已填输入，等待结束后允许再次提交；不把这句提示写成密码或重置码错误，也不显示成功。登录与注册请求也应防重复提交，页面切换清除错误和密码，晚到响应不得作用于已离开的页面；不改变既有接口或账号创建结果语义。

## 5. 验收条件

| 编号 | 可观察判据 |
| --- | --- |
| A1 | 登录模式仅有登录表单与入口链接；注册模式仍能注册进入控制台；两种模式均没有重置输入、服务探活或支付说明。 |
| A2 | 点击“忘记密码？”进入独立地址，只显示联系客服说明与两个入口，不出现邮箱申请表单或任何重置码签发请求；通过“已有重置码”进入独立重置页。 |
| A3 | 三个认证地址在开发服务和生产客户主机均可直接打开和刷新；前进后退恢复对应页面且不恢复秘密字段；管理端分发及未知 API 路径的 JSON 404 保持原义。 |
| A4 | 无会话直达带日期筛选的账单页，只显示登录且不请求账户数据；经忘记密码、重置页、刷新、返回登录并完成登录后回到原账单区间；直接登录、注册回跳和会话失效清屏仍成立。 |
| A5 | 外部、管理端、API、认证页和含凭据的候选目标不能用于回跳；成功登录、主动退出后不残留上次回跳目标。 |
| A6 | 缺重置码、空白重置码、新密码过短、确认密码缺失或不一致均不发兑换请求；有效输入只提交去除首尾空白的重置码和原值新密码，连续点击或按回车只发送一次。 |
| A7 | 客服签发的真实重置码可用；成功显示持久结果且不自动登录，秘密字段清除；返回登录后新密码可用、旧密码不可用；重复兑换被拒，与基础身份合同一致。 |
| A8 | 参数错误可以修改再试；不存在客户、5xx、响应丢失与异常响应分别展示约定反馈，未知结果不自动重提或假称失败；离开页面后的晚到响应不改变新页面或新会话。 |
| A9 | 有会话访问登录或忘记密码进入概览；有会话可直接打开重置页，成功后本地会话清除，返回登录按钮能显示登录表单；重置码属于另一客户时同样清除本地会话，未声称撤销另一客户的服务端会话。 |
| A10 | 桌面和窄屏人工查看三个页面，任务内容各自独立，输入标签、键盘导航、错误和成功反馈可用，无横向溢出；客户文案不展示内部机制。 |
| A11 | 注册、登录与重置码兑换各自在连续失败达到上限后返回带 `Retry-After` 的 429，提示不区分邮箱是否存在、也不区分重置码是否存在或已用；等待时长内即使凭据正确也被拒，等待结束后恢复；成功尝试不累计失败次数；按来源与按身份两维各自都能触发上限；上限与等待时长是运维可配的取值，改配置后限制随之改变；页面把该拒绝显示为等待提示而不是结果未知或成功。 |

## 6. 技术设计

[客户认证页面设计](../design/0016-customer-authentication-pages.md)承接本修订；身份与主机分发沿用[身份设计](../design/0010-identity-and-consoles.md)，受保护页面与历史查询沿用[客户导航设计](../design/0014-customer-console-navigation-and-history.md)。本修订接受后，客户导航设计中“未登录只挂载登录/注册”的范围限定为受保护地址；公开找回与重置地址按本 Spec 渲染。公开鉴权端点的有界尝试限制复用既有加速层计数，计数落点、键与无缓存降级由该设计 §3 承接。
