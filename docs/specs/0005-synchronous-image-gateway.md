# 同步图片网关与最小执行记录

本 Spec 拥有图片同步调用、业务载荷保留边界、重复调用、执行失败及运行资源保证。金额语义、余额、预授权、每日消费限额和账单归属仍由账户资金 Spec 拥有。本 Spec 接管[既有执行设计](../design/0002-image-generation-tech-design.md)的请求持久化、Worker 执行与结果持久化规则，以及[图片透传决定](../adr/0019-images-pass-through-without-asset-storage.md)中保留内部执行流水线的部分；其他有效规则继续适用。

## 1. 产品边界

消费者使用 `POST /v1/images/generations` 或 `POST /v1/images/edits`，在同一 HTTP 响应取得图片。成功响应为 `{created, data:[{url|b64_json}]}`，每项只保留一种渠道给出的图片形式。平台不下载响应图片、不解码响应 base64、不提供结果托管或公开异步任务接口。

参考图与遮罩只接受 `http(s)` 公网 URL。`data:` URL、multipart 文件部件与任何其他非法文本都不是合法的图片输入，按 §3 在受理前拒绝。调用方手上的本地文件先经[上传端点](0007-image-upload-and-object-storage.md)换成公网 URL 再提交；命中同一幂等记录的重发按 §4 回原请求事实，不用本规则重新解释原请求。

网关在请求期间完成参数过滤、已有合同校验、候选承载判定、选路、Offering Parameter Mapping、Provider 调用、计量采集和结算。已声明参数的取值原样交给上游，通用类型、枚举和区间不额外校验，只有输出 `n` 按合同声明的类型及上下界校验；该边界沿用[现有合同设计](../design/0005-vendor-model-contract-and-offering-mapping.md)，本稿不增加通用 JSON Schema 校验器。必填、图片组合、分支、输入参考图数量、输出 `n` 的声明范围与候选限制保持现有规则，包括候选较小 `n` 上限的既有处理。

平台不承诺进程崩溃后继续生成或恢复图片；执行状态和账务事实可恢复，业务载荷不可恢复。没有可证明未受理的依据时，平台不得重新提交生成请求。

## 2. 数据保留

本节的载荷边界只适用于生成请求：请求正文、prompt、任意用户参数值、参考图与遮罩的值、被拒绝的 `data:` URL 与文件部件字节、响应图片 URL、`b64_json`、完整 Provider 请求或响应只在执行所需内存中存在，结束或期限到达后释放。不得写入 PostgreSQL、Redis、消息队列、对象存储、临时文件、日志、trace、告警或审计附件。反向代理和应用观测配置不得录制正文；生产进程转储及持久交换配置必须满足相同边界。

上传端点写入对象存储的素材字节不属于本节：它不与执行记录关联，落点、有效性与保留边界由[图片上传与对象存储 Spec](0007-image-upload-and-object-storage.md)拥有。

允许保存以下最小事实，使用有界、强类型或白名单字段：内部 Job/Attempt 标识，账户与 API Key 标识，幂等键的不可逆标识及请求指纹，受理和终态时间，执行协议版本，受理时冻结的模型、修订、供给与渠道身份，Price Snapshot 与汇率，保底额、状态、执行所有权，Provider 逐请求或任务标识，计量计数、产出张数、成本事实、实收与账本关联，平台错误码、白名单 Provider 错误码和失败类别。Provider 标识不得包含结果访问地址或响应正文。

未知的 Provider 错误文本不得原样保留或返回；诊断只保存平台生成的有界分类与处理阶段。计量证据只保存可核验的计费字段、证据类型、来源和关联 Attempt，不用原始响应作附件。用户参数不能借助 JSON 扩展字段进入最小记录。

历史业务载荷必须纳入清理验收；在线清空字段或删除列不代表备份、WAL、副本及既有日志已经清理。实施前盘点这些存量载荷及其保留策略，清理与过期处理须有证据。账本、账户、合法计量事实及历史关联不得因清理丢失。

## 3. 受理与成功

认证、速率限制和本机读取容量检查在消费大正文之前完成；无效凭证不能触发图片解码或大 JSON 解析。请求、图片下载、渠道响应、解析结构及客户端响应均有字节与时限上限。超过请求上限返回 `413`；超过账户执行容量返回既有 `429 too_many_in_flight`，渠道或本机容量不足返回 `503 platform_unavailable`，不创建新占用、不调用 Provider。429 按既有规则给 `Retry-After`。

输入图片形态的拒绝也发生在受理之前，并且先于任何记录：参考图或遮罩的取值不是 `http(s)` 公网 URL（含 `data:` URL、multipart 文件部件与任何其他非法文本）时，返回 `400 public_image_url_required`，不创建执行记录、不取执行许可与资金占用、不调用 Provider，被拒绝的取值不落任何持久层（§2）。该判定属于按当前合同解释请求的那一步，在幂等预查未命中之后执行；命中同一幂等记录的重发按 §4 用记录冻结的规则比对，不受本条影响。

完成合同处理并冻结修订、路由、价格后，受理须按账户资金 Spec 原子创建最小记录和预授权。必须先持久化当前 Attempt 的提交状态，再发出可能产生生成费用的外部请求。上游任务句柄一旦收到，必须在后续轮询之前保存；保存失败不能发第二次生成请求。

正常 `200` 必须满足：结果结构可返回、存在有效计量证据、账务结算已确认提交。账务事务包含状态、证据、成本事实、占用结清与实际扣费；重复收尾或自动对账不得重复扣费。数据库提交结果未知时必须先按执行标识确认，不能直接认定未扣款，也不能重复发出外部请求。

Provider 成功且有有效证据时，按冻结价格结算；客户端断开、接收超时或未保存图片不证明 Provider 未产生费用。此类请求仍按实际用量收费，平台交付故障需要补偿时通过已有正式资金调整处理，不自动免单或重新生成。收费边界见 §7。

## 4. 重复调用

有 `Idempotency-Key` 时，幂等域为账户与该键；没有键时每次调用是独立请求。键格式与长度有界，数据库保存其不可逆标识。相同键不同请求指纹返回 `409 idempotency_conflict`，不改变原请求、不调用 Provider。

请求指纹覆盖端点、平台型号、请求中已识别的模型参数、输入参考图及 mask 的值，使用确定的规范化规则；过滤掉的未知字段不影响指纹。指纹在选路与候选截断之前形成，不依赖当前价格、当前候选或当前 Runtime Revision。相同键重发时先比对原记录，不用新修订重新解释原请求。JSON 与 multipart 两个端点不承诺共享请求指纹。

| 原请求事实 | 相同键、相同指纹的响应 | 副作用 |
| --- | --- | --- |
| 正在执行，尚无终态 | `409 request_in_progress`，给有界 `Retry-After` | 不重复占用，不执行第二次，不挂接另一条结果等待连接 |
| 已结算成功，结果不保留 | `409 result_not_retained` | 不再次收费，不重新生成；错误说明原请求已完成且结果无法重放，新键代表另一笔可能收费的调用 |
| 已确定失败 | 返回原平台错误码与 HTTP 状态 | 不重新执行，不增加占用 |
| 受理、结果或结算仍不确定 | `502 outcome_unknown` | 保留原处置与占用，不重新执行；错误不得引导自动换键重试 |

同步期限到达按已知事实响应：能确认未提交生成且释放已提交时，返回 `504 request_timeout`，说明没有执行生成；上游受理、结果或结算仍不明时返回 `504 outcome_unknown`，说明“未能在时限内确认结果，可能已产生费用”；已确认成功结算但图片无法在时限内准备返回时，返回 `504 result_delivery_timeout`，说明原请求已完成并收费，结果不保留。正文慢读发生在受理前时按有界读取超时返回 `408 request_timeout`，不创建记录。已知确定失败仍返回其平台错误，不用超时覆盖。同键重发按上表返回原事实；不得把已确认账务说成未知。历史成功记录清理结果后也遵守 `result_not_retained`。历史键继续防重并按原请求指纹算法比对，不能用新版过滤规则重新定义它；无法安全比对的旧键返回 `409 idempotency_conflict`，不执行新请求。以 `data:` URL 或文件部件受理的历史记录同样按其冻结规则比对：图片形态的新规则只在未命中记录时适用。

本期不对幂等最小记录配置自动过期，财务相关记录保留期间防重有效；将来归档或删除须另行确定公开保证窗口与边界外重复收费语义。不得依赖 Redis TTL 实现防重。对客错误码集合以 §4/§5 为准；新增或变更对客错误码时同步更新调用方文档。

## 5. 失败、断开与异常对账

| 事实 | 处置 |
| --- | --- |
| 尚未发生成请求，或 Adapter 可证明上游未受理 | 中间安全失败在原请求内按已有次数和退避上限重试同一候选，保存本次 Attempt、递增次数并保留原 Hold 与容量；只有终局确定失败、期限截止或重试耗尽才释放占用 |
| 已发请求但接受状态未知、提交响应丢失、同步 Provider 调用中进程崩溃 | `reconciliation_required`，保留占用；禁止自动重提 |
| 已知 Provider Task，仍未得到终态 | 同步期限内查询同一任务；期限后仅允许异常对账查询，不继续承担对客结果获取 |
| 已得到成功但证据缺失或无效，或渠道终态不能确认 | 进入对账，不凭估计正式扣费，不自动重提 |
| 已得到证据但结算数据库不可用或提交结果未知 | 不发送正常成功；有限尝试确认或收尾，仍不明时转异常处置；不得声称图片已可恢复 |
| 客户端断开 | 未提交则释放；可能已提交则由受监督的执行继续有限收尾，或转对账；断开本身不证明取消成功 |

已受理任务的只读对账查询，仅用于恢复计量与成本事实，不向用户恢复图片、不提交生成、不重新上传输入。自动对账必须同时取得可核验计量证据、Provider 成功终态及与原 Attempt 的可信关联，按原冻结价格幂等结算；明确不向消费者收费的失败按既有规则释放。查询会捎带返回图片时只做有界读取并立即丢弃。

渠道只提供整个含图响应且无法在上限内取得计量时，记录证据缺口，不能为对账无限读图。渠道没有按句柄查询能力或未知句柄时保留现有人工解除占用流程；不新增 `/v1/usage` 周期账单同步或人工确认扣款能力。

不新增未知费用占用的自动释放时长：在取得确定事实或运营解除前保持现有占用规则。配置对账重试上限和告警时限不会自动改变收费或释放语义。无法核实的成本明确为未知，不记为零；已知平台自担成本沿用现有平台账户规则。

## 6. 运行保证

API 直接执行 Provider 调用，不依赖 Worker 的生成队列或 PostgreSQL 结果轮询。Worker 只承接过期所有权清理、已知句柄异常对账、账务核对和有界旁路任务。API 进程数量与执行并发不受数据库连接池大小或单 Worker 串行循环限制。

执行并发、本机正文读取、渠道执行、账户在飞及响应发送有明确上限；多副本下账户与渠道全局上限必须共同遵守，不能把单机限制称为全局限制。账户执行名额沿用既有规则，转对账后释放；财务占用与可能仍在上游执行的渠道名额继续保留，不能混为同一计数。渠道名额仅由确定终态或可信运营处置释放，租约过期不证明上游结束。不使用无界排队或无界后台 future。Redis 作为速率计数与缓存时仍可按既有规则降级；资金受理和全局执行容量不能因此失去约束。

总执行期限覆盖参数读取、输入转换、上传、生成提交、Provider 轮询、安全重试和结算，另有有界客户端发送期限。请求期限和数据库提交结果的处置相互独立：期限到达不能撤销已经发生的 Provider 接受或账务提交。告警与缓存更新失败不能占用响应等待时间或改变已提交的资金结果。

客户端发送期限在连接层执行，不依赖响应 Body 是否继续被读取。HTTP/1 图片响应可以关闭连接；HTTP/2 按连接生效，最早期限到达时服务端可以终止整条连接及其关联任务，同连接其他流一并结束。服务端可以保守持有响应发送许可与字节预算至连接关闭，该期限不改变已经确认的账务事实。

首期直接执行依赖 Linux 的独立 socket 关闭事件检测。不具备等效检测的平台显式启用直接执行时拒绝启动，不回退为保存业务载荷的生成链路。对端关闭写半边按完整连接取消处理；经反向代理调用时，部署须核实客户端关闭传播，未传播时 API 不保证在总期限前观察到终端离开。

正常停机停止受理新执行，给受监督的在飞调用有限收尾机会；强杀后只恢复元数据与账务处置，不能恢复业务载荷或重发未知请求。

## 7. 收费与重复调用边界

Provider 成功并且证据有效时照常结算，即使客户端没有收到图片；因平台交付故障补偿时通过正式资金调整办理。

完成后同键返回 `409 result_not_retained`，不重放图片、不重新生成；新键视为新的计费请求。幂等最小记录本期不自动过期，未知费用占用继续沿用现有人工处置，不另定释放天数。

## 8. 验收条件

| 编号 | 可判定结果 |
| --- | --- |
| A1 | 无 Worker 生成循环时，两条同步入口通过假上游返回 URL 与 base64；响应形状与已有分支、参数过滤、候选 `n` 规则兼容，无公开异步接口。 |
| A2 | 用独特 prompt、输入 URL、被拒绝的 `data:` URL 与文件部件字节、结果 URL、base64 和渠道错误文本做标记；持久记录、缓存、日志、trace、审计及告警没有这些业务载荷。允许的计量字段与任务标识可以查到。 |
| A3 | 无效凭证、正文超限与容量超限均不触发生成；认证前不解析大 JSON 或解码图。无数据库连接或事务跨 Provider 等待。 |
| A4 | 同账户并发占用不超额；同键并发至多一次 Provider 执行；不同指纹冲突，同键处理中、完成、确定失败与未知结果分别符合 §4，账上至多一次实收；指纹密钥轮换不使同键重复受理，中间安全重试保留原资金占用。 |
| A5 | 提交前、提交中、接受后句柄未写入、轮询中、取得证据后、结算提交前后注入崩溃；只有可证明未受理的失败允许重试，强杀恢复不重新发生成请求。 |
| A6 | APIMart 接受后先保存句柄再轮询；API 消失后 Worker 只查原任务，取得有效证据后结算一次，丢弃图片；无句柄或无证据只建案。 |
| A7 | 断开、慢客户端和总期限触发时，占用、实收、错误与对账符合 §3–§5；重复收尾或 Worker/API 竞争不重复收费。 |
| A8 | 高并发、多个 API 副本、大图、多个候选与慢客户端场景下，上限可观察且不超配；SQL 不随 Provider 等待时长每 250ms 增加，峰值内存受并发与字节上限约束；发布或停用后即使缓存通知丢失也不得选旧修订或停用候选；转对账释放账户执行名额但保留资金及渠道未知占用。性能证据区分渠道耗时与网关耗时。 |
| A9 | 旧库升级保留余额、占用、Attempt、证据、账本外键和幂等关联；旧在飞执行排空或转对账，仍可能运行的旧任务计入渠道容量或冻结新增准入；历史载荷与备份保留策略有清理证据，旧执行端不能再写正文。 |
| A10 | 管理端与客户调用记录只展示最小用量、状态和金额；不依赖结果或原始参数；金额、跨日账单、成本缺口和人工解除规则继续满足资金 Spec。 |
| A11 | 客户端断开与发送期限在连接层生效：HTTP/1 已有流水线缓冲时仍能观察到 FIN；HTTP/2 阻塞流的最早发送期限终止同连接全部流；transport 任务与缓冲销毁后才释放发送许可，账务事实不被期限改写；不具备等效关闭检测的平台拒绝启用直接执行。 |
| A12 | 参考图或遮罩的取值不是 `http(s)` 公网 URL（含 `data:` URL、multipart 文件部件与任何其他非法文本）时，受理前返回 `400 public_image_url_required`：不建执行记录、不取执行许可与资金占用、不调用 Provider，被拒绝的取值不落持久层；同键重发已受理的旧记录仍按原记录与冻结的指纹规则回应。 |
