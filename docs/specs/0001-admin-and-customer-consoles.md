# 运营后台与对客自助控制台

本文是这一能力的**行为合同**：管理员与对客各能看到什么、能做什么、失败时怎么表现、边界在哪里。技术实现由承接本 Spec 的 RFC 拥有（见 §8）；实施进度归工作项，不写在这里。

术语沿用 [`CONTEXT.md`](../../CONTEXT.md)：**Gateway Model**、**Offering**、**Channel**、**Runtime Revision**、**Price Snapshot**、**API Key**、**Account**、**Ledger**、**Hold**。

## 1. 目标

平台的服务端能力（网关模型、发布、定价、路由策略、账户与账本、对账与诊断）已经有对应的管理 API，运营后台的前端六页也已经能调这些 API。缺的是两侧的身份与自助面：

- 管理员只有一枚共享的 `ADMIN_TOKEN`，浏览器里手填既不好用，也无法回答"这次改动是谁做的"；
- 对客侧没有"客户是谁"这回事：账户只能由管理员建，`API Key` 只能由管理员发，客户看不到自己的余额、充值记录与用量；
- 前端只有管理面，没有客户自助面。

本能力补上**管理员身份**（邮箱口令登录与会话）、**对客自助身份**（注册、登录、自助密钥与账务）与**对客控制台**，并把已有的管理后台六页从"手填共享令牌"接到管理员会话上。

## 2. 产品范围

### 2.1 管理员身份

| 编号 | 要求 |
| --- | --- |
| A1 | 管理员用**邮箱 + 口令**登录后台。登录成功得到一段会话凭据，之后的管理 API 调用用它认证。 |
| A2 | 会话有**过期时间**（部署期配置）。过期或已退出的会话，后续调用一律被拒，且对客行为是"未认证"，不泄露会话是否存在。 |
| A3 | 管理员可以**退出**，当前会话立即失效。 |
| A4 | 管理员可以**改自己的口令**（需提供当前口令）。改口令成功后，**该管理员此前发出的所有会话立即失效**（含发起这次修改的那个），必须重新登录。 |
| A5 | 邮箱不存在与口令不对**回同一个错误**，且两条路径的响应**不可通过耗时区分**；错误信息不回显口令或哈希。 |
| A6 | 首次部署由**运维引导出初始管理员账号**（引导手段由承接的 RFC 决定）；引导是幂等的：重复执行不产生第二个账号，也不改变已有账号的邮箱与口令。引导用的邮箱若已被客户身份占用，进程启动失败并点名该邮箱。 |
| A7 | 既有的共享 `ADMIN_TOKEN` **保留可用**：它服务于自动化与端到端测试，不因引入登录而失效。 |
| A8 | **忘记口令有出路**：运维（持共享令牌）或另一个管理员可以为一个管理员签发一次性重置令牌并写审计；凭令牌即可设置新口令，不需要旧口令。重置成功使该管理员此前所有会话失效。 |

### 2.2 管理员控制台

后台把已有管理 API 组织成可操作的页面。以下每一项都必须有界面，且界面上的每个事实都来自管理 API（界面不自己造数据、不自己算钱）：

| 编号 | 页面能力 |
| --- | --- |
| M1 | **网关模型**：列出型号（对客名、启用状态、厂商与原生名、合同修订、生效修订、发布时间、加价系数）；展开每条候选看档位、权重、渠道、渠道模型名、驱动器、成本与币种、成本来源、对客计价形态、能否走；能启停**型号**与**候选**。 |
| M2 | **发布修订**：提交一份发布命令（合同、候选数组、成本单价、加价系数、按候选的对客价载体），显示平台的校验结论；发布成功后能看到这次的修订标识。**运营给出的候选是"选中的 Offering + 这条候选的价"**：渠道三要素、驱动器、供应商模型名、承载面与参数映射由被引用的 Offering 决定，不由运营填（机制见 [`0012-platform-model-publishing.md`](../design/0012-platform-model-publishing.md)）。**改价时**整份候选引用沿用，只改价。**加价系数就是 `markup_bps`**（倍率 = 1 + `markup_bps`/10000），页面要能看出它怎么影响这个候选的对客价。**每条候选还要选对客计价形态**（按 token 四档 / 上游声明金额 × 倍率，界面默认预选按 token 四档），它与该 Offering 的成本计价形态**相互独立**：成本怎么算由渠道事实决定，对客怎么收由运营在这里选。对客 token 四档的**金额按渠道原币种给**（默认取平台维护的该 vendor/模型 token 价目，运营可改）；人民币对客价由**金额 × 折算率 × 倍率**算出并随修订发布、随 Job 快照冻结，界面上不出现微单位。该币种的**折算率缺了就当场录**，不用另开页面。它**不依赖该候选的成本单价**——成本由上游直接给金额的渠道也能按 token 四档卖。发布命令带的是运营最终确认的那份价，随修订发布、随 Job 快照冻结。 |
| M3 | **折算率**：按币种录入渠道币种 → CNY 的折算率，可给生效时刻；能看出当前录入结果。 |
| M4 | **路由策略**：读写全局与按型号覆盖的策略、折扣率表、标签映射。 |
| M5 | **账户与密钥**：建账户、充值、读余额、读账目流水、设账户标签、发 API Key（明文只显示这一次，在弹窗里展示、关闭即从页面清掉）。**管理端不吊销 API Key**：运营既判断不了客户是否正在正常使用，也拿不到要吊销的密钥标识（它只出现在签发响应里），吊销只由客户本人做。还要能**替客户开户**（C13）：用一个邮箱 + 口令建出客户身份，既可以是新账户，也可以是**给已有账户配上登录身份**；并**按邮箱找到客户账户**——不这样，"给客户充值""为客户签重置令牌"都没有入口。管理端的账户与客户各有列表页和详情页；从列表进入详情后，详情占据主内容区，不在列表下方追加。账户详情承载金额、标签、充值、充值记录、扣费记录与 API Key；客户详情承载邮箱、关联账户、上次登录与重置令牌操作。 |
| M6 | **对账与诊断**：未结案的对账案例（含发起退款）、平台侧失败清单、成本缺口清单。 |
| M7 | 后台在**未认证**时必须先显示登录，不得在未认证状态下展示任何管理数据。 |

### 2.3 对客自助

| 编号 | 要求 |
| --- | --- |
| C1 | 客户用**邮箱 + 口令**注册。注册成功即得到一个属于自己的账户与一段会话凭据。 |
| C2 | 注册时邮箱已被占用返回明确冲突（调用方能自己改）；**已被管理员身份占用的邮箱同样算被占用**，回同一个冲突，不透露它是管理员账号；邮箱或口令不合形状返回参数错误。 |
| C3 | 客户用邮箱 + 口令登录；失败语义与 A5 相同。 |
| C4 | 客户可以退出；可以改自己的口令（需提供当前口令）。**改口令成功后该客户此前发出的所有会话立即失效**（含发起这次修改的那个）。 |
| C5 | 客户能**列自己的 API Key**（标签、创建时间、是否已吊销；**绝不回显密钥本身**）、**新建**（明文只返回这一次）、**吊销**。新建的明文在**弹窗**里展示，内容**只有密钥本身**——不显示密钥标识（吊销按列表那一行操作，不需要抄标识）；客户关闭弹窗后明文不再留在页面上。吊销前须明确确认。 |
| C6 | 客户只能操作**自己账户**下的密钥与账目；对别人的账户一律"不存在"，不区分"无权"与"不存在"。 |
| C7 | 客户控制台显示**一个**余额数字，标题就是「余额」，取值是客户**现在能用的钱**（`available_microusd` = 已结算余额 − 正在处理的请求占住的额度）。请求受理时余额按占住的额度减少，结算后按实际扣费多退少补。内部三分解（已结算余额、持有中、可用额）只在管理员面出现，客户页面不分别展示，也不出现「预授权」「持有中」这类词。这个数字**允许为负**（实收超过已结算余额时由结算造成），页面照实显示、不截断成 0。金额语义见[账户资金 Spec](0002-account-funds-and-reservations.md) §1、§4。 |
| C8 | 客户能按时间区间查看自己的实际资金记录：**充值、扣费、运营调整**；可以按这三类筛选。界面用这三个客户语言的名字，**不出现 `capture`／`adjustment` 这类内部科目名，也不解释平台的预授权与结算机制**（本合同其余条款里的“实际扣费／正式调整”是金额口径名，界面按本节换成客户语言）。预授权及释放不作为资金记录展示。记录按入账时刻倒序，可继续翻看早于首页的记录。 |
| C9 | 客户能看**用量记录**：自己的每一次生成请求的请求时刻、终态时刻、型号、**对客状态**（成功 / 未产出 / 处理中 / 已取消）、本次用量（按模型类型：图片是产出张数，视频是产出秒数，对话是输入与输出 token）、实际扣费金额。结果尚不确定、仍需对账的请求显示“处理中”，直至结案；处理中请求与已结束历史分开。已结束历史默认查询含今天的最近 30 个本地自然日，按终态时刻倒序、可调整日期并连续翻页；未结束请求不计入账单请求数。对客状态是收敛后的值，不暴露平台内部 Job 状态。模型类型与用量的取值归[模型类型 Spec](0006-model-type-and-usage-records.md)。 |
| C10 | 客户能看**账单汇总**：选定时间区间内的已完成请求数、按模型类型分列的用量合计（图片张数、视频秒数、对话输入与输出 token）、实际扣费及正式调整后的净额。页面首次进入显示含今天的最近 30 个本地自然日（从 29 天前的本地零点到当前时刻），并标出区间与时区；客户可调整区间。汇总按该区间**全量**计算，不随逐笔列表的条数上限变化；充值不计入扣费净额。不同类型的量不相加。 |
| C11 | 客户控制台在未认证时先显示登录/注册，不得展示任何账户数据。 |
| C12 | **忘记口令有出路**：**由运营触发重置**——客户向运营提出，运营在管理端为该账户签发一次性重置令牌，通过运营与客户之间已有的渠道转交；客户凭令牌设置新口令，不需要旧口令。重置成功使该客户此前所有会话失效。**客户不能自助申请重置**：本能力不发送邮件、不做邮箱验证，任何"未认证即可申请令牌"的入口都等于"知道邮箱就能接管账户"。 |
| C13 | **运营可以替客户开户**：管理端能用一个邮箱与口令直接建出客户身份——开一个新的客户账户，或给**已有的账户**（今天由管理员建的、还没有登录身份的那些）配上登录身份。配好之后，该邮箱就是那个账户的登录名，客户能像自己注册的一样登录、管理密钥、看账务。开户不改变账户已有的余额、密钥与历史记录。目标邮箱若已被管理员身份占用，返回冲突。 |
| C14 | 运营开户时给的口令是**初始口令**：运营把它交给客户，客户登录后自行改掉（C4）。客户也可以选择不要初始口令，而是拿一枚重置令牌（C12）自己设——两种都由运营决定。 |
| C15 | 客户控制台按“概览、调用记录、账单与资金记录、API Key、账户设置”提供独立页面与固定导航。概览首屏只呈现一个标题为「余额」的数字（C7 的口径：客户现在能用的钱）和通往各项记录的入口；账户 id 与**账户名称**等低频资料放在账户设置。每个页面只加载所需数据，切换页面不丢失账单的日期选择；页面刷新、浏览器前进后退及直接打开内部地址能回到对应页面。 |

注册（C1）、登录（C3）与重置码兑换（C12）三个公开端点的**有界尝试限制**由[客户认证页面 Spec](0004-customer-authentication-pages.md) §1 的 S5 拥有：同一来源或同一身份的连续失败达到上限后，端点返回带可等待时长的拒绝，等待结束后恢复；成功的尝试不累计失败次数；上限与等待时长是运维可配置的取值；缓存不可用时按既有加速层降级规则放行。C12、C14 的**客户可见措辞**（“重置码”“密码”）由该 Spec 定义，运营侧与管理端沿用“重置令牌”“口令”。本 Spec 不改变这三个端点既有的签发、失效与错误语义。

### 2.4 交付形态

| 编号 | 要求 |
| --- | --- |
| D1 | 两个控制台都是**浏览器可用的界面**，与 API 同上一个来源，不要求客户或运营配置跨域。 |
| D2 | 会话凭据不得进入 URL（查询串、路径）与日志；前端刷新页面后仍保持登录。 |
| D3 | 静态产物可重复构建；构建命令与产物位置写在仓库里。 |
| D4 | **两套界面各自独立**：管理界面与客户界面是两个独立的**入口产物**（由一次构建产出，各自一套脚本与样式），由 API 按主机名分发（地址形式由承接的 RFC 定）。客户界面在浏览器里**不加载管理界面的代码**，管理界面也不加载客户界面的代码。 |
| D5 | 客户控制台的内部页面地址只标识页面和非敏感筛选条件，不含会话凭据或 API Key。未登录访问任一内部地址仅显示登录/注册，不取账户数据；登录后回到原定页面。会话过期时隐藏账户数据并要求重新登录。 |
| D6 | 管理端每个账户详情与客户详情都有自己的内部地址。点列表项、按账户 id 直达、建账户或开户成功后进入对应详情；直接打开、刷新、浏览器前进后退仍回到相应对象。返回列表时保留本次查找条件。无管理员会话时先登录，不取管理数据，登录后回原详情；对象不存在时显示明确的找不到状态，不继续显示上一个对象的数据。地址中不放会话凭据、API Key 明文或重置令牌。 |

## 3. 非目标

- **自助在线支付**：本期不做。充值仍由管理员在后台完成；客户控制台**展示**充值记录，但不提供支付入口。将来要做，需要单独的支付渠道与对账能力。
- **客户之间的协作与多用户组织**：不做组织、成员、角色。一个客户邮箱对应一个账户。
- **管理员角色与权限分级**：不做。本期管理员是同一种身份，全部管理 API 对每个管理员都可用。
- **账户合并与账户间转账**：不做。一个账户只对应一对邮箱口令；把两个账户的钱并到一起不在本期范围（开户是给一个账户配登录身份，不是把账户并起来——C13）。
- **邮件发送**：不做。开户的初始口令由运营转交；口令重置令牌回显在该次响应里、由运营转交客户。平台不接邮件通道，也就不做"邮箱验证"。
- **第三方登录**（OAuth、企业 SSO）：不做。
- **对客的密钥轮换自动化、用量告警**：不做。
- **界面上的国际化与主题定制**：不做。
- **改动既有对客协议**：`/v1/images/generations`、`/v1/images/edits` 的请求与响应形状不变；`/v1/models` 的既有字段（`name`、`vendor_id`、`revision`、`contract`）不变。

## 4. 可观察行为

### 4.1 登录与会话

- 登录成功：返回会话凭据与过期时刻。
- 登录失败（邮箱不存在、口令不对、形状不合法）：返回参数错误，文案只说"邮箱或口令不正确"。
- 用有效会话访问管理 API：成功，行为与用 `ADMIN_TOKEN` 时完全一致。
- 用无效、过期或已退出的会话访问管理 API：被拒，**响应体不说明失败原因**（不区分"没这个会话"与"会话过期"），也不区分它是不是一枚令牌写错了。
- 未带任何凭据访问管理 API：被拒，**状态码、错误码与文案都与"凭据不对"逐字相同**——调用方无法用响应区分这两种情形（`403 admin_forbidden`）。
- 口令：短于下限一律拒；口令不落日志、不回显。
- **改口令与重置口令都吊销该身份的全部会话**（A4、A8、C4、C12）：改动成功后，此前发出的任何会话凭据都不能再用，包括发起这次改动的那一个。
- **三条"关于我自己"的端点只认会话**（认身份、改口令、退出）：共享 `ADMIN_TOKEN` 不指向任何管理员，在这些端点上被拒。

### 4.2 对客越权

- 用 A 的会话请求 B 的密钥列表、余额、账目、用量、账单：一律**不存在**（404 语义），不返回 403，也不返回任何 B 的数据。
- 用 A 的会话吊销 B 的密钥：同上。
- 用已吊销的会话（退出后）：未认证。

### 4.3 一致的展示口径

- 客户控制台只显示一个余额数字，标题为「余额」，取值是 `available_microusd`：请求受理时按占住的额度减少、结算后按实际扣费多退少补，内部三分解不分别展示。这个数字允许为负（实收超过已结算余额时由结算造成），照实显示、不截断成 0；读取失败时显示错误与重试入口，不把缺失值画成 0，加载中不显示数字。页面只呈现这个数字与其更新时刻，**不写解释预授权占用或结算机制的文案**——那套机制属于平台内部，讲给客户听容易被读成"先多扣再退回"。管理员账户页可以分开显示已结算余额、持有中和可用额。金额语义及受理判定由[账户资金 Spec](0002-account-funds-and-reservations.md) §1、§4 拥有。
- 金额以微单位传输，界面按元显示（保留必要小数位，不四舍五入成整数元）。
- 用量与扣费取**账本与执行记录的事实**，不由界面重算；账单汇总的求和以账本条目为准。
- 显示时间一律带时区（浏览器本地时区即可），不得显示"3 小时前"这类相对描述作为唯一信息。
- **账单区间是半开区间 `[since, until)`，按 UTC 解释**：`since` 缺省为不限、`until` 缺省为"到此刻"。半开是为了相邻两个区间既不漏算也不重复算——闭区间会把边界上的那一笔算两次。
- **账单汇总的取数口径**：请求数按区间内到达终态的执行记录计；用量按模型类型分列各自的合计（图片张数、视频秒数、对话输入与输出 token），不同类型的量不相加；扣费总额按实际入账的 `capture` 与 `adjustment` 有符号金额计。预授权与释放不产生资金流水，退款以正式调整体现。跨天归属和明细核对见[账户资金 Spec](0002-account-funds-and-reservations.md) §5。
- 客户页面将账单返回的有符号扣费净额解释为“净支出”或“净返还”，并把运营调整与扣费分开说明（界面上是这两个客户语言的名字）；不把有符号净额除以请求数称作“平均每次扣费”。日期选择按浏览器本地日期呈现，提交给服务端的起止时刻仍为 UTC 半开区间，并在页面上标出时区。
- **对客价来自按候选发布的对客价目**：`初始对客价(CNY) = 该 vendor/模型已知的渠道价目单价 × 倍率 × 折算率(该币种 → CNY)`，倍率 = 1 + `markup_bps`/10000（同币种折算率恒为 1）——这条乘法是**初始值的推导依据**，不是结算期的被乘数。**成本计价形态**（渠道按 token、按张、按次、上游直接给金额）只决定"成本单价是几个数"；**对客计价形态由运营按候选选择**（按 token 四档 / 上游声明金额 × 倍率，界面默认预选按 token 四档），与成本形态相互独立。对客 token 四档的初始值取平台维护的该 vendor/模型 token 价目（初始参考渠道价目，如 AIHubMix 的四档）；运营可改，且不依赖该候选的成本单价，所以成本由上游直接给金额的候选也能按 token 四档卖。运营最终提交的那份价随修订发布、随 Job 快照冻结（页面上看到的金额来自服务端返回的数据）。**发布期校验的是能力**：对客选 token 四档要求渠道**能提供**四分项 `usage`；选上游金额要求渠道**能声明** `cost`。给不出即拒并点名。

### 4.4 失败与空态

- 管理 API 返回错误时，界面显示**平台给的原话**（错误码与消息），不把错误吞掉、不显示"操作成功"。
- 没有任何数据时显示空态说明（例如"还没有发布过任何网关模型"），不显示空白表格。

## 5. 验收条件

每条都必须可观察、可判定。

### 5.1 管理员身份

| 编号 | 判据 |
| --- | --- |
| V-A1 | 用正确邮箱与口令登录，拿到会话凭据；用该凭据调 `GET /api/v1/gateway-models` 成功。 |
| V-A2 | 用错误口令登录被拒；用不存在的邮箱登录被拒，且两者的错误码与响应体形状**相同**；两条路径都会走一次口令哈希（模块用例直接断言"邮箱不存在时调用了校验"，不靠计时断言）。 |
| V-A3 | 会话过期后（用短 TTL 配置 + 应用层替身覆盖时钟制造，不靠真实等待）再调用被拒为未认证；退出后立刻被拒。 |
| V-A4 | 改口令成功后，旧口令登录失败、新口令登录成功；用错误当前口令改口令被拒；**改口令前发出的会话凭据全部失效**。 |
| V-A5 | 首次启动带引导变量时恰好产生一个管理员账号；再启动一次不产生第二个，且已改过的口令**不被引导值覆盖**，原账号仍能登录。 |
| V-A6 | 共享 `ADMIN_TOKEN` 仍能调通**既有的全部管理端点**（那些走 `require_admin` 的读写端点，本能力不改它们）与本次新增的管理读端点；而"认身份、改口令、退出"这三条只认会话的端点用它调一律被拒，且错误码与"凭据不对"相同。 |
| V-A7 | 为一个管理员签发重置令牌后：凭令牌设置新口令成功、用新口令能登录、该管理员旧会话全部失效；签发事件在审计里可查。令牌用过一次后不能再用。 |
| V-A8 | 引导变量的三种组合各自的行为：两个都不给时不创建账号、进程照常启动，且日志里能看出"没有管理员账号"；只给一个时启动失败并点名缺哪一个。 |
| V-A9 | 引导用的邮箱已被客户身份占用时启动失败并点名该邮箱。 |

| V-C2 | 同一邮箱重复注册被拒为冲突；用**管理员身份已占用的邮箱**注册同样被拒为冲突且不产生写入；形状不合法的邮箱/口令被拒为参数错误。 |

| V-C5 | A 的会话读 B 的余额/流水/用量/账单/密钥列表，全部返回不存在；吊销 B 的密钥同样被拒，且 B 的密钥仍然可用。 |
| V-C6 | 管理员充值后，客户控制台余额与充值记录都反映该笔入账；客户发起请求时余额按占住的额度减少，结算后按实际扣费多退少补；页面不出现内部三分解或预授权金额。 |
| V-C7 | **先由管理员给该账户充值到足以受理**（新账户余额为 0，直接发请求必然被余额闸门拒为 402），之后客户发一次生成请求走通；用量记录里出现这一笔（型号、对客状态、时间、本次用量、扣费金额），且金额与账本 `capture` 条目一致。 |
| V-C8 | 按 `[since, until)`（UTC）查账单汇总，请求数、各模型类型的量合计与区间内**全量已完成**用量明细一致；逐笔扣费与区间 `capture` 合计一致，单独列示 `adjustment` 后与账单扣费总额一致。把明细条数上限调到小于全量时，汇总不变。 |
| V-C9 | 忘记口令：**由运营触发**、令牌经运营转交，客户凭它设置新口令后旧口令失效、新口令可登录，且重置前发出的会话全部失效；同一令牌第二次使用被拒。 |
| V-C10 | 未认证（无凭据、会话已过期、已退出）访问客户账务与密钥端点，一律**未认证**（与管理员面同一条：不带凭据或凭据无效回未认证，不回"不存在"，也不回"无权"）。 |
| V-C11 | 客户无法自助申请重置：对客面**不需要凭据就能访问**的端点只有四个——注册、登录、**凭令牌兑换新口令**这三个自助动作，加上既有的公开对客目录 `GET /v1/models`（只列已发布型号的身份与合同：调用方得先知道有哪些模型才建得出表单；它不含渠道、供给、驱动或执行记录）。没有任何"提交邮箱就拿到令牌"的入口。 |
| V-C12 | 客户改口令（C4）：用正确当前口令改成新口令后，旧口令登录失败、新口令成功，且改之前发出的会话全部失效；当前口令不对时被拒且不改动。 |
| V-C13 | 运营替客户开户（C13）：用邮箱 + 口令开一个新账户，之后客户用该邮箱口令能登录、能自助发 Key；**给一个已有的账户配上登录身份**后，该客户登录看到的余额、流水与密钥**就是那个账户原有的**（钱与密钥都在，历史不变）。同一邮箱再开一次被拒为冲突；已被绑定的账户再绑别的邮箱被拒为冲突；目标邮箱已被管理员身份占用时回冲突（开新账户与给已有账户配身份两条路径都拦）。 |
| V-C14 | 运营开户给的初始口令能登录；客户用 C4 改掉之后旧口令失效。运营也可以不给初始口令而只签发重置令牌（C12），客户凭它设口令后能登录。 |
| V-C15 | 造出多于一页的已结束请求及真实资金记录，按同一日期区间连续翻页后无重复、无漏项；未结案的对账请求仍列为处理中，取消的请求列为已取消；跨 UTC 日结算的完成记录与扣费在对应区间能查到。账单汇总不随翻页变化，充值与正式调整可分别识别，预授权金额始终不可见。 |

### 5.3 界面与交付

| 编号 | 判据 |
| --- | --- |
| V-D1 | 一次构建产出两个入口产物（管理、客户），可被 API 按其地址分发；浏览器打开管理地址看到登录界面，打开客户地址看到登录/注册界面。 |
| V-D2 | 用端到端夹具自造的数据（发布一份素材 + 一个账户 + 一条路由策略），登录后各管理页面读出**该夹具**的数据（不依赖某个开发库的当前状态，因而可重复）。 |
| V-D3 | 刷新页面后仍是登录态；URL 里不出现会话凭据。 |
| V-D4 | 未认证时不出现任何管理数据，且**不向管理 API 发出任何取数请求**（用无凭据的浏览器会话观察网络请求）。 |
| V-D5 | 客户登录后打开“概览”，**首屏**就能看到余额（不需滚动、不需切换视图），它是客户现在能用的钱；页面不出现已结算余额、持有中、可用额这三个内部分项，也不出现单笔预授权金额；调用、账单与资金记录、API Key、设置均可从固定导航进入，各自内容不在概览堆叠；未登录时只看到登录/注册。 |
| V-D6 | 客户入口产物里**不含管理界面的代码**：`portal.html` 引用的脚本与样式文件里，不出现只在 `src/console/` 里用到的模块（对产物逐文件核对，不靠肉眼）。客户会话调管理 API 一律被拒。 |
| V-D7 | **人工验收**：构建产物由 API 托管后，服务真的起着（`/health` 健康），由一个**人**用浏览器打开管理地址、用引导出来的邮箱口令登录，并逐个打开七个管理页面确认数据正确；结果留档（登录成功与否、每个页面看到什么、发现的问题）。这条不自动化，由人执行并记录。 |
| V-D8 | **加一个平台模型不需要碰任何技术字段**：运营在管理界面填平台模型名、**选 vendor**、在**该 vendor 下已配好的 Offering 里勾一条或多条**（可排档位、设权重），给价后发布成功，并在模型目录里看到这个模型。渠道、渠道地址、凭证变量名、驱动器、承载面与参数映射**不由运营填**——它们属于被选中的 Offering，由工程师随发布素材配置（设计与缺口见 [`0012-platform-model-publishing.md`](../design/0012-platform-model-publishing.md)）。运营后台的发布入口只有这一条，没有贴技术字段的旁路。 |
| V-D9 | **给已有型号改价不需要重新填全部技术字段**：选中一个已发布型号、只改倍率或对客费率即可发布出新修订，渠道地址、凭证变量名、驱动器**以及渠道费率与价目出处**都不需要运营重填（合同见 [`0012-platform-model-publishing.md`](../design/0012-platform-model-publishing.md)）。改价界面上因此看不到这些字段。 |
| V-D10 | **充值不需要先知道账户标识**：运营用邮箱或标签搜到账户，进入该账户的详情页充值；余额与流水随即反映这次充值。 |
| V-D11 | **替客户开户不需要先抄账户标识**：运营在客户区用一个邮箱开户（新建账户或绑到已有账户），随后进入该客户的详情页签发重置令牌；客户详情中的关联账户可进入账户详情。 |
| V-D12 | **对客计价形态与成本形态解耦**：对客计价形态只有两种（按 token 四档 / 上游声明金额 × 倍率），与成本计价形态（按 token / 按张 / 按次 / 上游声明金额）相互独立。一条成本为 `upstream_declared`（APIMart）的 Offering 可以对客选"按 token 四档"发布成功，结算按四档 CNY 向量收费；对客 token 四档的初始值取该 vendor/模型的 token 价目（初始参考渠道价目）、运营可改，不依赖该候选的成本单价；同一候选改成"上游金额 × 倍率"重发新修订后，之前已受理 Job 的收费逐位不变；发布期对客形态只接受这两个取值：给出按张 / 按次被拒并点名；渠道不能提供所选形态所需的能力（无 `usage` / 不能声明 `cost`）时同样拒绝并点名，运营界面的对客形态下拉也按这条能力过滤——给不出的形态不摆出来。运营在定价处按**渠道原币种**给四档金额（默认取该 vendor／模型已知的价目、可改），并给折算率与倍率；人民币对客价由平台算出、只读展示。成本侧字段（参考成本、成本来源、渠道费率表、成本币种）不出现在运营表单里，界面也不出现微单位。 |
| V-D13 | 登录后分别直达五个客户页面，刷新及浏览器前进后退保持所选页面；账单日期筛选返回时仍在 URL 中。无会话直达任一页面时不发账户请求，登录后回原页；会话失效后不继续显示旧账务或密钥数据，URL 和日志不含凭据。 |
| V-D14 | 概览只显示余额（客户现在能用的钱），不出现“扣费总额（全部）”或无区间说明的平均扣费；账单页默认最近 30 天并显示时区。点击账单页刷新时，汇总与资金流水按同一区间重取；失败时显示错误与重试，不把请求失败显示为零。客户吊销自己的 API Key 前需要确认，密钥明文在弹窗里、关闭后不再出现在页面；管理端没有任何吊销入口。 |
| V-D15 | 管理员点账户列表行、按完整账户 id 查看、建账户成功、点客户列表的“详情”以及开户成功后，地址分别指向对应详情页，列表不在详情页上方或下方；账户详情内的四项操作只显示当前选中的模块。两个详情地址直接打开或刷新仍读取该对象；前进后退恢复页面，返回列表保留查找条件。未登录直达时不取管理数据；不存在的对象显示找不到，不残留前一对象的金额、邮箱或一次性明文。 |
| V-D16 | 管理端账户详情的 API Key 模块只有签发与一次性明文，没有吊销入口、也没有要填的密钥标识；管理面不再提供吊销接口（未认证矩阵里不存在它），而客户按自己的会话吊销仍然立刻生效、不删行、可重复调用。 |

判据的**证据形态**在承接的 RFC 里给（哪些用端到端用例、哪些用浏览器实测、哪些用代码复核）。

## 6. 约束与兼容性

- `/v1/account` 的 `balance_microusd` 语义改为已结算余额，并增加 `available_microusd`；其余对客生成端点的请求、响应形状保持各自既有合同；`/v1/models` 只增模型类型字段（取值与展示见[模型类型 Spec](0006-model-type-and-usage-records.md)）。账户读接口的完整金额语义见[账户资金 Spec](0002-account-funds-and-reservations.md) §4。
- 对客 `ledger` 与 `usage` 读取保留现有 `since`、`until`、`limit`；`usage` 行内的用量改为按模型类型给出（`image_count` 换成按类型的用量，见[模型类型 Spec](0006-model-type-and-usage-records.md)），其余既有响应字段保留；增加可选的连续翻页参数及下一页标记。`ledger` 增加实际资金类别筛选，未知类别返回参数错误；`usage` 增加处理中与已结束历史的分组查询，已结束历史按终态时刻过滤。翻页不得泄露别的账户数据，翻页标记不含凭据；不带新增参数的原调用继续可用。详细金额与跨天口径仍由[账户资金 Spec](0002-account-funds-and-reservations.md) §3–§5 拥有。
- 管理员账户读接口的 `balance_microusd` 语义改为已结算余额，并增加 `available_microusd`；账户流水只返回实际收支。发布端点的内联形状新增必填的模型类型，引用式形状不变（见[模型类型 Spec](0006-model-type-and-usage-records.md)）；账户调用明细的行内用量同样按模型类型给出（`image_count` 换成按类型的用量）；其它管理身份端点的请求与响应合同保持不变。管理员流水保留可选的 `until`、`offset` 与响应中的 `total`；对客账务读按上一条扩展。`ADMIN_TOKEN` 认证路径保持可用，但不适用于"关于我自己"的三条端点（§4.1）。
- `GET /api/v1/accounts/{account_id}/summary` 仅接受现有管理员认证，按 id 返回既有 `AccountSummary` 字段（账户 id、**账户名称**、已结算余额、标签、绑定邮箱、创建与更新时间），账户不存在时返回 404。账户列表同样返回非空名称并可按名称子串筛选；名称的规则、生成与编辑见[账户名称 Spec](0003-account-names-and-login-identities.md)。详情页的持有中与可用额仍由既有 `GET /api/v1/accounts/{account_id}` 提供；两个响应都不由页面重算金额。除新增的名称字段外，既有账户读与列表端点的响应形状保持不变。
- 管理面**不再提供** `DELETE /api/v1/api-keys/{key_id}`：吊销只由客户会话按自己的账户执行（`DELETE /v1/customer/api-keys/{key_id}`，见 C5/C6）。这是删除既有能力，不是新增接口；删除后管理端未认证矩阵里不再有这一条。
- `GET /api/v1/customers/{customer_id}` 仅接受现有管理员认证，返回既有 `CustomerView` 字段（客户 id、邮箱、账户 id、**关联账户名称**、创建时间、上次登录），客户不存在时返回 404；口令、会话、API Key 明文和重置令牌均不在响应中。既有 `GET /api/v1/customers` 的按邮箱查询与列表行为保持不变。
- **账本是唯一权威**：余额、充值、扣费都以 `ledger` 为准，控件不引入第二份计数。
- **凭证纪律**：口令、会话凭据、API Key 明文、重置令牌都只从请求里来、只在必要的那一次响应里回，不写入配置、日志、响应其它字段或测试 fixture。
- 客户控制台的唯一余额数字取 `GET /v1/customer/account` 的 `available_microusd`，标题为「余额」；该接口继续同时返回已结算余额、持有中与可用额，并增加自己的**账户名称**（客户可在账户设置里修改，见[账户名称 Spec](0003-account-names-and-login-identities.md)）。API Key 面的 `GET /v1/account` 响应形状不变。
- **不变式**：一个邮箱在平台身份里唯一——既在管理员与客户各自域内唯一，也不能同时被一个管理员与一个客户占用；一个客户对应恰好一个账户；会话凭据与重置令牌在库里只以摘要存在，且都有过期时刻。
- **运维不变量**：会话有效期（缺省 12 小时）与口令长度下限（缺省 8）是配置项，缺省值写在承接的 RFC 里；引导变量**缺失时视为"不引导"**（不创建管理员、不阻止进程启动），只给一个视为配置错误、启动失败并点名缺哪一个。
- **对外价的唯一入口是发布**：对客卖多少钱只在发布修订时定——修订级 `markup_bps`、**按候选的对客计价形态**与按候选的对客费率向量，汇率走 `PUT /api/v1/fx-rates`。仓库里的 `config/bootstrap/*.json` 是**发布夹具**，其中的对客费率是夹具值、**不是生产价、不构成定价入口**；界面上介绍它与用到它的地方都要这么说。在运营录入真实价之前，不得宣称平台已有对外定价策略。

## 7. 未解决问题

无。两套界面的承载形态与静态产物的提供方式都已定案（**一个前端工程、一次构建出两个互不引用的入口产物**，由 `apps/api` 按其地址分发；首次引导的手段由 RFC §3.4 定为环境变量、仅在账号不存在时写入），设计见 `docs/design/0010-identity-and-consoles.md` §4.5 与 §4.6。

## 8. 技术设计

身份与两个入口产物由[身份与控制台设计](../design/0010-identity-and-consoles.md)承接；管理员账户与客户的列表、详情和导航由[管理端页面设计](../design/0011-console-information-architecture.md)承接；客户控制台的页面组织、历史浏览与独立导航由[客户控制台改造设计](../design/0014-customer-console-navigation-and-history.md)承接；身份邮箱在管理员与客户之间互斥的落地方式由[身份邮箱互斥记录](../../.agents/notes/implemented/platform/2026-10-05-identity-email-exclusivity.md)承接。本 Spec 不复制设计正文。
