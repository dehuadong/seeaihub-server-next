# 运营后台与对客自助控制台

本文是这一能力的**行为合同**：管理员与对客各能看到什么、能做什么、失败时怎么表现、边界在哪里。技术实现由承接本 Spec 的 RFC 拥有（见 §10）；实施进度归工作项，不写在这里。

术语沿用 [`CONTEXT.md`](../../CONTEXT.md)：**Gateway Model**、**Offering**、**Channel**、**Runtime Revision**、**Price Snapshot**、**API Key**、**Account**、**Ledger**、**Hold**。

## 1. 目标

平台的服务端能力（网关模型、发布、定价、路由策略、账户与账本、对账与诊断）已经有对应的管理 API，运营后台的前端六页也已经能调这些 API。缺的是两侧的身份与自助面：

- 管理员只有一枚共享的 `ADMIN_TOKEN`，浏览器里手填既不好用，也无法回答"这次改动是谁做的"；
- 对客侧没有"客户是谁"这回事：账户只能由管理员建，`API Key` 只能由管理员发，客户看不到自己的余额、充值记录与用量；
- 前端只有管理面，没有客户自助面。

本能力补上**管理员身份**（邮箱口令登录与会话）、**对客自助身份**（注册、登录、自助密钥与账务）与**对客控制台**，并把已有的管理后台六页从"手填共享令牌"接到管理员会话上。

## 2. 产品范围

### 2.1 管理员身份

| 编号 | 要求 |
| --- | --- |
| A1 | 管理员用**邮箱 + 口令**登录后台。登录成功得到一段会话凭据，之后的管理 API 调用用它认证。 |
| A2 | 会话有**过期时间**（部署期配置）。过期或已退出的会话，后续调用一律被拒，且对客行为是"未认证"，不泄露会话是否存在。 |
| A3 | 管理员可以**退出**，当前会话立即失效。 |
| A4 | 管理员可以**改自己的口令**（需提供当前口令）。改口令成功后，**该管理员此前发出的所有会话立即失效**（含发起这次修改的那个），必须重新登录。 |
| A5 | 邮箱不存在与口令不对**回同一个错误**，且两条路径的响应**不可通过耗时区分**；错误信息不回显口令或哈希。 |
| A6 | 首次部署由**运维引导出初始管理员账号**（引导手段由承接的 RFC 决定）；引导是幂等的：重复执行不产生第二个账号，也不改变已有账号的邮箱与口令。 |
| A7 | 既有的共享 `ADMIN_TOKEN` **保留可用**：它服务于自动化与端到端测试，不因引入登录而失效。 |
| A8 | **忘记口令有出路**：运维（持共享令牌）或另一个管理员可以为一个管理员签发一次性重置令牌并写审计；凭令牌即可设置新口令，不需要旧口令。重置成功使该管理员此前所有会话失效。 |

### 2.2 管理员控制台

后台把已有管理 API 组织成可操作的页面。以下每一项都必须有界面，且界面上的每个事实都来自管理 API（界面不自己造数据、不自己算钱）：

| 编号 | 页面能力 |
| --- | --- |
| M1 | **网关模型**：列出型号（对客名、启用状态、厂商与原生名、合同修订、生效修订、发布时间、加价系数）；展开每条候选看档位、权重、渠道、渠道模型名、驱动器、成本与币种、成本来源、对客计价形态、能否走；能启停**型号**与**候选**。 |
| M2 | **发布修订**：提交一份发布命令（合同、候选数组、成本单价、加价系数、按候选的对客价载体），显示平台的校验结论；发布成功后能看到这次的修订标识。**运营给出的候选是"选中的 Offering + 这条候选的价"**：渠道三要素、驱动器、供应商模型名、承载面与参数映射由被引用的 Offering 决定，不由运营填（机制见 [`0012-platform-model-publishing.md`](../design/0012-platform-model-publishing.md)）。**改价时**整份候选引用沿用，只改价。**加价系数就是 `markup_bps`**（倍率 = 1 + `markup_bps`/10000），页面要能看出它怎么影响这个候选的对客价。**每条候选还要选对客计价形态**（按 token 四档 / 上游声明金额 × 倍率，界面默认预选按 token 四档），它与该 Offering 的成本计价形态**相互独立**：成本怎么算由渠道事实决定，对客怎么收由运营在这里选。对客 token 四档的**金额按渠道原币种给**（默认取平台维护的该 vendor/模型 token 价目，运营可改）；人民币对客价由**金额 × 折算率 × 倍率**算出并随修订发布、随 Job 快照冻结，界面上不出现微单位。该币种的**折算率缺了就当场录**，不用另开页面。它**不依赖该候选的成本单价**——成本由上游直接给金额的渠道也能按 token 四档卖。发布命令带的是运营最终确认的那份价，随修订发布、随 Job 快照冻结。 |
| M3 | **折算率**：按币种录入渠道币种 → CNY 的折算率，可给生效时刻；能看出当前录入结果。 |
| M4 | **路由策略**：读写全局与按型号覆盖的策略、折扣率表、标签映射。 |
| M5 | **账户与密钥**：建账户、充值、读余额、读账目流水、设账户标签、发 API Key（明文只显示这一次）、吊销 API Key。还要能**替客户开户**（C13）：用一个邮箱 + 口令建出客户身份，既可以是新账户，也可以是**给已有账户配上登录身份**；并**按邮箱找到客户账户**——不这样，"给客户充值""为客户签重置令牌"都没有入口。 |
| M6 | **对账与诊断**：未结案的对账案例（含发起退款）、平台侧失败清单、成本缺口清单。 |
| M7 | 后台在**未认证**时必须先显示登录，不得在未认证状态下展示任何管理数据。 |

### 2.3 对客自助

| 编号 | 要求 |
| --- | --- |
| C1 | 客户用**邮箱 + 口令**注册。注册成功即得到一个属于自己的账户与一段会话凭据。 |
| C2 | 注册时邮箱已被占用返回明确冲突（调用方能自己改）；邮箱或口令不合形状返回参数错误。 |
| C3 | 客户用邮箱 + 口令登录；失败语义与 A5 相同。 |
| C4 | 客户可以退出；可以改自己的口令（需提供当前口令）。**改口令成功后该客户此前发出的所有会话立即失效**（含发起这次修改的那个）。 |
| C5 | 客户能**列自己的 API Key**（标签、创建时间、是否已吊销；**绝不回显密钥本身**）、**新建**（明文只返回这一次）、**吊销**。 |
| C6 | 客户只能操作**自己账户**下的密钥与账目；对别人的账户一律"不存在"，不区分"无权"与"不存在"。 |
| C7 | 客户能看**余额**与**持有中**，两者分开呈现，不合成一个数。 |
| C8 | 客户能看**充值记录**（自己的账目流水里的充值条目）。 |
| C9 | 客户能看**用量记录**：自己的每一次生成请求的时间、型号、**对客状态**（成功 / 失败 / 处理中）、产出图片数量、实际扣费金额。逐笔列表按时间倒序、条数有上限。对客状态是一个**收敛过的三值**，不是平台内部的 Job 状态。 |
| C10 | 客户能看**账单汇总**：一段时间内的请求数、产出图片数、扣费总额。汇总按该区间**全量**计算，不随逐笔列表的条数上限变化。 |
| C11 | 客户控制台在未认证时先显示登录/注册，不得展示任何账户数据。 |
| C12 | **忘记口令有出路**：**由运营触发重置**——客户向运营提出，运营在管理端为该账户签发一次性重置令牌，通过运营与客户之间已有的渠道转交；客户凭令牌设置新口令，不需要旧口令。重置成功使该客户此前所有会话失效。**客户不能自助申请重置**：本能力不发送邮件、不做邮箱验证，任何"未认证即可申请令牌"的入口都等于"知道邮箱就能接管账户"。 |
| C13 | **运营可以替客户开户**：管理端能用一个邮箱与口令直接建出客户身份——开一个新的客户账户，或给**已有的账户**（今天由管理员建的、还没有登录身份的那些）配上登录身份。配好之后，该邮箱就是那个账户的登录名，客户能像自己注册的一样登录、管理密钥、看账务。开户不改变账户已有的余额、密钥与历史记录。 |
| C14 | 运营开户时给的口令是**初始口令**：运营把它交给客户，客户登录后自行改掉（C4）。客户也可以选择不要初始口令，而是拿一枚重置令牌（C12）自己设——两种都由运营决定。 |

### 2.4 交付形态

| 编号 | 要求 |
| --- | --- |
| D1 | 两个控制台都是**浏览器可用的界面**，与 API 同上一个来源，不要求客户或运营配置跨域。 |
| D2 | 会话凭据不得进入 URL（查询串、路径）与日志；前端刷新页面后仍保持登录。 |
| D3 | 静态产物可重复构建；构建命令与产物位置写在仓库里。 |
| D4 | **两套界面各自独立**：管理界面与客户界面是两个独立的**入口产物**（由一次构建产出，各自一套脚本与样式），由 API 按主机名分发（地址形式由承接的 RFC 定）。客户界面在浏览器里**不加载管理界面的代码**，管理界面也不加载客户界面的代码。 |

## 3. 非目标

- **自助在线支付**：本期不做。充值仍由管理员在后台完成；客户控制台**展示**充值记录，但不提供支付入口。将来要做，需要单独的支付渠道与对账能力。
- **客户之间的协作与多用户组织**：不做组织、成员、角色。一个客户邮箱对应一个账户。
- **管理员角色与权限分级**：不做。本期管理员是同一种身份，全部管理 API 对每个管理员都可用。
- **账户合并与账户间转账**：不做。一个账户只对应一对邮箱口令；把两个账户的钱并到一起不在本期范围（开户是给一个账户配登录身份，不是把账户并起来——C13）。
- **邮件发送**：不做。开户的初始口令由运营转交；口令重置令牌回显在该次响应里、由运营转交客户。平台不接邮件通道，也就不做"邮箱验证"。
- **第三方登录**（OAuth、企业 SSO）：不做。
- **对客的密钥轮换自动化、用量告警**：不做。
- **界面上的国际化与主题定制**：不做。
- **改动既有对客协议**：`/v1/images/generations`、`/v1/images/edits`、`/v1/models` 的请求与响应形状不变。

## 4. 可观察行为

### 4.1 登录与会话

- 登录成功：返回会话凭据与过期时刻。
- 登录失败（邮箱不存在、口令不对、形状不合法）：返回参数错误，文案只说"邮箱或口令不正确"。
- 用有效会话访问管理 API：成功，行为与用 `ADMIN_TOKEN` 时完全一致。
- 用无效、过期或已退出的会话访问管理 API：被拒，**响应体不说明失败原因**（不区分"没这个会话"与"会话过期"），也不区分它是不是一枚令牌写错了。
- 未带任何凭据访问管理 API：被拒，**状态码、错误码与文案都与"凭据不对"逐字相同**——调用方无法用响应区分这两种情形（`403 admin_forbidden`）。
- 口令：短于下限一律拒；口令不落日志、不回显。
- **改口令与重置口令都吊销该身份的全部会话**（A4、A8、C4、C12）：改动成功后，此前发出的任何会话凭据都不能再用，包括发起这次改动的那一个。
- **三条"关于我自己"的端点只认会话**（认身份、改口令、退出）：共享 `ADMIN_TOKEN` 不指向任何管理员，在这些端点上被拒。

### 4.2 对客越权

- 用 A 的会话请求 B 的密钥列表、余额、账目、用量、账单：一律**不存在**（404 语义），不返回 403，也不返回任何 B 的数据。
- 用 A 的会话吊销 B 的密钥：同上。
- 用已吊销的会话（退出后）：未认证。

### 4.3 一致的展示口径

- 余额与持有中是两个数，分开显示；界面不得显示"总额"。
- 金额以微单位传输，界面按元显示（保留必要小数位，不四舍五入成整数元）。
- 用量与扣费取**账本与执行记录的事实**，不由界面重算；账单汇总的求和以账本条目为准。
- 显示时间一律带时区（浏览器本地时区即可），不得显示"3 小时前"这类相对描述作为唯一信息。
- **账单区间是半开区间 `[since, until)`，按 UTC 解释**：`since` 缺省为不限、`until` 缺省为"到此刻"。半开是为了相邻两个区间既不漏算也不重复算——闭区间会把边界上的那一笔算两次。
- **账单汇总的取数口径是账本条目**：区间内的请求数与产出张数按该区间完成的执行记录数；**扣费总额按该区间内账本里的扣费与调整条目求和**（`capture` 与 `adjustment`），**不含预授权（`hold`）与它的释放（`release`）**——持有的那笔钱从未离开账户（`hold` 为负、`release` 为正，两者成对抵消），把它们计进来只会得到"平台占用了多少"，那不是扣费。退款以账本里的调整/释放形式体现，随之净额减少。
- **对客价来自按候选发布的对客价目**：`初始对客价(CNY) = 该 vendor/模型已知的渠道价目单价 × 倍率 × 折算率(该币种 → CNY)`，倍率 = 1 + `markup_bps`/10000（同币种折算率恒为 1）——这条乘法是**初始值的推导依据**，不是结算期的被乘数。**成本计价形态**（渠道按 token、按张、按次、上游直接给金额）只决定"成本单价是几个数"；**对客计价形态由运营按候选选择**（按 token 四档 / 上游声明金额 × 倍率，界面默认预选按 token 四档），与成本形态相互独立。对客 token 四档的初始值取平台维护的该 vendor/模型 token 价目（初始参考渠道价目，如 AIHubMix 的四档）；运营可改，且不依赖该候选的成本单价，所以成本由上游直接给金额的候选也能按 token 四档卖。运营最终提交的那份价随修订发布、随 Job 快照冻结（页面上看到的金额来自服务端返回的数据）。**发布期校验的是能力**：对客选 token 四档要求渠道**能提供**四分项 `usage`；选上游金额要求渠道**能声明** `cost`。给不出即拒并点名。

### 4.4 失败与空态

- 管理 API 返回错误时，界面显示**平台给的原话**（错误码与消息），不把错误吞掉、不显示"操作成功"。
- 没有任何数据时显示空态说明（例如"还没有发布过任何网关模型"），不显示空白表格。

## 5. 验收条件

每条都必须可观察、可判定。

### 5.1 管理员身份

| 编号 | 判据 |
| --- | --- |
| V-A1 | 用正确邮箱与口令登录，拿到会话凭据；用该凭据调 `GET /api/v1/gateway-models` 成功。 |
| V-A2 | 用错误口令登录被拒；用不存在的邮箱登录被拒，且两者的错误码与响应体形状**相同**；两条路径都会走一次口令哈希（模块用例直接断言"邮箱不存在时调用了校验"，不靠计时断言）。 |
| V-A3 | 会话过期后（用短 TTL 配置 + 应用层替身覆盖时钟制造，不靠真实等待）再调用被拒为未认证；退出后立刻被拒。 |
| V-A4 | 改口令成功后，旧口令登录失败、新口令登录成功；用错误当前口令改口令被拒；**改口令前发出的会话凭据全部失效**。 |
| V-A5 | 首次启动带引导变量时恰好产生一个管理员账号；再启动一次不产生第二个，且已改过的口令**不被引导值覆盖**，原账号仍能登录。 |
| V-A6 | 共享 `ADMIN_TOKEN` 仍能调通**既有的全部管理端点**（那些走 `require_admin` 的读写端点，本能力不改它们）与本次新增的管理读端点；而"认身份、改口令、退出"这三条只认会话的端点用它调一律被拒，且错误码与"凭据不对"相同。 |
| V-A7 | 为一个管理员签发重置令牌后：凭令牌设置新口令成功、用新口令能登录、该管理员旧会话全部失效；签发事件在审计里可查。令牌用过一次后不能再用。 |
| V-A8 | 引导变量的三种组合各自的行为：两个都不给时不创建账号、进程照常启动，且日志里能看出"没有管理员账号"；只给一个时启动失败并点名缺哪一个。 |

### 5.2 对客自助

| 编号 | 判据 |
| --- | --- |
| V-C1 | 注册成功后，用该邮箱与口令能登录；账户余额为 0。 |
| V-C2 | 同一邮箱重复注册被拒为冲突；形状不合法的邮箱/口令被拒为参数错误。 |
| V-C3 | 客户新建 API Key，明文只在这次响应里出现；随后列自己的密钥能看到该标签与创建时间，且**列表里没有任何明文**。 |
| V-C4 | 客户吊销该密钥后，用该密钥调对客生成接口被拒。 |
| V-C5 | A 的会话读 B 的余额/流水/用量/账单/密钥列表，全部返回不存在；吊销 B 的密钥同样被拒，且 B 的密钥仍然可用。 |
| V-C6 | 管理员给该账户充值后，客户看到的余额与充值记录都出现这笔；余额与持有中分开返回。 |
| V-C7 | **先由管理员给该账户充值到足以受理**（新账户余额为 0，直接发请求必然被余额闸门拒为 402），之后客户发一次生成请求走通；用量记录里出现这一笔（型号、对客状态、时间、产出张数、扣费金额），且金额与账本 `capture` 条目一致。 |
| V-C8 | 按 `[since, until)`（UTC）查账单汇总，请求数、产出张数与扣费总额，与同一区间内**全量**用量明细的求和一致（扣费总额＝该区间 `capture` 与 `adjustment` 条目之和，**不含** `hold` 与 `release`）；把明细条数上限调到小于全量的值时，汇总不变。 |
| V-C9 | 忘记口令：**由运营触发**、令牌经运营转交，客户凭它设置新口令后旧口令失效、新口令可登录，且重置前发出的会话全部失效；同一令牌第二次使用被拒。 |
| V-C10 | 未认证（无凭据、会话已过期、已退出）访问客户账务与密钥端点，一律**未认证**（与管理员面同一条：不带凭据或凭据无效回未认证，不回"不存在"，也不回"无权"）。 |
| V-C11 | 客户无法自助申请重置：对客面**不需要凭据就能访问**的端点只有四个——注册、登录、**凭令牌兑换新口令**这三个自助动作，加上既有的公开对客目录 `GET /v1/models`（只列已发布型号的身份与合同：调用方得先知道有哪些模型才建得出表单；它不含渠道、供给、驱动或执行记录）。没有任何"提交邮箱就拿到令牌"的入口。 |
| V-C12 | 客户改口令（C4）：用正确当前口令改成新口令后，旧口令登录失败、新口令成功，且改之前发出的会话全部失效；当前口令不对时被拒且不改动。 |
| V-C13 | 运营替客户开户（C13）：用邮箱 + 口令开一个新账户，之后客户用该邮箱口令能登录、能自助发 Key；**给一个已有的账户配上登录身份**后，该客户登录看到的余额、流水与密钥**就是那个账户原有的**（钱与密钥都在，历史不变）。同一邮箱再开一次被拒为冲突；已被绑定的账户再绑别的邮箱被拒为冲突。 |
| V-C14 | 运营开户给的初始口令能登录；客户用 C4 改掉之后旧口令失效。运营也可以不给初始口令而只签发重置令牌（C12），客户凭它设口令后能登录。 |

### 5.3 界面与交付

| 编号 | 判据 |
| --- | --- |
| V-D1 | 一次构建产出两个入口产物（管理、客户），可被 API 按其地址分发；浏览器打开管理地址看到登录界面，打开客户地址看到登录/注册界面。 |
| V-D2 | 用端到端夹具自造的数据（发布一份素材 + 一个账户 + 一条路由策略），登录后各管理页面读出**该夹具**的数据（不依赖某个开发库的当前状态，因而可重复）。 |
| V-D3 | 刷新页面后仍是登录态；URL 里不出现会话凭据。 |
| V-D4 | 未认证时不出现任何管理数据，且**不向管理 API 发出任何取数请求**（用无凭据的浏览器会话观察网络请求）。 |
| V-D5 | 客户控制台登录后，**首屏**就能看到可用余额与持有中（两者分行、不需滚动、不需切换视图）；充值记录、用量明细与账单汇总在同一控制台内可见；未登录时只看到登录/注册。 |
| V-D6 | 客户入口产物里**不含管理界面的代码**：`portal.html` 引用的脚本与样式文件里，不出现只在 `src/console/` 里用到的模块（对产物逐文件核对，不靠肉眼）。客户会话调管理 API 一律被拒。 |
| V-D7 | **人工验收**：构建产物由 API 托管后，服务真的起着（`/health` 健康），由一个**人**用浏览器打开管理地址、用引导出来的邮箱口令登录，并逐个打开七个管理页面确认数据正确；结果留档（登录成功与否、每个页面看到什么、发现的问题）。这条不自动化，由人执行并记录。 |
| V-D8 | **加一个平台模型不需要碰任何技术字段**：运营在管理界面填平台模型名、**选 vendor**、在**该 vendor 下已配好的 Offering 里勾一条或多条**（可排档位、设权重），给价后发布成功，并在模型目录里看到这个模型。渠道、渠道地址、凭证变量名、驱动器、承载面与参数映射**不由运营填**——它们属于被选中的 Offering，由工程师随发布素材配置（设计与缺口见 [`0012-platform-model-publishing.md`](../design/0012-platform-model-publishing.md)）。运营后台的发布入口只有这一条，没有贴技术字段的旁路。 |
| V-D9 | **给已有型号改价不需要重新填全部技术字段**：选中一个已发布型号、只改倍率或对客费率即可发布出新修订，渠道地址、凭证变量名、驱动器**以及渠道费率与价目出处**都不需要运营重填（合同见 [`0012-platform-model-publishing.md`](../design/0012-platform-model-publishing.md)）。改价界面上因此看不到这些字段。 |
| V-D10 | **充值不需要先知道账户标识**：运营用邮箱或标签搜到账户，在该账户的详情里充值；余额与流水随即反映这次充值。 |
| V-D11 | **替客户开户不需要先抄账户标识**：运营在客户区用一个邮箱开户（新建账户或绑到已有账户），随后能在同一处为该客户签发重置令牌。 |
| V-D12 | **对客计价形态与成本形态解耦**：对客计价形态只有两种（按 token 四档 / 上游声明金额 × 倍率），与成本计价形态（按 token / 按张 / 按次 / 上游声明金额）相互独立。一条成本为 `upstream_declared`（APIMart）的 Offering 可以对客选"按 token 四档"发布成功，结算按四档 CNY 向量收费；对客 token 四档的初始值取该 vendor/模型的 token 价目（初始参考渠道价目）、运营可改，不依赖该候选的成本单价；同一候选改成"上游金额 × 倍率"重发新修订后，之前已受理 Job 的收费逐位不变；发布期对客形态只接受这两个取值：给出按张 / 按次被拒并点名；渠道不能提供所选形态所需的能力（无 `usage` / 不能声明 `cost`）时同样拒绝并点名。运营在定价处按**渠道原币种**给四档金额（默认取该 vendor／模型已知的价目、可改），并给折算率与倍率；人民币对客价由平台算出、只读展示。成本侧字段（参考成本、成本来源、渠道费率表、成本币种）不出现在运营表单里，界面也不出现微单位。 |

判据的**证据形态**在承接的 RFC 里给（哪些用端到端用例、哪些用浏览器实测、哪些用代码复核）。

## 6. 约束与兼容性

- **既有对客协议不变**：三个 `/v1` 端点的请求与响应形状逐字保持。
- **既有管理 API 的请求与响应形状不变**：本能力只**新增**端点（登录/退出/改口令/重置令牌/折算率读/对客自助读），既有端点不改形状、不改语义。唯一的例外是管理员账户流水（`/api/v1/accounts/{id}/entries`）与对客账务读：它们**增加可选参数与可选响应字段**（`until`、`offset`、`total`），既有参数与既有字段的含义保持不变。`ADMIN_TOKEN` 那条认证路径保持可用，但它不适用于"关于我自己"的三条端点（§4.1）。
- **账本是唯一权威**：余额、充值、扣费都以 `ledger` 为准，控件不引入第二份计数。
- **凭证纪律**：口令、会话凭据、API Key 明文、重置令牌都只从请求里来、只在必要的那一次响应里回，不写入配置、日志、响应其它字段或测试 fixture。
- **不变式**：一个邮箱在一个身份域（管理员 / 客户）内唯一；一个客户对应恰好一个账户；会话凭据与重置令牌在库里只以摘要存在，且都有过期时刻。
- **运维不变量**：会话有效期（缺省 12 小时）与口令长度下限（缺省 8）是配置项，缺省值写在承接的 RFC 里；引导变量**缺失时视为"不引导"**（不创建管理员、不阻止进程启动），只给一个视为配置错误、启动失败并点名缺哪一个。
- **对外价的唯一入口是发布**：对客卖多少钱只在发布修订时定——修订级 `markup_bps`、**按候选的对客计价形态**与按候选的对客费率向量，汇率走 `PUT /api/v1/fx-rates`。仓库里的 `config/bootstrap/*.json` 是**发布夹具**，其中的对客费率是夹具值、**不是生产价、不构成定价入口**；界面上介绍它与用到它的地方都要这么说。在运营录入真实价之前，不得宣称平台已有对外定价策略。

## 7. 未解决问题

无。两套界面的承载形态与静态产物的提供方式都已定案（**一个前端工程、一次构建出两个互不引用的入口产物**，由 `apps/api` 按其地址分发；首次引导的手段由 RFC §3.4 定为环境变量、仅在账号不存在时写入），设计见 `docs/design/0010-identity-and-consoles.md` §4.5 与 §4.6。
