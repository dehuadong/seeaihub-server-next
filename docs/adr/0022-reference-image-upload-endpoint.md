# 参考图上传端点：调用方本地素材换公网 URL，生成请求内仍不落盘

## 背景

[0019](./0019-images-pass-through-without-asset-storage.md) 撤掉了生成请求内的平台资产：参考图与遮罩只是参数值，平台不落盘、不代传，结果按渠道原形进原形出。这条边界没有回答"调用方手上只有本地文件时怎么办"：`data:` URL 把整个文件塞进请求体，平台要在内存里解一份 base64 再交给需要字节的渠道；multipart 文件部件同样只能由生成请求代为搬运。素材搬运于是落在每一次生成上，混进受理、幂等与执行限额。

## 决定

- **生成接口只收 `http(s)` 公网 URL**：参考图或遮罩的取值是 `data:` URL、或以 multipart 文件部件给出时，受理前返回 `400 public_image_url_required`，不建执行记录、不取执行许可与资金占用、不调用渠道；形态判定发生在幂等预查未命中之后，命中同一记录的重发仍按记录冻结的规则比对（[Spec 0005](../specs/0005-synchronous-image-gateway.md) §3、§4）。
- **新增显式上传端点** `POST /v1/uploads/images`：调用方把本地文件交给平台，平台写入对象存储并返回不带签名、不带过期参数的公网可读 URL。上传不绑定 Job、不产生执行记录、不计费、不计量、不限配额。
- **结果仍不归档**：0019 的"不下载、不解码、不归档结果"与"只有同步形态"继续成立；本端点只处理调用方输入素材。
- **不承诺保留期与删除**：对象由对象存储控制台管理，平台不代删、不续期；换桶或换 region 不迁移既有对象。

产品行为见 [Spec 0007](../specs/0007-image-upload-and-object-storage.md)，技术机制见 [Design 0021](../design/0021-object-storage-upload.md)；本 ADR 只拥有决策与边界。

## 与 0008 的区别

[0008](./0008-own-object-storage-is-the-platform-result.md) 要求平台把**生成结果**先归档到自有对象存储、再标 Job 成功：对象是结果，触发方是平台自己的执行流程，平台因此要替调用方持有结果字节并承担它的访问语义与寿命；0019 退役了这条路线。本 ADR 让平台持有的是**调用方输入素材**，且只在调用方显式调用上传端点时持有：对象是输入，触发方是调用方，生成请求与执行流程仍不落盘、不代传、不归档结果。两条都用对象存储，但对象、触发方与责任都不同。

## 反悔成本

上传端点一旦上线，返回的 URL 会被写进调用方集成，并被当成"平台会一直提供这个地址"的承诺使用；对象键前缀、`storage.upload_storage` 表与它的公开配置也会成为持久结构。改回 0008 式的结果归档要重建结果侧的对象存储与资产身份；改回"生成接口内联收字节"要让受理重新承担素材搬运，并为已受理的历史请求与新的形态规则各留一套指纹解释；改成私有桶或预签名读要为已发出的公网 URL 规定解释规则，并改写调用方的取图方式。

## 权衡

- **调用方自备图床**（平台不提供上传）：平台零责任，但调用方要先接入一个对象存储并自己保证公网可读，参考图能不能用变成调用方的问题，平台也失去了对"提交进来的 URL 至少可读"这件事的任何判据——落选；
- **生成接口内联收字节**（`data:` URL / 文件部件）：调用方一次调用就能带图，但每次生成都承担一次素材搬运与解码，请求体要装下整张图，素材责任混进受理、幂等与执行限额——落选；
- **私有桶 + 预签名读取**：访问可控，但返回的 URL 带签名与有效期，调用方拿到的是"过一会儿失效的地址"，上游渠道也不一定能在有效期内取图，对象存储的访问控制与 URL 的可分享语义分叉——落选；
- **显式上传端点 + 公网可读 URL**（选定）：素材搬运从生成路径移到一次独立调用，生成请求只带 URL；平台不承诺保留期，桶的公网可读由激活上传存储时的健康检查判据确认。

代价：平台多一层对象存储与一条管理端点，调用方多一次调用；URL 一旦分享就等于分享图片内容，没有访问控制；素材的寿命由对象存储控制台决定，平台既不代删也不续期。

**批准依据**：用户 2026-10-04 裁决生成接口只收公网 URL、新增单文件上传端点，并要求上传不绑定 Job、不计费、不承诺保留期。
