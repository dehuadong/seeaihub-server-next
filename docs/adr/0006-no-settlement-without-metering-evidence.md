# 结算的证据门槛、计量维度与成本口径

**没有可核验的计量证据，就不做正式资金结算。** 结算只读取强类型证据与 Job 固化的 Price Snapshot；公开单价只能作为 Price Plan 候选，不能单独证明最终结算依据；不得用请求参数反推用量并当作真实账单；证据缺字段、负数、总量不一致或解析失败时**不得猜测费用**，进对账；未取得可核验计量证据前，该 Offering 不能以正式资金结算状态发布。Reconciliation Case **不是**例外：人工处置当前只能退款并释放全部预授权，不能仅凭金额、备注、业务键或运营判断确认扣款。

**证据必须带单位，计价必须声明维度。** 计量形态**跟着渠道的计费方式走**——按 token 计费就取分项 token，直接声明金额就用那句金额，按次数或张数计费就取次数/张数；平台不假设"计量必然是 token"。逐项要能唯一落到该 Offering 已声明的单位或档位，落不到就进对账；某渠道只有一个恒定单价时，应发布**单档覆盖全域**的档位表，而不是省略档位。同一个 Offering 上两种形态不得并存或隐含切换，由 Price Plan 在受理时固定。**不得由金额反推计量量**——金额是结果，不是计量。

**成本与结算基数是两个量，成本按渠道各自的口径取数。** APIMart 直接给出 `cost`，那就是它的实际成本（含账号倍率，不可复现），平台不按 token × 公开费率去反算；AIHubMix 不给任何金额字段，成本只能按分项 token × 已发布费率自算；将来接入按次数或按张数计费的渠道，成本就按该渠道的计费单位取数。`cost` 只用于核成本，**不替代计量事实**。平台对外价与账号折扣是否让利属后期产品决定。

**币种**：账本与 Price Snapshot 以 microUSD 计价。Price Plan 保留原生币种、原生单价与发布时固定的汇率，使"厂商原价 → 平台美元价"可追溯，已受理 Job 不受后续汇率漂移影响；以 USD 计价的计划原生价即 microUSD、汇率取恒等值，不得为此伪造一次换算。

**合并说明**：本条合并了原 `0010`（计量证据承单位、计价声明维度）与 `0016`（成本按渠道口径取数），二者编号保留为存根以便旧链接可解析。"上游声明的金额能否作为第二类证据"这一候选问题已由实测回答并否决，依据见 `.agents/notes/rejected/domain/2026-09-19-provider-declared-charge-as-metering-evidence.md`。

**批准依据**：本条的规划评审通过记录在 `#2` 上不可复核，**批准待用户事后确认**（2026-09-20 核对，见工作项 [`#6`](https://github.com/dehuadong/seeaihub-server-next/issues/6)）——本条在实现中生效，但不据此推断已获批准。

**2026-09-22 修订（币种段：对客单币种，成本按渠道声明的币种）**：上文"账本与 Price Snapshot 以 microUSD 计价"改为——**对客平面只有人民币（CNY）单币种**：余额、充值、售价、保底额（预授权）与扣费一律 CNY；**成本平面按渠道声明的 `currency`** 记原值，**可能是 USD、CNY 或别的，不假定 USD**。**汇率只用于把成本折算成 CNY 做毛利核算，不参与对客金额**（对客金额只由受理时冻结的 CNY 费率快照决定）。上文"以 USD 计价的计划原生价即 microUSD"仍成立（那是**该渠道**的币种口径：成本按渠道币种记原值），但**同句"汇率取恒等值"的部分被取代**——折算率是"渠道币种 → CNY"的率，USD 渠道不再取恒等值，也不再省掉那次换算（换算只发生在成本/毛利侧）。既有列名里的 `usd`（如余额列）是**历史命名**，币种语义以本条修订为准。改这一段的理由：对客只有一个收付平面（用户不会按多币种充值），成本却是各渠道各自的事实，两个平面必须分开记、分开核。

**2026-09-22 修订（汇率段：从"发布时固定"改为"受理时快照"）**：上文"Price Plan 保留…发布时固定的汇率"改为——**汇率按币种维护成折算率表**（渠道币种 → CNY，带生效时间），**受理时按该候选的成本币种取"受理时刻生效的那一行"，把该行原值快照进 Price Snapshot**，**受理后不再换算**。改这一段的理由：汇率是外部事实，同一时刻同一币种全平台必须是同一个数才对账得起来；放进每条 Price Plan 的发布里，改一次汇率就要重发所有计划。**"已受理 Job 不受后续汇率漂移影响"这一点不变**，变的只是固定的时点与来源：从"发布时写死在计划里的一个数"改为"受理时刻折算率表里生效的那一行"，毛利口径因此可复算。
