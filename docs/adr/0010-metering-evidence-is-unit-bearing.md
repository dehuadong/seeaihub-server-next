# 计量证据承载单位，计价必须声明维度

结算不假设"计量必然是 token"，而是要求 **Metering Evidence 是带单位的计量量**、**Price Plan 显式声明按哪个维度计价**；**维度跟着渠道的计费方式走**——渠道按 token 计费就取分项 token，按张数、次数或像素档计费就取对应的量。当前已应用的维度只有 token（四分项）；其它维度是已声明能力，本阶段不启用。逐项必须能唯一落到已声明的单位或档位，落不到就不得猜金额、进对账；若某 Provider 只有一个恒定单价，应发布**单档覆盖全域**的档位表，而不是省略档位。

**不得由金额反推计量量**——金额是结果，不是计量。同一个 Offering 上两种形态不得并存或隐含切换，由 Price Plan 在受理时固定。（"上游声明的扣费金额"能否作为第二种证据形态，已由实测结清并被否决：两家渠道都返回分项 token。）

**币种**：账本与 Price Snapshot 以 microUSD 计价。Price Plan 保留原生币种、原生单价与发布时固定的汇率，使"厂商原价 → 平台美元价"可追溯，已受理 Job 不受后续汇率漂移影响；以 USD 计价的计划原生价即 microUSD、汇率取恒等值，不得为此伪造一次换算。

**批准依据**：本条的规划评审通过记录在 `#2` 上不可复核，**批准待用户事后确认**（2026-09-20 核对，见工作项 [`#6`](https://github.com/dehuadong/seeaihub-server-next/issues/6)）——本条在实现中生效，但不据此推断已获批准。
