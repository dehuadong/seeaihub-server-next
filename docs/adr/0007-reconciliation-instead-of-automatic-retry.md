# Provider 提交结果不确定时失败关闭，进入对账而不自动重提

AIHubMix `/v1` 没有公开幂等键，成功调用也不进入可查询任务列表，因此从请求发出到完整响应落库之间存在「上游可能已生成、平台却没有结果」的不确定窗口。首期明确接受这一 Provider 限制，采用失败关闭策略：

- 本地幂等键与数据库唯一约束保证一个 Job 只建立一个 Attempt；
- Worker 提交前写入 `submitting` 并持续维护租约，**通用重试器不得重放 Provider POST**；
- 只有明确的连接前失败可以重试；请求可能已发出、响应超时、连接中断、进程崩溃或解析失败，全部进入 `reconciliation_required`；
- 不自动切换 Channel / Offering，不重新生成；
- 人工通过上游账单或支持渠道核查，不能恢复结果时按运营规则退款或释放预授权；
- 监控该类事件率；若实际故障率不可接受，再评估 Provider 账单 API、幂等能力或 `/ai/v1` usage，**而不是削弱安全规则**。

Reconciliation Case 保留预授权，当前只允许管理员以幂等业务键退款并释放全部预授权，每次处置写入不可变账本和审计。没有可核验 Metering Evidence 时不能人工确认扣款；未来若能从上游账单取得可核验证据，需另立设计后再增加结算路径。

该项优先保证不重复出图和不重复产生上游成本，代价是极少数模糊失败无法自动恢复结果，需要人工对账。

**来源**：技术设计 v3、v4 与 v5；仓库根 `AGENTS.md` 同样声明该约束。
