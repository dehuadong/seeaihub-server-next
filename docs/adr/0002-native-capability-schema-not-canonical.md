# 不做跨厂商参数大一统，原生能力由不可变 Revision 发布

平台为每个 Vendor Model Revision 保存一份**原生**能力 Schema：保留厂商自己的字段名与条件规则，**不**建立 Canonical 参数大一统，也不构成跨厂商翻译层。它与价格一起随不可变 Runtime Revision 发布，已受理的请求与 Job 固定受理时的版本，运行时请求不随远端文档变化。

**两条配套规则**：实时 Schema 与模型介绍冲突时按保守交集发布首版能力，未证实的参数不开启，每个冲突参数经真实 wire 验证后再发新修订，不在原修订上静默放宽；**未知字段的处置必须由平台在受理前执行**——实测中已有上游会静默接受未声明字段并降级为默认值，这道防线不能外包给上游（2026-09-20 用户把处置定为**丢弃**：不报错、也不发给上游，见 [0018](./0018-open-parameters-by-first-party-docs.md) 的同日修订）。

**2026-09-20 修订（"未证实的参数不开启"的适用范围）**：那条规则针对的是**冲突**与**未知字段**，不是"每个参数都要先花一次计费调用实测"。**渠道第一方文档写明支持的参数就该声明**，并按声明做受理前的取值校验；某个参数**真正需要用时**再验证它在实际端点上的行为（见 [0018](./0018-open-parameters-by-first-party-docs.md)）。**声明面以该模型对应端点的 `request.schema` 为准**（字段、枚举、取值范围都取它）：AIHubMix 的 `background` / `output_compression` / `user` / `moderation` 属 `/ai/v1` 那族（放在 `extra` 里），本平台走的是 `/v1` 那族，端点 schema 里没有这四项，因此素材**不声明**它们。

**2026-09-20**：本条原有的补充决定（输入侧只认渠道原生参数名、平台内部不做映射）已由 [0015](./0015-vendor-model-contract-and-offering-parameter-mapping.md) 取代；以上内容不变。
