# 渠道参数的开启依据是第一方文档，不要求逐个实测

渠道第一方文档（或该渠道公布的机器 Schema）写明支持的参数，**直接声明并开放**；平台按声明在受理前做取值校验。不再要求"每个参数先花一次计费调用实测过才开启"（[0002](./0002-native-capability-schema-not-canonical.md) 的"未证实的参数不开启"收窄为只针对**冲突**与**未知字段**）。

**理由**：把"没实测"当成拦截理由，会让能力面长期小于渠道真实能力，而这层差距不产生任何保护——真正需要防的是"平台声明了却发不出去"（静默降级），那由"未知字段在受理前拒绝"和"取值按声明校验"来兜。某个参数**真正需要用到时**再验证它在实际端点上的行为，那时才值得一次计费调用。

**代价**：文档与实际端点不一致时（渠道文档是 OpenAI 兼容面、机器 Schema 却是另一套参数集合），平台可能先声明、后在使用时才发现打不通；这类不一致按渠道事实登记，不靠"一律不声明"回避。
