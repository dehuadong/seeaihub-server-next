# 渠道错误对客一律改写：只用平台错误码，平台侧故障不得算在消费者头上

渠道的 HTTP 状态码、错误码与原文**只留在内部**（Attempt 的 `provider_error_code` / `provider_error_message` 与管理端对账），对客响应只用平台自己的错误码。**责任方决定对客语义**：渠道因**平台的**参数、凭证、权限、额度或限流而拒绝（APIMart 的 `402`、`403`、`429`、以及用 `500` 承载的参数错误；AIHubMix 的 401 与 403 各分支）一律表现为**平台侧故障**，绝不返回 4xx 让消费者以为是自己错；只有渠道明确因**消费者的内容**而拒绝，才是消费者的 4xx。渠道 5xx 同样**不透传**——它表示我们调用上游失败，对客统一为平台自己的"上游不可用"。

**拿不准时按平台侧处理**。原因：渠道说的"账户余额不足"指的是**我们**在渠道侧的账户（AIHubMix 的错误标识符就叫 `insufficient_user_quota`），原样返回会让消费者去充值而问题在我们；渠道的 5xx 语义也不统一（有渠道用它承载参数错误），透传既误导消费者又泄露渠道信息。宁可让消费者以为是我们的问题，也不要把我们的问题说成他的。

**平台欠费与用户欠费是两个状态**（见 `CONTEXT.md` 的 `Platform Funding Failure` / `Consumer Insufficient Balance`）：用户欠费在**受理前**拒绝、对客可见；平台欠费只在**调用渠道时**才暴露，属**运营事件，必须能被发现与处置**，对客不得表现为"余额不足"。渠道错误的实际码表见 `docs/facts/channel-facts.md` §2.13（AIHubMix）与 §3.10（APIMart）。
