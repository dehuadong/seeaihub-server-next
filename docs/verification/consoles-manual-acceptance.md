# 管理后台与客户控制台的人工验收清单

- **用途**：执行 Spec 的 **V-D7**（`docs/specs/0001-admin-and-customer-consoles.md` §5）——构建产物由 API 托管之后，由**一个人**用浏览器把两套界面走一遍，并记录看到什么、发现什么问题。V-D7 是这套验收条件里唯一写明"不自动化"的一条，其余各条的机器证据见该条自己的说明与 `apps/web/e2e/`。
- **读者**：执行验收的人（运营/运维/开发都行；不需要读代码）。
- **前置**：一个跑着的 API（`/health` 回 `{"status":"ok"}`）与它托管的前端产物。怎么起见 [`apps/web/README.md`](../../apps/web/README.md)。
- **记录方式**：把下面每一节的结论填进本文件末尾的「验收记录」，或写进对应工作项的评论；**发现的问题连带当时的地址与操作一起记**，不要只写"有问题"。

## 0. 地址与账号

| 打开哪个 | 地址 | 应该看到 |
| --- | --- | --- |
| 运营后台 | `http://admin.<domain>/` | 标题「seeai 运营后台」的登录页 |
| 客户控制台 | `http://app.<domain>/` | 标题「seeai 控制台」的登录/注册页 |

本机没有域名时，Chrome/Edge 把 `*.localhost` 解析到回环，所以直接用 `http://admin.localhost:8090/` 与 `http://app.localhost:8090/` 即可（**不用改 hosts**）。也可以按文件名直达两个入口：`/console.html` 与 `/portal.html`——它们在任何主机上都各回自己那一份。

账号：管理员用部署时 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 引导出来的邮箱与口令。**引导只在账号不存在时写入**，所以改过口令之后重启服务不会把它打回去。客户自己注册一个，或在后台「账户与密钥 → 客户登录身份」里替客户开户。

## 1. 管理后台登录（V-D7 的前半）

1. 打开运营后台地址：应当只有登录页，**看不到任何管理数据**（V-D4）。
2. 打开浏览器的网络面板，筛 `/api/v1/`：**在登录之前不该有任何一条**（V-D4 的硬判据）。
3. 用管理员邮箱与口令登录：应当进到后台，左侧出现六个导航项（V-A1）。
4. **刷新页面**：仍是登录态；地址栏里**不出现**任何会话凭据（V-D3）。会话存在标签页的 `sessionStorage` 里，所以换个标签页要重新登录——那是设计，不是故障。
5. 点「退出登录」：回到登录页，且再点一次后台导航不会又进去（V-A2）。

## 2. 六个管理页面（V-D7 的后半）

逐个打开，确认**页面读出的数据与你在库里/上一节的录入一致**，而不是空白或报错：

| 页面 | 看什么 | 期望 |
| --- | --- | --- |
| 网关模型 | 已发布的网关模型清单、每个模型的启用开关 | 列出你自己发布过的那些；名字是对客名，**不出现厂商原生名** |
| 发布修订 | 贴发布素材、发布、看结果 | 能贴能发；缺定价或缺折算率时**拒绝并说明原因** |
| 折算率 | 录入 + **当前生效的折算率**两张表 | 你录的币种与数值出现在下半部分；同币种只有一行 |
| 路由策略 | 策略清单与写入 | 能读能写；写入不改动已发布的修订 |
| 账户与密钥 | 建账户、充值、发/吊销密钥、**客户登录身份** | 能按邮箱找到客户账户、替他开户、给他签一次性重置令牌；账户余额与流水能读 |
| 对账与诊断 | 对账案例、平台侧失败清单、成本缺口 | 三块都读得出数；没有案例时显示空态而不是报错 |

页面读的若是**空库**，大部分会显示"还没有…"的空态——那也算通过。**"页面读的是库里的真实数据"这条有自动化证据**：`apps/web/e2e/admin-reads-fixture-data.spec.ts` 先用管理 API 造事实（一个币种的折算率、一个带初始余额的账户），再让页面去读并断言出现的是**刚造的那组值**；整套跑在每次重建的空库上，所以"读到旧库的状态"不可能蒙对。六个页面里已按这条验的是**折算率**与**账户与密钥**两页，其余四页仍属人工那一半。

## 3. 客户控制台（V-D5、V-C1…V-C14 的人工那一半）

1. 打开客户控制台地址：只看到登录/注册，**没有任何账户数据**。
2. 注册一个新客户：进到控制台，看到四块——**余额与持有**（两个数分开）、**API Key**、**改口令**、**用量与账单**。
3. 建一把 API Key：明文**只显示这一次**；刷新页面之后列表里只有标签、创建时间与状态，**再也找不到明文**。
4. 改口令：改完此前所有登录会话失效（会被带回登录页），用新口令能重新登录。
5. 忘了口令那条路：让运营在后台「客户登录身份」里**签发一枚重置令牌**，把令牌交给客户；客户在登录页下方的「用重置令牌设置新口令」里填令牌与新口令，设置成功后能登录，**同一枚令牌再用一次会被拒**。
6. 用量与账单：跑一次生成请求（或在后台给该账户充值/调账）之后，这里的请求数、产出张数、扣费总额与明细应当对得上——**汇总不随明细条数变化**。

## 4. 不该出现的东西（Spec §3 的非目标）

确认下面这些**没有**入口，也没有暗示它们存在：在线支付/充值通道、邮件发送（含"提交邮箱就收到重置链接"）、账户之间转账、账户合并、第三方登录。客户控制台上应当**明说**充值由运营完成、不能自助重置口令。

### 已经由机器承担的部分

这些是 V-D7 之外各条验收条件的证据，人不用重做，只需知道它们已被覆盖：

- **接口契约**（状态码、鉴权规则、口令链路、账务口径）：`cargo test -p seeai-api --test http_contract -- --ignored`（`cases_identity` / `cases_billing` / `cases_pricing` 等）。
- **浏览器行为**（路由守卫不取数、刷新仍登录、两个入口的分发、密钥明文只出现一次、改口令与重置令牌）：`npm run e2e --prefix apps/web`。
- **产物隔离**（客户产物里不含管理端代码）：`apps/web/README.md` 里那三条带引号的精确路径核对命令。
