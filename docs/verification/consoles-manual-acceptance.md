# 管理后台与客户控制台的人工验收清单

- **用途**：执行 Spec 的 **V-D7**（`docs/specs/0001-admin-and-customer-consoles.md` §5）——构建产物由 API 托管之后，由**一个人**用浏览器把两套界面走一遍，并记录看到什么、发现什么问题。V-D7 是这套验收条件里唯一写明"不自动化"的一条，其余各条的机器证据见该条自己的说明与 `apps/web/e2e/`。
- **读者**：执行验收的人（运营/运维/开发都行；不需要读代码）。
- **前置**：一个跑着的 API（`/health` 回 `{"status":"ok"}`）与它托管的前端产物。怎么起见 [`apps/web/README.md`](../../apps/web/README.md)。
- **记录方式**：把下面每一节的结论填进本文件末尾的「验收记录」，或写进对应工作项的评论；**发现的问题连带当时的地址与操作一起记**，不要只写"有问题"。

## 0. 地址与账号

| 打开哪个 | 地址 | 应该看到 |
| --- | --- | --- |
| 运营后台 | `http://admin.<domain>/` | 标题「seeai 运营后台」的登录页 |
| 客户控制台 | `http://app.<domain>/` | 标题「seeai 控制台」的登录/注册页 |

本机没有域名时，Chrome/Edge 把 `*.localhost` 解析到回环，所以直接用 `http://admin.localhost:8090/` 与 `http://app.localhost:8090/` 即可（**不用改 hosts**）。也可以按文件名直达两个入口：`/console.html` 与 `/portal.html`——它们在任何主机上都各回自己那一份。

账号：管理员用部署时 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 引导出来的邮箱与口令。**引导只在账号不存在时写入**，所以改过口令之后重启服务不会把它打回去。客户自己注册一个，或在后台「客户」页用「开户」替他建一个。

## 1. 管理后台登录（V-D7 的前半）

1. 打开运营后台地址：应当只有登录页，**看不到任何管理数据**（V-D4）。
2. 打开浏览器的网络面板，筛 `/api/v1/`：**在登录之前不该有任何一条**（V-D4 的硬判据）。
3. 用管理员邮箱与口令登录：应当进到后台，左侧出现六个导航项（V-A1）。
4. **刷新页面**：仍是登录态；地址栏里**不出现**任何会话凭据（V-D3）。会话存在标签页的 `sessionStorage` 里，所以换个标签页要重新登录——那是设计，不是故障。
5. 点「退出登录」：回到登录页，且再点一次后台导航不会又进去（V-A2）。

## 2. 六个管理页面（V-D7 的后半）

逐个打开，确认**页面读出的数据与你在库里/上一节的录入一致**，而不是空白或报错：

| 页面 | 看什么 | 期望 |
| --- | --- | --- |
| 模型目录 | 在售的模型清单、每个模型的启用开关；右上角「上架新模型」与每行的「改价」 | 列出你自己上架过的那些；名字是对客名，**不出现厂商原生名** |
| 模型目录 → 上架新模型 | 贴发布素材、发布、看结果 | 能贴能发；缺定价、缺折算率或合同 `model.const` 与型号不符时**拒绝并说明原因** |
| 模型目录 → 改价 | 从某一行点「改价」，看表单里剩什么 | 只有商务字段（倍率、对客费率）；渠道地址、凭证变量名、驱动器与渠道费率**不出现**，由服务端沿用（V-D9） |
| 折算率 | 录入 + **当前生效的折算率**两张表 | 你录的币种与数值出现在下半部分；同币种只有一行 |
| 路由策略 | 策略清单与写入 | 能读能写；写入不改动已发布的修订 |
| 账户 | 建账户、按邮箱／标签查、点一行进账户详情 | 列表（`#/accounts`）与详情（`#/accounts/{id}`）是**两个地址**，详情不在列表下方追加；详情里充值、充值记录、扣费记录、API Key 一次只显示一个模块；余额与流水能读 |
| 客户 | 按邮箱查客户、开户、点「详情」进客户详情 | 列表（`#/customers`）与详情（`#/customers/{id}`）是两个地址；详情可看邮箱与关联账户、进入账户详情、签一次性重置令牌 |
| 对账与诊断 | 对账案例、平台侧失败清单、成本缺口 | 三块都读得出数；没有案例时显示空态而不是报错 |

「上架新模型」与「改价」不是两个页面，它们开在「模型目录」的抽屉里：一页看、一页写会让人看不出两者的联系，所以合成了一页。

页面读的若是**空库**，大部分会显示"还没有…"的空态——那也算通过。**"页面读的是库里的真实数据"这条在大多数页面上有自动化证据**：`apps/web/e2e/admin-reads-fixture-data.spec.ts` 先用管理 API 造事实（一个币种的折算率、一条作用域唯一的策略、一个带初始余额的账户），再让页面去读并断言出现的是**刚造的那组值**；`admin-publishes-a-model.spec.ts` 用表单发布之后断言模型列表里出现该型号；`admin-opens-a-customer.spec.ts` 开户之后断言客户详情里出现该邮箱。这套跑在每次重建的空库上，所以"读到旧库的状态"不可能蒙对。

账户与客户的**列表进入独立详情**还有一层浏览器证据：`admin-console-detail-addresses.spec.ts` 断言点行后地址指向该对象、刷新与前进后退落在同一对象、返回列表保留查找条件、未登录直达不取管理数据、对象不存在时显示找不到且不残留上一个对象；`admin-account-detail-modules.spec.ts` 断言四个模块一次只挂载一个、密钥明文切走即消失。

**对账与诊断页没有这条浏览器证据，也不假装它有**：它的三块事实要真跑一笔生成才出得来（上游给不出确定终态），浏览器用例里造不起；`admin-reads-fixture-data.spec.ts` 里那一条只断言三块都渲染出来、空库时给空态而不是报错。三块事实由接口层用例覆盖，都是真库真进程：对账案例（执行级）`cases_parameters::post_acceptance_failure_keeps_the_task_id_for_reconciliation`、对账案例（账户级）`cases_lifecycle::the_ledger_audit_reports_a_balance_that_disagrees_with_its_entries`、平台侧失败清单 `cases_lifecycle::channel_rejections_reach_consumers_as_platform_problems`、成本缺口 `cases_cost_facts::a_cost_gap_is_listed_for_operations_without_pushing_the_job_into_reconciliation`。V-D2 在对账页那一半的证据因此在接口层，页面这一层按上表核对。

## 3. 客户控制台（V-D5、V-C1…V-C14 的人工那一半）

1. 打开客户控制台地址：只看到登录/注册，**没有任何账户数据**。
2. 注册一个新客户：进到控制台，固定导航有**五条独立地址**——`/` 概览、`/usage` 调用记录、`/billing` 账单与资金记录、`/keys` API Key、`/settings` 账户设置。逐个打开，确认地址、导航选中项与页面内容一一对应，且各页只显示自己那一块：

| 地址 | 页面 | 人工看什么 |
| --- | --- | --- |
| `/` | 概览 | 首屏只有**已结算余额**（不出现可用额、持有中或预授权金额），以及通往调用记录、账单与资金记录、API Key 的入口；没有"扣费总额（全部）"或无区间说明的平均扣费。 |
| `/usage` | 调用记录 | 处理中请求与已结束历史分开；历史给出请求时刻、终态时刻、型号、对客状态、产出张数与实际扣费。 |
| `/billing` | 账单与资金记录 | 汇总给出请求数、产出张数与扣费净额，并标出日期区间与时区；资金流水区分充值、实际扣费与资金调整。 |
| `/keys` | API Key | 列出标签、创建时间与状态，可新建与吊销；吊销前有确认。 |
| `/settings` | 账户设置 | 登录邮箱、可复制的账户 id、改口令与退出。 |

3. 刷新这五条地址、用浏览器前进后退：各自回到对应页面，地址栏里不出现会话凭据或 API Key。
4. 建一把 API Key：明文**只显示这一次**；关闭一次性展示或刷新页面之后，列表里只有标签、创建时间与状态，**再也找不到明文**。
5. 改口令：改完此前所有登录会话失效（会被带回登录页），用新口令能重新登录。
6. 忘了口令那条路：让运营在后台「客户」页打开该客户详情、**签发一枚重置令牌**，把令牌交给客户；客户在登录页下方的「用重置令牌设置新口令」里填令牌与新口令，设置成功后能登录，**同一枚令牌再用一次会被拒**。
7. 账务对得上：跑一次生成请求（或在后台给该账户充值/调账）之后，调用记录里的明细与账单里的请求数、产出张数、扣费净额、资金流水应当对得上——**汇总不随明细条数变化**。

## 4. 不该出现的东西（Spec §3 的非目标）

确认下面这些**没有**入口，也没有暗示它们存在：在线支付/充值通道、邮件发送（含"提交邮箱就收到重置链接"）、账户之间转账、账户合并、第三方登录。客户控制台上应当**明说**充值由运营完成、不能自助重置口令。

### 2026-09-27 的执行记录

执行人：**不是人**——这一轮由 Agent 执行了 V-D7 里**可以用 HTTP 判定**的部分，并留档如下。**"一个人用浏览器看一遍界面渲染得对不对"这一半仍然没人做过**，所以 V-D7 未结清。

先说做不到的那半，免得把下面这些当成整条通过：V-D7 的判据是"由**一个人**用浏览器打开并逐个确认"，其中"页面渲染得对不对、有没有说清它自己"只有人眼能判。Agent 能观测的是**页面读的那些端点回什么**（页面每个取数都走 `apps/web/src/console/client.ts` 里的路径）。

**已核**（`scripts/verification/console-page-probe.mjs`，对着一个跑着的 API 与有数据的库）：

- `/health` 回 `{"status":"ok"}`；
- 六个页面读的端点全通，且**读得到刚造的事实**而不是空态：`/api/v1/gateway-models`（列出 `gpt-image-2.5-flare`）、`/api/v1/fx-rates`、`/api/v1/route-policies`、`/api/v1/accounts`、`/api/v1/customers`、`/api/v1/reconciliation-cases` 与 `/api/v1/provider-failures`、`/api/v1/provider-cost-gaps`；
- 账户面：建账户（初值 25 元）→ 余额 `25000000` 微单位、流水 1 条 `credit`、`total=1`、`truncated=false`；
- 客户面：用 `account_id` 替客户开户成功，`/api/v1/customers?limit=20` 里能看到该邮箱**绑在同一个账户上**（V-D11 的机器那一半）；
- 两个入口可用（V-D1）：`/console.html` 与 `/portal.html` 在任何主机上各回自己那一份，产物隔离核对在 `npm run build` 末尾通过。

**留档的界面图像**：`apps/web/screenshots/` 下十张整页截图（`npm run capture`，由 Playwright 托管 API 与产物），覆盖登录页、六个管理页面、上架新模型的抽屉与客户控制台。它是**渲染留档**，不是人工结论。

**未做**：第 4 节（非目标里有没有暗示入口）与"某一页讲不讲得清它自己"这类判断；按文件名直达两个入口之外的主机分发（`admin.<domain>` / `app.<domain>`）也没在真域名下试过，试的是 `*.localhost`。

### 已经由机器承担的部分

这些是 V-D7 之外各条验收条件的证据，人不用重做，只需知道它们已被覆盖：

- **接口契约**（状态码、鉴权规则、口令链路、账务口径）：`cargo test -p seeai-api --test http_contract -- --ignored`（`cases_identity` / `cases_billing` / `cases_pricing` 等）。
- **浏览器行为**（路由守卫不取数、刷新仍登录且 URL 不含凭据、两个入口的分发、密钥明文只出现一次、改口令与重置令牌、页面读出库里的真实数据）：`npm run e2e --prefix apps/web`。
- **产物隔离**（客户产物里不含管理端代码，反之亦然）：`npm run build --prefix apps/web` 末尾自带这条核对，也可单独跑 `npm run check:isolation --prefix apps/web`。
