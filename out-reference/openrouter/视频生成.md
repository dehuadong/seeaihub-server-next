# 视频生成

> 如何使用 OpenRouter 模型生成视频

OpenRouter 通过专用的异步 API 支持基于文本提示（以及可选的参考图像）生成视频。您可以通过筛选我们的[支持视频输出的模型列表](https://openrouter.ai/docs/guides/overview/models?output_modalities=video)来查看支持的模型、其功能和定价。

## 模型发现

您可以通过多种方式查找视频生成模型：

### 通过视频模型 API

使用专用的视频模型端点列出所有可用的视频生成模型及其支持的参数：

```bash lines theme={null}
curl "https://openrouter.ai/api/v1/videos/models"
```

响应返回一个 `data` 数组，每个模型包含以下字段：

```json lines theme={null}
{
  "data": [
    {
      "id": "google/veo-3.1",
      "canonical_slug": "google/veo-3.1",
      "name": "Google: Veo 3.1",
      "description": "...",
      "created": 1719792000,
      "supported_resolutions": ["720p", "1080p"],
      "supported_aspect_ratios": ["16:9", "9:16", "1:1"],
      "supported_sizes": ["1280x720", "1920x1080"],
      "pricing_skus": {
        "per-video-second": "0.50",
        "per-video-second-1080p": "0.75"
      },
      "allowed_passthrough_parameters": ["output_config"]
    }
  ]
}
```

| 字段 | 描述 |
| -------------------------------- | --------------------------------------------------------------------------------- |
| `id` | 生成请求中使用的模型标识符 |
| `canonical_slug` | 永久模型标识符 |
| `supported_resolutions` | 支持的输出分辨率列表（例如 `720p`、`1080p`） |
| `supported_aspect_ratios` | 支持的宽高比列表（例如 `16:9`、`9:16`） |
| `supported_sizes` | 支持的像素尺寸列表（例如 `1280x720`） |
| `pricing_skus` | 每个 SKU 的定价信息 |
| `allowed_passthrough_parameters` | 可通过 `provider` 选项传递的提供商特定参数 |

在提交生成请求之前，使用此端点检查每个模型支持的分辨率、宽高比和透传参数。

### 通过模型 API

您还可以在[模型 API](/api/api-reference/models/list-all-models-and-their-properties) 中使用 `output_modalities` 查询参数来发现视频生成模型：

```bash lines theme={null}
# 仅列出视频生成模型
curl "https://openrouter.ai/api/v1/models?output_modalities=video"
```

### 在模型页面上

访问[模型页面](/guides/overview/models)并按输出模态筛选，以查找能够生成视频的模型。查找在其输出模态中列出 `"video"` 的模型。

## 工作原理

与文本或图像生成不同，视频生成是**异步**的，因为生成视频需要更长的时间。工作流程如下：

1. **提交** 生成请求到 `POST /api/v1/videos`
2. **立即接收** 任务 ID 和轮询 URL
3. **轮询** 轮询 URL（`GET /api/v1/videos/{jobId}`）直到状态变为 `completed`
4. **从内容 URL 下载** 视频（`GET /api/v1/videos/{jobId}/content`）

## API 使用

### 提交视频生成请求

```python Python 可展开 lines theme={null}
    import requests
    import json
    import time

    url = "https://openrouter.ai/api/v1/videos"
    headers = {
        "Authorization": f"Bearer {API_KEY_REF}",
        "Content-Type": "application/json"
    }

    payload = {
        "model": "google/veo-3.1",
        "prompt": "一只金毛猎犬在阳光明媚的海滩上玩接球游戏，背景中海浪拍打"
    }

    # 步骤 1：提交生成请求
    response = requests.post(url, headers=headers, json=payload)
    result = response.json()

    job_id = result["id"]
    polling_url = result["polling_url"]
    print(f"任务已提交：{job_id}")
    print(f"状态：{result['status']}")

    # 步骤 2：轮询直到完成
    while True:
        time.sleep(30)  # 轮询间隔 30 秒
        poll_response = requests.get(polling_url, headers=headers)
        status = poll_response.json()

        print(f"状态：{status['status']}")

        if status["status"] == "completed":
            # 步骤 3：下载视频
            content_url = status["unsigned_urls"][0]
            video_response = requests.get(content_url)
            with open("output.mp4", "wb") as f:
                f.write(video_response.content)
            print("视频已保存为 output.mp4")
            break
        elif status["status"] == "failed":
            print(f"生成失败：{status.get('error', '未知错误')}")
            break
```

```typescript title="TypeScript (fetch)" 可展开 lines theme={null}

```

### 请求参数

| 参数 | 类型 | 是否必需 | 描述 |
| ------------------ | ------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `model` | string | 是 | 用于视频生成的模型（例如 `google/veo-3.1`） |
| `prompt` | string | 是 | 要生成的视频的文本描述 |
| `duration` | integer | 否 | 生成视频的时长（秒） |
| `resolution` | string | 否 | 输出视频的分辨率（例如 `720p`、`1080p`） |
| `aspect_ratio` | string | 否 | 输出视频的宽高比（例如 `16:9`、`9:16`、`3:2`） |
| `size` | string | 否 | 精确像素尺寸，格式为 `宽度x高度`（例如 `1280x720`）。可与 `resolution` + `aspect_ratio` 互换使用 |
| `frame_images` | array | 否 | 首帧/尾帧图像（图像转视频） |
| `input_references` | array | 否 | 风格引导参考图像（参考转视频） |
| `generate_audio` | boolean | 否 | 是否在生成视频的同时生成音频。对于支持音频输出的模型，默认为 `true` |
| `seed` | integer | 否 | 确定性生成的种子（并非所有提供商都保证） |
| `callback_url` | string | 否 | 任务完成时接收 Webhook 通知的 URL。如果设置，将覆盖工作区级别的默认回调 URL。必须是 HTTPS |
| `provider` | object | 否 | 提供商特定的透传配置 |

### 支持的分辨率

* `480p`
* `720p`
* `1080p`
* `1K`
* `2K`
* `4K`

### 支持的宽高比

* `16:9` — 宽屏横向
* `9:16` — 竖屏/纵向
* `1:1` — 方形
* `4:3` — 标准横向
* `3:4` — 标准纵向
* `3:2` — 摄影横向
* `2:3` — 摄影纵向
* `21:9` — 超宽
* `9:21` — 超高

### 使用图像

提供图像有两种方式，每种方式触发不同的生成模式：

* **`frame_images`** — 指定**图像转视频**生成的首帧或尾帧图像。每个条目必须包含 `frame_type`，值为 `first_frame` 或 `last_frame`。
* **`input_references`** — 为**参考转视频**生成提供风格或内容参考图像。模型将这些图像作为视觉指导而非精确帧。

如果同时提供了这两个字段，`frame_images` 优先，请求将被视为图像转视频。

#### 图像转视频（frame_images）

```json lines theme={null}
{
  "model": "alibaba/wan-2.7",
  "prompt": "一个角色在森林中行走",
  "frame_images": [
    {
      "type": "image_url",
      "image_url": {
        "url": "https://example.com/first-frame.png"
      },
      "frame_type": "first_frame"
    }
  ],
  "resolution": "1080p"
}
```

#### 参考转视频（input_references）

```json lines theme={null}
{
  "model": "alibaba/wan-2.7",
  "prompt": "行星旁的巨大太阳耀斑",
  "input_references": [
    {
      "type": "image_url",
      "image_url": {
        "url": "https://example.com/style-ref.png"
      }
    }
  ],
  "resolution": "1080p"
}
```

### 提供商特定选项

您可以使用 `provider` 参数传递提供商特定选项。选项按提供商标识符键控，只有匹配的提供商的选项会被转发：

```json lines theme={null}
{
  "model": "google/veo-3.1",
  "prompt": "花朵盛开的延时摄影",
  "provider": {
    "options": {
      "google-vertex": {
        "parameters": {
          "personGeneration": "allow",
          "negativePrompt": "模糊，低质量"
        }
      }
    }
  }
}
```

使用[视频模型 API](#通过视频模型-api) 检查每个模型通过 `allowed_passthrough_parameters` 字段支持哪些透传参数。

## 响应格式

### 提交响应（202 已接受）

当您提交视频生成请求时，您会立即收到包含任务详情的响应：

```json lines theme={null}
{
  "id": "abc123",
  "polling_url": "https://openrouter.ai/api/v1/videos/abc123",
  "status": "pending"
}
```

### 轮询响应

轮询任务状态时，响应会随着任务的推进包含额外字段：

```json lines theme={null}
{
  "id": "abc123",
  "generation_id": "gen-1234567890-abcdef",
  "polling_url": "https://openrouter.ai/api/v1/videos/abc123",
  "status": "completed",
  "unsigned_urls": [
    "https://openrouter.ai/api/v1/videos/abc123/content?index=0"
  ],
  "usage": {
    "cost": 0.25,
    "is_byok": false
  }
}
```

### 任务状态

| 状态 | 描述 |
| ------------- | ----------------------------------------------- |
| `pending` | 任务已提交并排队 |
| `in_progress` | 视频正在生成中 |
| `completed` | 视频已就绪，可下载 |
| `failed` | 生成失败（请检查 `error` 字段） |

### 下载视频

当任务状态为 `completed` 时，`unsigned_urls` 数组包含用于下载生成视频内容的 URL。您也可以直接使用内容端点：

```bash lines theme={null}
curl "https://openrouter.ai/api/v1/videos/{jobId}/content?index=0" \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  --output video.mp4
```

`index` 查询参数默认为 `0`，当模型生成多个视频输出时可以使用。

## Webhook

您可以不再轮询任务状态，而是在视频生成任务完成时接收 Webhook 通知。配置回调 URL 有两种方式：

1. **每个请求单独设置**：在请求体中传递 `callback_url`。这将优先于工作区默认值。
2. **工作区默认设置**：在您的[工作区设置](/guides/features/workspaces)中设置默认回调 URL。这将应用于所有未指定自己 `callback_url` 的视频生成请求。

### Webhook 载荷

当任务达到终态时，会向回调 URL 发送一个 POST 请求，包含事件信封。每次投递还携带一个 `X-OpenRouter-Idempotency-Key` 头，格式为 `<job_id>-<status>`，用于安全的重试去重。

### 签名密钥

您可以在[工作区设置](/guides/features/workspaces)中配置签名密钥，以验证 Webhook 载荷确实来自 OpenRouter。当配置了签名密钥时，每次 Webhook 投递都会包含一个 `X-OpenRouter-Signature` 头。

签名包含时间戳和 HMAC 哈希：

```lines theme={null}
X-OpenRouter-Signature: t=1234567890,v1=a1b2c3d4...
```

### 验证签名

要在您的 Webhook 接收端验证签名：

1. 从头部提取时间戳（`t`）和签名哈希（`v1`）
2. 构造签名载荷：`{timestamp},{raw_request_body}`（用逗号连接）
3. 使用签名密钥作为密钥，计算签名载荷的 HMAC-SHA256
4. 将十六进制编码的结果与 `v1` 值进行比较

```typescript 可展开 lines theme={null}
import crypto from 'crypto';

const FIVE_MINUTES_IN_SECONDS = 300;

function verifyWebhookSignature(
  rawBody: string,
  signatureHeader: string,
  secret: string,
): boolean {
  const parts = signatureHeader.split(',');
  const timestamp = parts.find((p) => p.startsWith('t='))?.slice(2);
  const hash = parts.find((p) => p.startsWith('v1='))?.slice(3);

  if (!timestamp || !hash) {
    return false;
  }

  // 拒绝超过 5 分钟的时间戳，以防止重放攻击
  const age = Math.floor(Date.now() / 1000) - Number(timestamp);
  if (Number.isNaN(age) || age > FIVE_MINUTES_IN_SECONDS) {
    return false;
  }

  const signedPayload = `${timestamp},${rawBody}`;
  const expected = crypto
    .createHmac('sha256', secret)
    .update(signedPayload)
    .digest('hex');

  if (expected.length !== hash.length) {
    return false;
  }

  return crypto.timingSafeEqual(
    Buffer.from(expected),
    Buffer.from(hash),
  );
}
```

<Warning>
  使用**原始请求体**（接收到的精确字节）进行验证。解析并重新序列化 JSON 可能会改变键的顺序或数字格式，导致验证失败。
</Warning>

## 最佳实践

* **详细的提示词**：提供具体、描述性的提示词以获得更好的视频质量。包括关于运动、摄像机角度、光照和场景构图的细节
* **适当的分辨率**：更高的分辨率生成时间更长且成本更高。选择适合您用例的分辨率
* **轮询间隔**：使用合理的轮询间隔（例如 30 秒）以避免过多的 API 调用。视频生成通常需要 30 秒到几分钟，具体取决于模型和参数
* **错误处理**：始终检查任务状态是否为 `failed` 状态，并适当处理 `error` 字段
* **参考图像**：使用参考图像时，确保它们质量高且与所需的视频输出相关

## 零数据保留

视频生成**不符合**[零数据保留（ZDR）](/guides/features/zdr)的资格。由于视频生成是异步的，生成的视频输出必须由提供商短暂保留，以便在生成完成后可以检索。这种临时保留是异步轮询工作流固有的，无法绕过。

如果您启用了 ZDR 强制（通过[账户设置](https://openrouter.ai/settings/privacy)或每个请求的 `zdr` 参数），视频生成请求将不会被路由。

## 故障排除

**任务长时间处于 `pending` 状态？**

* 视频生成可能需要几分钟，具体取决于模型、分辨率和服务器负载
* 按固定间隔继续轮询

**生成失败？**

* 检查轮询响应中的 `error` 字段以获取详情
* 验证模型支持视频生成（`output_modalities` 包含 `"video"`）
* 确保您的提示词合适且在模型指南范围内
* 检查所有参考图像是否可访问且格式受支持

**找不到模型？**

* 使用[视频模型 API](#通过视频模型-api) 或[模型页面](/guides/overview/models)查找可用的视频生成模型
* 验证模型标识符是否正确（例如 `google/veo-3.1`）
