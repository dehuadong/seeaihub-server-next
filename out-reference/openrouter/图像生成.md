# 图像生成

> 如何使用 OpenRouter 的专用图像 API 生成图像

 

export const API_KEY_REF = '<OPENROUTER_API_KEY>';

OpenRouter 提供了一个专用图像 API，用于根据文本提示（以及可选的参考图像）生成图像。该 API 涵盖模型发现、每个端点的能力以及生成功能。您可以在[按图像输出筛选的模型页面](https://openrouter.ai/models?output_modalities=image)上浏览可用模型和定价。

## 模型发现

### 通过图像模型 API

专用图像模型端点列出了每个可用图像模型及其能力：

```bash lines theme={null}
curl "https://openrouter.ai/api/v1/images/models"
```

`data` 数组中的每个条目包括：

```json lines theme={null}
{
  "data": [
    {
      "id": "bytedance-seed/seedream-4.5",
      "name": "Seedream 4.5",
      "description": "一个文本转图像模型。",
      "created": 1692901234,
      "architecture": {
        "input_modalities": ["text", "image"],
        "output_modalities": ["image"]
      },
      "supported_parameters": {
        "resolution": { "type": "enum", "values": ["1K", "2K", "4K"] },
        "seed": { "type": "boolean" }
      },
      "supports_streaming": false,
      "endpoints": "/api/v1/images/models/bytedance-seed/seedream-4.5/endpoints"
    }
  ]
}
```

| 字段                   | 描述                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `id`                   | 在生成请求中使用的模型标识符                                                                                                  |
| `architecture`         | 模型接受的输入和输出模态                                                                                                      |
| `supported_parameters` | 所有端点能力的并集。每个键是一个请求字段名；值是一个[能力描述符](#能力描述符)                                                 |
| `supports_streaming`   | 是否有任何端点支持原生 SSE 流式传输（`stream: true`）                                                                         |
| `endpoints`            | 该模型完整每个端点记录的 URL                                                                                                  |

### 每个端点的记录

每个模型可能由多个提供商提供。要查看每个端点的最终能力、定价和直通选项：

```bash lines theme={null}
curl "https://openrouter.ai/api/v1/images/models/bytedance-seed/seedream-4.5/endpoints"
```

```json lines theme={null}
{
  "id": "bytedance-seed/seedream-4.5",
  "endpoints": [
    {
      "provider_name": "Bytedance",
      "provider_slug": "bytedance",
      "provider_tag": "bytedance",
      "supported_parameters": {
        "resolution": { "type": "enum", "values": ["1K", "2K", "4K"] },
        "seed": { "type": "boolean" }
      },
      "allowed_passthrough_parameters": [],
      "supports_streaming": false,
      "pricing": [
        { "billable": "output_image", "unit": "image", "cost_usd": 0.05 }
      ]
    }
  ]
}
```

| 字段                               | 描述                                                                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `provider_slug`                  | 在 `provider.options[slug]` 中使用，以传递特定于提供商的参数                                                                                                                               |
| `provider_tag`                   | 用于将请求固定到特定提供商。当提供商级别的路由不可用时为 `null`                                                                                                                                       |
| `supported_parameters`           | *此*端点接受的最终参数集（模型级别并集的子集）                                                                                                                                                  |
| `allowed_passthrough_parameters` | 在 `provider.options[provider_slug]` 下接受的特定于提供商的键                                                                                                                          |
| `supports_streaming`             | *此*端点是否支持原生 SSE 流式传输                                                                                                                                                      |
| `pricing`                        | 此端点的计费定价行。每个条目有 `billable`（例如 `output_image`、`input_image`、`input_reference`）、`unit`（`image`、`megapixel` 或 `token`）、`cost_usd`，以及一个可选的 `variant` 层级（例如分辨率分层定价的 `2k`、`4k`） |

### 能力描述符

`supported_parameters` 映射使用类型化描述符来描述每个请求字段接受的内容：

| 类型      | 结构                                          | 含义                                      |
| --------- | ---------------------------------------------- | ---------------------------------------- |
| `enum`    | `{ type: "enum", values: ["1K", "2K", "4K"] }` | 离散的允许字符串值列表                    |
| `range`   | `{ type: "range", min: 0, max: 100 }`          | `[min, max]` 范围内的任意整数均有效       |
| `boolean` | `{ type: "boolean" }`                          | 支持（存在）或不支持（不存在）            |

缺少的键表示该端点不支持该参数。

### 通过模型 API

您还可以通过通用[模型 API]发现图像模型：

```bash lines theme={null}
curl "https://openrouter.ai/api/v1/models?output_modalities=image"
```

### 在模型页面

访问[模型页面](/models)并按输出模态筛选，以查找具有图像生成能力的模型。

## API 使用

向 `/api/v1/images` 发送 `POST` 请求，包含模型和提示词：

```python title="Python (requests)" lines theme={null}
    import requests
    import json

    url = "https://openrouter.ai/api/v1/images"
    headers = {
        "Authorization": f"Bearer {API_KEY_REF}",
        "Content-Type": "application/json"
    }

    payload = {
        "model": "bytedance-seed/seedream-4.5",
        "prompt": "a red panda astronaut floating in space, studio lighting"
    }

    response = requests.post(url, headers=headers, json=payload)
    result = response.json()

    for image in result["data"]:
        # image["b64_json"] 包含 base64 编码的图像
        print(f"Generated image ({len(image['b64_json'])} chars)")
        
```

```typescript title="TypeScript (fetch)" lines theme={null}
    const response = await fetch('https://openrouter.ai/api/v1/images', {
      method: 'POST',
      headers: {
        Authorization: `Bearer ${API_KEY_REF}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        model: '{{MODEL}}',
        prompt: 'a red panda astronaut floating in space, studio lighting',
      }),
    });

    const result = await response.json();

    for (const image of result.data) {
      // image.b64_json 包含 base64 编码的图像
      console.log(`Generated image (${image.b64_json.length} chars)`);
    }
    
```

```bash title="cURL" lines theme={null}
    curl -X POST "https://openrouter.ai/api/v1/images" \
      -H "Authorization: Bearer $OPENROUTER_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "{{MODEL}}",
        "prompt": "a red panda astronaut floating in space, studio lighting"
      }'
      
```


### 响应格式

图像以 base64 编码的字节形式返回。当可用时，`usage` 字段报告令牌计数和成本。

当格式可识别时（包括 `image/png`），`media_type` 字段存在，仅在无法确定时省略：

```json lines theme={null}
{
  "created": 1748372400,
  "data": [
    {
      "b64_json": "<base64-encoded-image>",
      "media_type": "image/png"
    }
  ],
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 4175,
    "total_tokens": 4175,
    "cost": 0.04
  }
}
```

对于非 PNG 输出（例如来自 Recraft 矢量模型的 JPEG、WebP 或 SVG），`media_type` 反映实际格式：

```json lines theme={null}
{
  "created": 1748372400,
  "data": [
    {
      "b64_json": "<base64-encoded-image>",
      "media_type": "image/svg+xml"
    }
  ],
  "usage": {
    "prompt_tokens": 0,
    "completion_tokens": 4175,
    "total_tokens": 4175,
    "cost": 0.04
  }
}
```

## 图像配置选项

### 分辨率和宽高比

使用 `resolution`、`aspect_ratio` 或便捷的 `size` 简写控制输出尺寸：

```json lines theme={null}
{
  "model": "bytedance-seed/seedream-4.5",
  "prompt": "a landscape photo",
  "resolution": "2K",
  "aspect_ratio": "16:9"
}
```

* `resolution` — 标准化层级（`512`、`1K`、`2K`、`4K`）。具体像素尺寸由各提供商自行推导。
* `aspect_ratio` — 标准化比例。传入 `auto` 让提供商自行选择。常见值包括 `1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`3:2`、`2:3`、`4:5`、`5:4`，以及扩展比例如 `1:2`、`2:1`、`1:4`、`4:1`、`1:8`、`8:1`、`9:21`、`21:9`。提供商会限制在其支持的子集内 — 请检查模型的 `supported_parameters` 以获取可接受的值。
* `size` — 便捷简写。传入层级（`"2K"`）或显式像素（`"2048x2048"`），它将为提供商进行标准化。层级尺寸等同于设置 `resolution` 并与 `aspect_ratio` 结合使用。显式像素尺寸是权威的 — 如果同时传入不匹配的 `resolution` 或 `aspect_ratio`，将返回 400 错误被拒绝。

检查模型的 `supported_parameters` 以查看每个端点接受哪些值。

### 质量和输出格式

```json lines theme={null}
{
  "model": "openai/gpt-image-1",
  "prompt": "a product photo",
  "quality": "high",
  "output_format": "png",
  "background": "transparent"
}
```

* `quality` — `auto`、`low`、`medium` 或 `high`。没有质量调节功能的提供商将忽略此参数。
* `output_format` — `png`、`jpeg`、`webp` 或 `svg`（仅限矢量化模型；SVG 标记在 `b64_json` 中以 base64 编码）。
* `background` — `auto`、`transparent` 或 `opaque`。`transparent` 需要支持 alpha 通道的格式（png 或 webp）。
* `output_compression` — webp/jpeg 的 0–100 压缩级别。对 png 忽略。

### 多图像生成

每次调用使用 `n` 请求最多 10 张图像：

```json lines theme={null}
{
  "model": "openai/gpt-image-1",
  "prompt": "a cute cat",
  "n": 4
}
```

并非所有提供商都支持 `n > 1`。检查模型的 `supported_parameters` 以了解可用性。

### 图像到图像（参考图像）

通过 `input_references` 传递参考图像以引导生成：

```json lines theme={null}
{
  "model": "openai/gpt-image-1",
  "prompt": "make this scene look like a watercolor painting",
  "input_references": [
    {
      "type": "image_url",
      "image_url": {
        "url": "https://example.com/photo.jpg"
      }
    }
  ]
}
```

参考图像可以是 HTTP(S) URL 或 base64 数据 URL。接受的参考图像数量因提供商而异。

### 提供商路由

当模型有多个提供商时，使用 `provider` 对象选择哪些端点可以服务请求：

```json lines theme={null}
{
  "model": "google/gemini-2.5-flash-image",
  "prompt": "a red panda astronaut floating in space",
  "provider": {
    "only": ["google-ai-studio"],
    "allow_fallbacks": false
  }
}
```

图像 API 支持以下路由字段：

* `only` — 仅允许列出的提供商标识符。
* `order` — 按列出的顺序尝试提供商。
* `ignore` — 排除列出的提供商标识符。
* `sort` — 按 `price`、`throughput` 或 `latency` 对符合条件的端点排序。
* `allow_fallbacks` — 当为 `false` 时，在主提供商之后停止，不再尝试其他符合条件的提供商。

使用[每个端点记录](#每个端点的记录)中的 `provider_tag` 作为基础提供商标识符。有关 OpenRouter API 共享的路由行为，请参见[提供商路由](https://openrouter.ai/docs/guides/routing/provider-selection.md)。

### 特定于提供商的选项

通过 `provider.options` 传递特定于提供商的参数，使用端点 API 中的提供商标识符作为键：

```json lines theme={null}
{
  "model": "black-forest-labs/flux.2-pro",
  "prompt": "a dramatic portrait",
  "provider": {
    "options": {
      "black-forest-labs": {
        "steps": 40,
        "guidance": 3
      }
    }
  }
}
```

每个端点记录中的 `allowed_passthrough_parameters` 字段列出了接受哪些键。

## 流式图像生成

支持原生 SSE 流式传输的模型（发现 API 中 `supports_streaming: true`）可以在生成过程中返回部分图像：

```json lines theme={null}
{
  "model": "openai/gpt-image-1",
  "prompt": "a detailed landscape",
  "stream": true
}
```

响应是一个包含三种事件类型的 SSE 流：

**部分图像** — 在每个部分渲染可用时发出：

```
data: {"type":"image_generation.partial_image","partial_image_index":0,"b64_json":"<base64>"}
```

**完成** — 在最终图像就绪时发出。当格式可识别时，`media_type` 字段存在：

```
data: {"type":"image_generation.completed","b64_json":"<base64>","media_type":"image/png","created":1748372400,"usage":{"prompt_tokens":16,"completion_tokens":272,"total_tokens":288,"cost":0.011}}
```

对于非 PNG 输出（例如来自 Recraft 矢量模型的 SVG），`media_type` 反映实际格式：

```
data: {"type":"image_generation.completed","b64_json":"<base64>","media_type":"image/svg+xml","created":1748372400,"usage":{"prompt_tokens":16,"completion_tokens":272,"total_tokens":288,"cost":0.011}}
```

完成事件中的 `usage` 对象包含 `cost`（美元），与缓冲响应结构匹配。

**错误** — 如果在流中间生成失败，则发出：

```
data: {"type":"error","error":{"message":"Generation failed","code":"server_error"}}
```

流以 `data: [DONE]` 终止。

```python title="Python (requests)" expandable lines theme={null}
    import requests

    url = "https://openrouter.ai/api/v1/images"
    headers = {
        "Authorization": f"Bearer {API_KEY_REF}",
        "Content-Type": "application/json"
    }

    response = requests.post(url, headers=headers, json={
        "model": "openai/gpt-image-1",
        "prompt": "a detailed landscape painting",
        "stream": True
    }, stream=True)

    for line in response.iter_lines():
        if line:
            decoded = line.decode("utf-8")
            if decoded.startswith("data: ") and decoded != "data: [DONE]":
                import json
                event = json.loads(decoded[6:])
                print(f"Event: {event['type']}")
```

```typescript title="TypeScript (fetch)" expandable lines theme={null}
    const response = await fetch('https://openrouter.ai/api/v1/images', {
      method: 'POST',
      headers: {
        Authorization: `Bearer ${API_KEY_REF}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        model: 'openai/gpt-image-1',
        prompt: 'a detailed landscape painting',
        stream: true,
      }),
    });

    const reader = response.body?.getReader();
    const decoder = new TextDecoder();

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      const chunk = decoder.decode(value);
      for (const line of chunk.split('\n')) {
        if (line.startsWith('data: ') && line !== 'data: [DONE]') {
          const event = JSON.parse(line.slice(6));
          console.log(`Event: ${event.type}`);
        }
      }
    }
```

```bash title="cURL" lines theme={null}
    curl -N -X POST "https://openrouter.ai/api/v1/images" \
      -H "Authorization: Bearer $OPENROUTER_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "openai/gpt-image-1",
        "prompt": "a detailed landscape painting",
        "stream": true
      }'
```


## 计费和取消

图像生成计费是**全有或全无**的。生成要么完成并全额计费，要么失败且不计费 — 不存在部分或分数图像计费。这与聊天补全不同，后者的取消流仍会为取消前产生的令牌计费。

* **完成的生成**根据端点的定价对完整图像输出进行计费。
* **失败或取消的生成**不计费。当生成未完成时，请求返回 `502 Bad Gateway` 而不是部分结果，并且不记录任何费用。

如果客户端在生成过程中断开连接，上游提供商可能仍会完成图像渲染并向 OpenRouter 收费。无论如何，客户端只观察到两种结果之一：完全计费的结果或错误。OpenRouter 不会尝试对用户未收到的工作进行计费。

对于流式请求，在流结束之前传递的任何部分预览图像都**不会**产生部分费用。计费以最终图像的完成为依据，因此提前终止的流（客户端断开或流中间错误）完全等同于失败的生成：完全不收费。

## 请求参数

| 参数                      | 类型             | 必需 | 描述                                                                |
| -------------------------- | ---------------- | ---- | ------------------------------------------------------------------- |
| `model`                    | string           | 是   | 模型标识符（例如 `bytedance-seed/seedream-4.5`）                    |
| `prompt`                   | string           | 是   | 所需图像的文本描述                                                  |
| `n`                        | integer          | 否   | 要生成的图像数量（1–10）                                            |
| `resolution`               | string           | 否   | 分辨率层级（`512`、`1K`、`2K`、`4K`）                               |
| `aspect_ratio`             | string           | 否   | 宽高比（`1:1`、`16:9`、`9:16`、`4:3`、`3:4`、`1:4`、`4:1` 等）      |
| `size`                     | string           | 否   | 便捷简写 — 层级或显式像素（`"2048x2048"`）                          |
| `quality`                  | string           | 否   | `auto`、`low`、`medium` 或 `high`                                   |
| `output_format`            | string           | 否   | `png`、`jpeg`、`webp` 或 `svg`                                      |
| `background`               | string           | 否   | `auto`、`transparent` 或 `opaque`                                   |
| `output_compression`       | integer          | 否   | webp/jpeg 的压缩级别（0–100）                                       |
| `seed`                     | integer          | 否   | 确定性生成的种子（在支持的情况下）                                   |
| `stream`                   | boolean          | 否   | 通过 SSE 流式传输部分图像                                           |
| `input_references`         | array            | 否   | 用于图像到图像生成的参考图像                                        |
| `provider.only`            | string\[]        | 否   | 仅允许这些提供商标识符                                              |
| `provider.order`           | string\[]        | 否   | 按此顺序尝试提供商标识符                                            |
| `provider.ignore`          | string\[]        | 否   | 排除这些提供商标识符                                                |
| `provider.sort`            | string or object | 否   | 按价格、吞吐量或延迟对符合条件的端点排序                            |
| `provider.allow_fallbacks` | boolean          | 否   | 当主提供商失败时允许其他符合条件的提供商                            |
| `provider.options`         | object           | 否   | 以提供商标识符为键的特定于提供商的参数                              |

使用[图像模型 API](#通过图像模型-api) 检查每个模型和端点支持哪些参数。
