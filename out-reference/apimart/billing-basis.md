# APIMart 计费口径与结算明细

- **来源**：`https://apimart.ai/zh/pricing`（价格页）、`https://docs.apimart.ai/cn/api-reference/images/gpt-image-2.5/generation.md`（计费口径），以及**用户 2026-09-19 提供的上游控制台"详情"面板**（上游自己的结算明细，见 §3）。
- **抓取时间**：2026-09-19
- **性质**：外部参考资源，不是平台接口合同；运行中服务不读取本目录。
- **写法**：**价格页/营销页**的档位名与展示用别名不抄——那是营销口径。但**上游结算明细里的费率与倍率**（§3）是结算依据，如实转录，并注明出处与哪些字段被省略（`task_id`、密钥标签）。

## 1. 结算口径以响应为准，不以页面为准

`gpt-image-2.5` 文档原文：「最终费用请以价格页面或 `/api/pricing` 返回的实时值为准。」

而 `/api/pricing` 在本机只读探测的 **6 个候选路径上全部 404**：

```text
apimart.ai/api/pricing
api.apimart.ai/api/pricing
api.apimart.ai/v1/pricing
apimart.ai/v1/pricing
api.apimart.ai/pricing
www.apimart.ai/api/pricing
```

⇒ **不存在可用的机器可读价格端点**。价格只能从真实调用的响应取得。

## 2. 差额是折扣，不是计量误差

文档原文：「实际扣费还会受到**账号分组倍率和折扣**影响。」

⇒ 即便平台按已发布单价算出的金额与上游声明的金额**存在系统性差额，那也是账号折扣**。对账逻辑必须容纳该差额，**不得把它当异常反复追查**；同时意味着**仅凭公开单价无法核对实际扣费**——可信度来自金额能否逐笔关联到某个 Attempt（任务查询返回金额，但不含 token 用量，见 `tasks-status.cn.md`）。

## 3. 折扣机制与明细口径（2026-09-19 由上游账单面板结清）

上游控制台的"详情"面板给出它自己的结算明细。两次图生图（`gpt-image-2.5-flare`、`n=1`、`1:1`、`1k`、`quality=low`）的面板数字与本仓库记录**逐位一致**，并暴露了之前不知道的两项：

| 项 | 值 |
| --- | --- |
| 明细里的费率行 | 文本输入 $5/1M、**缓存文本输入 $1.25/1M**、图片输入 $8/1M、**缓存图片输入 $2/1M**、文本输出 $10/1M（未出现，本次为 0）、图片输出 $30/1M |
| 折扣构成 | 面板自己写明 `Group ratio 0.8` × `Channel ratio 1` × `Discount ratio 1` |
| 关系式 | `Base cost` = 各分项 token × 各自费率之和；`Actual cost` = `Base cost` × 各 ratio；`Credits = Actual cost × 10` |
| 实例 | 29/1024/196 tokens ⇒ Base **$0.014217** ⇒ Actual **$0.011374**（0.11374 Credits），**差价 $0.002843**；33/1024/196 ⇒ Base **$0.014237** ⇒ Actual **$0.011390**（0.11390 Credits），**差价 $0.002847** |

**差价（用户核对的问题）**：三笔实测都是**整笔 −20%**，没有其它费用——`$0.014217→$0.011374`（$0.002843）、`$0.014237→$0.011390`（$0.002847）、纯文生图 `$0.005950→$0.004760`（$0.001190）。差价只来自面板自报的 `Group ratio 0.8`。

**因此**：`Base cost` = "费率 × 真实分项 token"；`Actual cost` = Base × 账号倍率。**上游声明的 `cost` 就是本笔的成本价**（它等于 `Actual cost`）；`Base cost` 与公开费率只是解释差额、并做平台侧结算基数。

**注意这条与 AIHubMix 的分工**：**APIMart 直接给金额**，成本价取 `cost` 即可，**不要**再用公开费率乘倍率重算（倍率随账号变化，重算会引入失真）；**AIHubMix 只给四分项 token、不给金额**，成本价才需要按四档 token 费率自算。两者的共同点是都有四分项 token，所以平台侧 `TokenUsage` 归一不变（见 `docs/facts/channel-facts.md` §5.1）。

**平台侧只做成本侧**：平台**对外价**（加价、让利）属**后期产品决定**，本阶段不做。**按 Tokens 计费不考虑缓存**——不为缓存加字段、也不作为待办。见 `docs/facts/channel-facts.md` §5。

**上游声明金额与 `docs/adr/0012`**：上游声明的金额随账号倍率变化，**不是可复现的计量事实**，因此平台的**计量事实**仍是四分项 token，结算由分项 token 推出（这正是 `docs/adr/0012` 在本阶段作废的原因之一）；而它作为**成本价**（本阶段要的东西）是直接可用的。

**来源**：用户 2026-09-19 在会话中提供的上游控制台"详情"面板截图。截图含 `task_id` 与 API 密钥标签，**不入库**；本文件只转录费率、倍率、token 数与金额。逐笔核对表见 `docs/facts/channel-facts.md` §5。

## 结论

APIMart 侧的权威计费口径**只能由真实调用结清**，属实施期的显式受控验证项。**在获批准前不发起任何计费调用。**（2026-09-19 已按此执行一次受控验证，见 `docs/verification/paid-provider-calls.md` §6。）
