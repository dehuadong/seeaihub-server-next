# 独立 ADR 写法

仅在项目明确将**新架构决定**交给独立 ADR 时使用本文件。Agent Notes 项目使用其部署后的 README、模板和检查器；这里的编号、正文和状态不适用于 Note。

先使用项目登记的 ADR 目录、文件名、格式和状态约定。项目选了独立 ADR 但没有确定位置时，先补全归属配置，再创建文件。多上下文仓库按上下文映射选择决定属主。

项目没有更具体的文件名约定时，在选定目录中顺序编号为 `0001-slug.md`、`0002-slug.md`。不同目录的编号可能重复，引用时带上下文或路径。只在首份独立 ADR 需要时创建目录。

项目没有既有格式时，使用以下最小结构；“反悔成本”和“权衡”写具体：

```md
---
status: proposed
---

# {决策标题}

## 背景

{触发该选择的约束或问题。}

## 决定

{选择了什么；引用产品合同与既有设计，不复制正文。}

## 反悔成本

{改变决定需要迁移什么，或会付出什么长期成本。}

## 权衡

{真实可行的备选、选择理由，以及接受的代价。}
```

采用上述默认格式时，只有决定获得项目要求的明确批准后，才将新 ADR 从 `proposed` 改为 `accepted`。决定撤回或被取代时，保留原编号及必要历史依据，按项目约定标明 `deprecated` 或替代 ADR。非显然的其他后果可增加“后果”一节。
