# 持久架构决定

先判断架构决定是否需要独立记录，再按项目文档入口确定属主。Agent Note 可以承载范围更广的技术设计；本技能的准入条件不限制其他类型的 Note。

## 独立记录的准入条件

以下三个条件都成立时，才为架构决定单独建档：

1. **难以逆转**：以后改变决定有具体、显著的迁移或反悔成本。
2. **脱离上下文会令人困惑**：未来读者有理由追问为何选择这条路线。
3. **真实权衡**：存在可行备选，并能说明选择理由与接受的代价。

不能具体说明反悔成本或权衡时，不为它单独建档；相关事实可以留在已有设计属主。规范性行为、安全策略、协议和兼容要求归工作项或独立 Spec，普通实现细节归实现及其设计属主。

## 选择属主

读取项目文档归属配置，使用其中为该决定指定的属主：

- **项目选定 Agent Note 为属主**：更新同一决定的现有 Note，或按项目 Agent Notes README 所述范围创建 Note。使用项目的 Note 格式、路径与生命周期；本技能不提供 Note 模板或批准状态。评审与批准证据按项目约定维护。
- **项目明确选用独立 ADR**：沿用项目已登记的 ADR 属主与约定。只有这一分支才读取 [独立 ADR 写法](./independent-adr.md)；同一决定不再另建 Note。

配置缺失或存在冲突时，报告该决定的记录位置与适用范围缺口，由项目配置解决后继续记录。
