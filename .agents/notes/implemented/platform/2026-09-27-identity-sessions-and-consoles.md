# Agent Note：身份与控制台：不透明会话、请求级管理员身份、两个入口一次构建

## 问题

管理面原来只有一枚共享的 `ADMIN_TOKEN`，对客面只有 API Key，两边都没有"人"的概念：无法回答"这次改动是谁做的"，客户登录后也看不到自己的余额、用量与账单。补身份就要动数据模型、认证路径与前端形态，其中三处是代码与测试都表达不出理由的选择。

## 决定

**会话令牌是不透明的。** `identity.admin_sessions` / `identity.customer_sessions` 里**只存 SHA-256 摘要**，明文只在签发那一次回给调用方；令牌是两段 UUIDv4 拼成的 64 位十六进制。每次请求都按摘要读库，所以吊销与过期**立刻生效**，不依赖任何缓存或本地状态。

**管理面的四种失败是同一个答复。** 共享令牌不对、会话不存在、会话过期、**根本没带凭据**都回 `403 admin_forbidden`。这要求管理面的取凭据走 `admin_bearer_token`（把"没带"也映射成同一个答复），而不是对客面那条"未认证一律 401"的 `bearer_token`；两边各自内部一致。

**"是哪个管理员"走请求级任务局部。** 审计在仓储层的 `insert_audit` 落地，而身份是**请求级**的事实：把它顺着函数参数传下去要改十几个调用点的签名。所以认证中间件在作用域内执行后续处理，`insert_audit` 读 `current_admin_id()` 填 `admin_id`。共享令牌与机器自我操作没有具体的人，那一列留空，`actor` 仍然说明"经哪条路径做的"。

**一个工程产出两个互不引用的入口。** `console.html`（`src/console/`）与 `portal.html`（`src/portal/`）共用 `src/shared/` 里的取数与展示骨架，由一次 Vite 构建产出两份脚本。静态产物由 `apps/api` 按**主机名**分发（`admin.` 前缀回运营后台），未命中路由的请求回对应入口 HTML。

**静态兜底显式让出 `/api` 与 `/v1`。** 这两个命名空间属于 API：未注册的路径必须回既有的 JSON 404，不能被兜底成一份 HTML。

## 备选方案

**令牌直接存在会话表里（可读）。** 落选：读库的权限或一次备份泄漏就等于拿到所有人的会话；摘要只有"签发那一次"能拿到明文，代价是每条请求多一次哈希——哈希本来就随那次读一起做。

**用 JWT 之类的自包含令牌，省掉每次读库。** 落选：吊销与过期立刻生效是本主题的硬要求（改口令要让**全部**旧会话失效），自包含令牌要么引入集中式吊销表（又回到读库），要么接受一段失效窗口。

**把管理员身份作为参数传进每个写操作。** 落选：十几个调用点都要改签名，而且这个参数在绝大多数层里只是被原样往下传——它是请求级上下文，不是某个用例的输入。

**两份产物分成两个仓库或两个构建。** 落选：用户明确否掉"两次构建、两份依赖"；共享层（HTTP 调用与错误解析、金额与时间格式）本来就只有一份，复制它比共享它更容易长出两个不一致的版本。

**兜底不排除 `/api` 与 `/v1`，让未注册路径也回入口 HTML（SPA 的常规做法）。** 落选：这会把"路径写错了"变成"调用成功"——按状态码判成败的调用方会把一份 HTML 当成正常响应读下去。第一版实现正是这样，实测 `/api/v1/nope` 回了 200 HTML 才发现。

## 后果

平台由此能回答"谁做的"（`operations.audit_events.admin_id`）与"客户看到了什么"（用量是执行记录的**对客投影**，不含 Job 标识与内部状态取值）。代价是每条带凭据的请求多一次读库，且管理面必须让出 `/api` 与 `/v1` 两个命名空间给 API 而不是给前端路由。

对客面因此**没有**"提交邮箱就收到重置链接"这条路：不发邮件也不做邮箱验证时，那种入口等于"知道邮箱就能接管账户"。重置令牌由运营在后台签发、经既有渠道转交，一次有效。同样，平台上没有在线支付，充值由运营完成，客户控制台只展示余额与记录。

静态分发要先认**入口文件名**再认主机名：`console.html` 与 `portal.html` 在同一个产物目录里，只认主机名时，本机把开发出口一开，`/portal.html` 也会回管理端那一份——两个入口在本机反而只剩一条路。

**端到端夹具的库是"从模板克隆"而不是"空库"**（`apps/api/tests/http_contract/harness.rs` 的 `isolated_database_url` 用 `CREATE DATABASE "{name}"`，默认模板是 `template1`，而它那条 doc comment 写的是"创建独立的空库"）。所以**把 `HTTP_CONTRACT_DATABASE_URL` 指着的那个库当开发库用，会把行带进之后每一次夹具**：本轮就发生过，模板里一度有 1 个管理员、2 个客户、3 条管理会话、1 把密钥与 6 条审计。现有用例的断言几乎都按"本次刚建的账户"或"总数前后之差"写，所以没被打破；但这是偶然，不是设计。要长期可靠，应把该库重置成"只应用迁移、没有业务行"的状态再跑套件。

浏览器那一层的端到端与上面那套**用不同的库**：`apps/web/e2e/ensure-database.mjs` 每次把 `seeai_e2e`（`SEEAI_E2E_DATABASE` 可覆盖）**删掉重建**再让 API 自己跑迁移。这两个默认值必须指着不同的库——`ensure-database.mjs` 的默认值一度是 `seeai_next`，而它同时又被人当作别的用途的克隆模板，跑一次就把那个库清空了。

## 验证

- `cases_identity` **15 passed**、`cases_billing` **4 passed**（真库 + 真进程）：登录、四种失败同答复、退出即失效、过期会话被拒、重置令牌一次性、改口令使全部旧会话失效、引导幂等且不回写口令、引导变量三分支、越权与未认证的区别、客户口令两条出路、注册的取值与形状两种错法。
- **headless Chrome 实测交付形态**（API 直接托管构建产物、`--host-resolver-rules` 让两个域名落到本机、`--no-proxy-server` 绕开机器上的代理）：管理端未登录只有登录页 → 登录进后台 → 六个导航项；客户控制台注册 → 四块数据各存各的会话键；折算率页录入后读回当前生效那一行；账户页替客户开户 → 按邮箱找到 → 签发重置令牌 → **客户端凭该令牌设新口令并能登录、旧口令被拒**。
- **静态托管**：`/api/v1/nope` 与 `/v1/nope` 回 JSON 404（用例与 curl 各核一次）、越目录路径 404、主机名决定回哪份入口（`<title>` 分别是对应的两份）、两个入口按文件名直达且内容不相同。
- **产物隔离**（按带引号的**精确路径**搜，别用裸路径——`/v1/customers` 是管理端自己的 `/api/v1/customers` 的子串）：客户产物里没有 `"/api/v1/…"` 系列的任何一个端点，也没有控制台的会话键 `seeai.console.session`；管理产物里没有 `"/v1/customer/…"` 系列的端点。两边各 0 命中。
- **审计落身份**：交付环境实查 `operations.audit_events`——客户开户、两次签发重置令牌与折算率录入**都带 `admin_id`**；登录与客户自助那些行留空。
