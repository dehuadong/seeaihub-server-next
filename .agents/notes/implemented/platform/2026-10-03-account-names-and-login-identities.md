# Agent Note：账户名称独立于邮箱身份和路由标签

## 问题

账户可以先充值和签发 API Key，再开通邮箱登录。现有创建表单只有标签和初始充值；标签参与路由，邮箱又可缺失，运营没有独立的服务对象名称。既有[详情页记录](../../implemented/platform/2026-10-02-admin-account-and-customer-detail-pages.md)保留列表与详情分离、明文生命周期和筛选恢复理由，本提案只涉及名称与创建提交，不改变这些决定。

## 提案

产品行为归[账户名称 Spec v2](../../../../docs/specs/0003-account-names-and-login-identities.md)，持久化、原子创建、生成规则、关联读、预览及发布顺序归[名称与登录开通设计](../../../../docs/design/0015-account-names-and-login-identities.md)。名称放在账户上，使无登录身份的账户仍能识别服务对象。

账户 id 的铸造上提到 application 用例（三处新建路径），生成函数才拿得到 id；生成在服务端一处实现，API、Web 与持久化都不各自拼名称。**名称始终存在，留空即生成**：有登录邮箱时是 `<邮箱本地部分>_<账户 id 前 4 位>`（`zhangsan@example.com` → `zhangsan_3f9a`），没有邮箱时是 `账户_<账户 id 前 8 位>`（`账户_3f9a2b1c`）。生成在服务端一处实现，表单与服务端都不把“没有名称”当成一种状态。负责人：名称由**运营和客户本人**都能改——客户改自己账户的名称走客户会话的新接口与账户设置页字段，运营沿用账户详情里的改名。

创建账户与写可选标签合并为一个事务，取代既有详情页记录中“创建后标签失败仍进详情”的局部处理。这样名称、标签和初始充值是否成立有一个确定提交结果，不需要把名称当成创建后的补救操作。

## 备选方案

- 继续靠邮箱和标签识别：保持接口最少变化，但无邮箱账户仍缺服务对象名称，且路由标签不能自由承担命名职责。
- 新建独立业务客户主体并让账户关联它：能表达多账户、联系人等关系，但当前没有已确认的组织、成员或 CRM 需求，需要额外迁移与界面。本次推荐账户名称，未来独立客户主体应另行设计。
- **名称在接口和数据库全部必填**：一致性更强，但客户邮箱自助注册这条路径根本拿不到名称，只能让客户先填一个“账户名称”或直接拒绝注册；改的是控制台 Spec 的注册能力，代价大于收益。
- **留空即“未命名账户”，由运营事后补录**（v1 的做法）：不用生成规则，但每个自助注册的账户都要等运营起名，运营成为瓶颈；名称在不同账户上还可能长期缺失，列表识别不到服务对象。
- **只由运营改名称**（v1 的做法）：维护入口与“运营识别服务对象”的定位一致，但自助注册留下的空名只能等运营补，客户看到自己的账户名不对也改不了。
- 生成组合的取舍：纯邮箱本地部分（`zhangsan`）在合法范围内可能撞名且无法区分同名；纯账户 id 片段没有任何可读信息；日期或序号需要计数器、并发下还会撞。取**本地部分 + id 前 4 位**兼顾可读与可区分，无邮箱时才退回 id 片段。

## 验收条件

产品完成判据由[Spec §6](../../../../docs/specs/0003-account-names-and-login-identities.md#6-验收条件)拥有，验证切入点由[设计 §6](../../../../docs/design/0015-account-names-and-login-identities.md#6-验证承接)拥有。本记录不另设行为规则或实现通过证据。

## 风险

- 名称不唯一，也不验证法律主体；自动生成的名字可能撞名，运营仍需结合 id 与登录邮箱确认账户。
- 客户能改自己的名称，就可能改成难以识别或与他人重名的值；本次不做唯一性与内容审核，靠列表同时展示 id 与邮箱兜底。
- 生成值里带账户 id 的片段：客户在账户设置里本来就能看到并复制完整 id，运营台也一直显示，因此不算新增暴露面。
- 迁移会把开发库里已存在的行回填成 `账户_<id 前 8 位>`（平台账户那一行回填「平台账户」）；这不是产品行为，之后由运营与客户改成真名——开发阶段允许直接重置开发库。
- 迁移编译进二进制、启动时执行，没有独立迁库步骤；真正的约束是**混合版本**：名称列非空且无默认值，旧二进制的账户插入会失败，所以回退旧 API 需要先补一条默认值迁移或直接重置开发库。
- 子串查询在大数据量下可能需索引，实际测量后再优化。创建确定失败可回滚，但网络响应未知仍需先查找确认，创建幂等协议不在本次范围。
