# Agent Note：客户侧余额改为「现在能用的钱」

## 问题

客户控制台概览此前显示「已结算余额」（`balance_microusd`）：它是**大于等于**客户实际能花的钱的那个数——请求受理时先按保底额占住一部分额度（**Held Amount**），这个数却不动。两处后果：客户拿它估「还能发多少请求」，会在余额闸门处被拒（`402 insufficient_balance`）而看不出为什么；新账户的 `0 元` 又容易被读成「充值没到账 / 额度用完」。

产品行为归[控制台 Spec v16](../../../../docs/specs/0001-admin-and-customer-consoles.md) C7、C15、§4.3、V-C6、V-D5、V-D14 与[账户资金 Spec v4](../../../../docs/specs/0002-account-funds-and-reservations.md) §4、§7（A7）；术语归 [`CONTEXT.md`](../../../../CONTEXT.md) 的 **Customer Balance**。本记录只写这次变更独有的理由、备选、后果与验证。

## 决定

客户侧只保留**一个**余额数字，标题就是「余额」，取 `available_microusd`（= 已结算余额 − 持有中）：请求受理时按占住的额度减少，结算后按实际扣费多退少补；允许为负，照实显示、不截断成 0。页面不出现已结算余额、持有中、可用额三个分项，也不出现单笔预授权金额；这个数字下面只有一行「更新于 …」。**不写解释预授权占用或结算机制的文案**：曾经写过「正在处理的请求会先占住一部分额度，结算后按实际扣费多退少补」，用户判定这种表述会误导客户（读起来像"先多扣、再退回"），已删；那套机制只留在合同与管理员面。取数失败显示错误与重试、不把缺失值画成 0，加载中不显示数字；另给一个刷新入口，因为受理与结算都会动这个数，而页面不轮询。

**取代**：本决定完全取代「客户控制台已结算余额的浏览器验证」那份 workflow 记录，它已删除；其中仍然有效的验证手法并入本文「验证」——e2e 装置只起 API、**不起 Worker**，所以「受理占住额度」靠同步入口在窗口后超时（504）真跑出来，而「实收结算」与「仅释放」用 `apps/web/e2e/account-state.ts` 把结果直接摆进库，浏览器只看页面读数。

## 备选方案

- **保留「已结算余额」、只补一句说明**：代价最小，但那个数仍然比客户能花的钱大，「还能发多少」还是得靠猜，客户侧也还挂着内部口径的名字。
- **同时显示「余额」与「持有中」两个数**：客户能自己算，但等于把内部三分解搬上客户页面——正是本次要避免的。
- **仍显示已结算余额、页面自己减去占用**：界面重算金额，与「金额取账本事实、界面不重算」的口径冲突，也对不上库里的值。
- **不加刷新入口**：客户想确认「这笔到底扣没扣」只能整页刷新；账单页早有刷新入口，概览没有反而更别扭。

## 后果

- 读数会在受理与结算之间变化，可能被读成「扣费不准」——接受这一点：客户侧不解释内部占用机制（那是平台内部的事，讲出来更像乱扣费），要核实就去调用记录与账单看逐笔事实。
- 客户看到的读数**不承诺**本次请求必能受理：它是读取那一刻的值，受理以数据库当前值为准（[`CONTEXT.md`](../../../../CONTEXT.md) 的 **Consumer Insufficient Balance**）。
- 接口与字段形状都没变：对客账户读继续同时返回三个金额字段，管理员账户页继续分别展示三项；变的只是客户页面渲染哪一个、叫什么。
- 术语表新增 **Customer Balance**，**Settled Balance** 与 **Held Amount** 的条目改成指向它——「已结算余额」这个名字从此只属于内部与管理员面。
- 页面锚点随之改名（`portal-settled-balance` → `portal-balance`），浏览器用例文件改名 `portal-balance.spec.ts`，断言方向反转：受理时读数**变小**、释放后回到原值。

## 验证

- `cd apps/web && npx playwright test e2e/portal-balance.spec.ts`：**3 passed**——充值 100、受理占住 30 后显示 70（受理后点刷新入口取数）；仅释放后回到 100；实收 20 结算后显示 80。三条都断言页面不出现已结算余额、持有中、可用额或预授权金额。
- `cd apps/web && npx playwright test` 全量**两次各 55 passed**（含 `portal-self-service.spec.ts` 的「首屏只有一个『余额』」与禁词表、`portal-navigation.spec.ts` 的五个地址与前进后退）。
- `npm run typecheck` 通过；`npm run build` 产物隔离核对通过。
