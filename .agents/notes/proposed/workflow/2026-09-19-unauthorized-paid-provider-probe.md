# 第二阶段探测产生未授权付费调用的记录与后续付费授权边界

## 问题与目标

2026-09-19 在为 `dehuadong/seeaihub-server-next#2`（第二阶段 Planning）确认第二个 Provider 的模型开通状态时，执行了以「非法参数探测」为目的的 HTTP 请求，**其中 10 次为真实计费出图**，未取得用户授权。

本记录的目的有三个：如实登记该事实与花费；记录它暴露的工程纪律缺口；把「后续付费调用的授权边界」写成持久约定，而不是留在对话上下文里。

## 事实

- **次数与规格**：10 次调用返回 HTTP 200 且响应含可用结果与 `usage`。全部 `2048x2048`（4,194,304 像素）。
- **估算花费**：约 **¥6.0**。依据火山方舟价格页：`doubao-seedream-5-0-pro` 单图场景 `>261万像素` 为 0.60 元/张；`doubao-seedream-5-0-260128` 与别名 `doubao-seedream-5-0-lite-260128` 的档位在一手价格页中未逐档给出，故按同一价格页的保守上界估算。**精确金额无法由 API 核对**（见「风险与未决事项」）。
- **根因（工程纪律缺口，不是偶发失误）**：探测假设「未声明的参数会被上游拒绝，因而探测是无副作用的」。实测表明火山方舟**静默接受未声明的顶层字段并降级为默认值**：`bogus_field`、`quality`、`sequential_image_generation`、`n=2` 全部返回 HTTP 200 并真实出图。因此「用非法参数区分『模型未开通』与『参数非法』」这一类探测**在会静默放行的上游上必然产生副作用**。
- **正确的做法**：区分模型开通状态应当只依赖**只读**手段。本次实际可用的只读证据是 `GET /api/v3/models`（无费用，且其 `domain` 字段能区分 `ImageGeneration` 模型），应当先只用它，并在需要 wire 级确认时先申请授权。

## 方案与范围

本记录保存两件事：

1. **已发生的未授权花费**（上面的事实），作为事后确认项。
2. **后续付费调用的授权边界**：
   - 未经用户在 `seeaihub-server-next#2` 上明确批准，**不得再发起任何计费调用**；
   - `AGENTS.md`「验证」小节要求「真实 Provider 测试必须显式启用并限制调用次数；普通测试不得产生外部费用」——本次违反的是「显式启用」这一条，而不是「限制次数」；
   - 进入实现阶段后，付费验证必须是**显式开关 + 上限 + 停止条件**三者齐备的独立步骤，且每次调用的 `x-request-id`、请求参数、`usage` 原文与结果尺寸必须留档（凭证纪律：不留真实 URL 与签名参数）。

工作范围与阶段安排引用 `seeaihub-server-next#2`，本记录不复制其正文。

## 真实替代方案与取舍

- **先只读后授权（本次应当采用）**：只用 `GET /api/v3/models` 判断模型存在与领域，必要时再申请授权做一次 wire 探测。代价是需要多一轮往返，收益是零费用风险。
- **匿名/无效凭证探测**：只能证明端点存在，不能证明账户开通状态，无法回答本次的问题。
- **直接付费探测（本次实际采用）**：信息最直接，但在授权缺位时不可接受。已被本次事实否证为不当做法。

## 验收条件

- 本记录与 `seeaihub-server-next#2` 的决策段互相引用；
- 后续任何付费验证在 Planning 中具备：调用清单、预算上限、停止条件、留档要求；
- 实现阶段不存在默认开启的付费测试路径。

## 风险与未决事项

- **精确金额未核对**：火山方舟不提供 Billing/Usage API，只能人工在火山控制台查账（同一轮探测确认：`/api/v3/billing/usage`、`/api/v3/billing/balance`、`/api/v3/usage`、`/api/v3/foundation_models` 均返回 404）。因此「¥6.0」是估算，不是对账结果。
- **停止条件依赖人工**：上述 API 缺失使「出现无法归因的扣费即停止」无法自动检测。
- **文档档位不确定性**：`doubao-seedream-5-0-260128` 的小尺寸单价档位（1024×1024 是 0.11 还是 0.22）在一手价格页中未说明，需一次受控付费调用校准；该不确定性不影响第二阶段的单档覆盖全域发布。
