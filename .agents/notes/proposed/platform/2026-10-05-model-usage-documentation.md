# Agent Note：模型使用文档随发布提供

## 问题

[目录读取](../../../../apps/api/src/main.rs)只给模型身份和 JSON Schema，客户端能读取参数结构，但缺少参数含义、素材流程和完整调用示例。把各种类型和厂商写进一篇图片说明无法维持模型之间的差别，引用内部规范或渠道文档也不能满足客户仅凭平台说明完成调用的需要。

参数合同已由[厂商模型合同设计](../../../../docs/design/0005-vendor-model-contract-and-offering-mapping.md)与[模型发布设计](../../../../docs/design/0012-platform-model-publishing.md)拥有。同一次发布的说明必须与它一致，不能在目录读取之后又取到别次发布的参数解释。

## 提案

本设计承接[模型使用文档 Spec v1](../../../../docs/specs/0008-model-usage-documentation.md) §1–§5。没有新建独立 ADR：文档的内容边界属于该 Spec，存储和渲染沿用既有不可变发布机制。

### 文档素材与对客正文

`public-docs/` 只放客户可以阅读的使用说明。内部设计、来源清单、抓取快照与批准证据各留在既有属主，不随公开文档部署。现有人工编写的[模型族说明](../../../../public-docs/models/openai/gpt-image-2.5.md)提供叙述内容；实施时从其参数释义形成结构化素材，并把手写参数规则替换为同版 Schema 的生成结果。

模型素材通过现有供给素材导入链配置，配置引用公开叙述正文与按 JSON Pointer 绑定的字段释义；身份、参数表和示例中的模型值使用受控占位符，不能靠全局替换厂商原生名生成平台别名。素材可以由两个厂商模型修订共享，但导入后与各自的 Vendor Model 修订关联。

模板只支持预定的身份、合同表和示例模型值插入位置。公开素材中的本地文档链接必须解析到 `public-docs/`；模型发布时将公共文档链接转换为 Spec §2 的同源公共地址。开发文档路径、未解析占位符、合同外的字段释义和缺失释义在发布前拒绝。公开素材不包含开发取证字段，因此不是从整个供给 JSON 抽取说明。

渲染参数表递归读取 Schema，并展示存在的组合条件和自然语言描述，不新增执行期 JSON Schema 校验器。示例中只注入平台身份，保留明确的示例参数；准备素材时逐条审阅示例，避免把示例值当成默认值保证。

### 持久化与发布

Persistence 新增独立的模型文档素材版本记录，关联 `catalog.vendor_models`；它不修改 Vendor Model 合同的唯一键和不可变规则。同一内容重复导入复用素材版本，内容变化追加版本，发布从库里选择该厂商模型最新导入的素材；已发布正文不再依赖素材文件或这条最新指针。

发布经 Application 读取同版合同和素材，在事务前生成有界的最终 Markdown，再在既有发布事务中保存正文、独立 UUID 文档标识、平台名及 Runtime Revision 关联。参数合同、技术候选与文档同时生效；保存正文失败回滚发布。正文大小上限为 256 KiB，超限拒绝发布，不截断客户说明。

引用式发布自动从工程侧已导入的素材取得说明，不要求运营填写正文或文档版本。内联兼容发布也读取相同的厂商模型关联素材；没有素材则拒绝，不允许通过该路径绕开文档要求。文案修正由工程侧重新导入，再沿既有完整发布流程发布；对客合同修订可以保持不变。

### 读取与模块职责

Application 提供当前文档和按平台名/文档版本读取正文的用例，Persistence 实现相关读取端口；API 负责模型名的路径段编码、版本参数解析、正文编码与错误信封。当前读取和目录使用同一个可调用判据；历史读取只按平台名与文档 UUID 对应关系，不使用当前启用开关。Worker 与 Provider Adapter 没有新职责。

目录取数在一次查询中取合同与文档标识，投射生成根相对地址。历史路由先验证版本 UUID，名字按 UTF-8 路径段编码和解码；不收紧现有模型命名范围。合法名字含斜杠与 URI 保留字符的行为由真实 HTTP 合同夹具验证，避免链接在路由阶段被误解释。

公共文档通过只允许 Spec §2 三个名称的路径提供，资源仅从 `public-docs/` 选取；构建/部署将它们作为应用资源携带，直接运行与容器部署一致，不提供任意文件读取。它们是当前平台规则说明，不随模型修订冻结。模型文档的历史保证限定于已保存的模型正文及参数，不扩大为公共规则历史或旧版模型执行保证。

### 兼容与切换

迁移新增说明关联表以兼容历史 Runtime Revision：每条公开文档记录携带正文、独立 UUID、平台名和 Runtime Revision 外键，同一修订只有一条记录；历史修订可以没有关联。只新增文档记录，不重写既有 Runtime Revision、历史合同或执行记录。首次启用目录新字段之前，为所有当前模型生成明确关联的文档快照；不会为了填字段而发布新的价格或路由定义。历史修订无说明时不伪造旧版参数释义。

若运行库存在首批两款之外的当前模型，交付前报告并把其正文范围补回工作项；不能隐藏该模型，不能以空正文或通用图片正文顶替。切换门槛和模型集合不变的证据归 Spec A10。旧接口字段和受理路径保持原语义；出现不完整关联时不能开放此版目录响应。

## 备选方案

只给 Schema 加 `description` 的改动较小，但无法充分表达素材处理、调用例子与结果读取，也会使普通释义修正碰到合同不可变规则。

直接维护按名字寻址的 Markdown 静态文件容易开始，但平台别名与同版参数靠手工对齐，目录读取和模型重新发布之间可能串版。

选用独立文档素材加发布快照：参数规则从合同生成，叙述单独维护，平台名和版本由发布注入。代价是增加素材记录、发布校验和公开读取，而不增加客户端对渠道的了解要求。

## 验收条件

验收合同见 Spec §5，不在此复写。A1/A2/A6/A7/A8/A10 用真实数据库的 HTTP 合同夹具核对目录、版本读取与发布原子性；A3/A9 用离线素材和生成结果验证参数、别名与跨类型区别；A4/A5 检查公开文档正文、链接和调用示例，上传流程复用已有假对象存储和假 Provider，不调用真实渠道。

## 风险

结构约束可以从 Schema 生成，参数含义和适用场景仍需人工核实；渲染器不能靠字段名猜含义。发布校验拦住结构遗漏，人工审阅负责语义一致性。

不可变正文增加存储量，256 KiB 上限避免无界输入；本轮不建立清理策略或历史文档过期规则。公共规则单独维护，修改它们时必须同步客户使用说明；不能把模型正文的冻结解释为冻结服务行为。
