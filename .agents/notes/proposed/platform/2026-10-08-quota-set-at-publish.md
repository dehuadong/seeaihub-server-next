# Agent Note：并发名额在上架时给出，进程配置不再提供名额

## 问题

#94 交付后，名额落在 `publication.gateway_models.max_concurrent_jobs`（可空＝用部署缺省），只有**编辑**路径能设（模型卡片上的 `PATCH`）。两处不合需求：

- **上架路径没有设置项**：控制台发布抽屉没有该字段，发布命令不收它，发布事务只写 `(gateway_model, updated_by)`；
- **进程配置仍是名额来源**：模型行为 `NULL` 时读 `GENERATION_MAX_CONCURRENT_JOBS`（缺省 1）——用户指出这个变量"本来就是不要的"，留着它就是没做完。

需求：名额由运营在**上架新模型或者编辑新模型**时给，进程配置里**不再有任何**名额来源。

## 提案

1. **删掉配置来源**：`GENERATION_MAX_CONCURRENT_JOBS` 的读取、`DirectExecutionLimits.default_max_concurrent_jobs`、读面顶层的 `max_concurrent_jobs_default`、`configuration.md` 与 `.env.example` 里的那一项、代码与文档里"部署缺省"的说法。名额只有 `publication.gateway_models.max_concurrent_jobs` 一个来源。
2. **列必填**：新迁移先回填存量行 **1**、再 `SET NOT NULL`、并**重写列注释**（`0048` 的注释里写着"`NULL`＝用部署缺省"，与新状态矛盾；`CHECK (> 0)` 已在 `0048` 上，历史迁移按校验和规则不改）。**这会改变存量部署的生效容量**：原来把变量设成 N 的部署，升级后每个模型是 1——这是"进程配置不再是名额来源"的必然产品后果，不是顺带副作用，因此写进 Spec 修订记录与验收。

**无窗口的切换路径**（RUNBOOK）：迁移一跑，回填对所有副本当场生效，所以不能"升级后再设回去"。顺序是：① 用 #94 已经有的 `PATCH /api/v1/gateway-models/{model}` 在**升级前**把要保留 N 的模型逐个设成 N（此时列还是可空的，写进去就生效）；② 用读面核对每个模型的值；③ 再升级（新迁移回填剩下的 `NULL` 为 1 并 `SET NOT NULL`）；④ 升级后核对一遍。旧副本在过渡期读的是同一张表，因此这条路径没有"降流窗口"。
3. **上架路径**：发布命令加可选字段 `max_concurrent_jobs`（正整数 `Option<u32>`，值域由接口校验到 `1..=i32::MAX`，与该整数列一致）。写值落在 `publish_runtime` 的**同一事务**里，形状与 `set_gateway_model_settings` 一致（**只有这一套**）：
   - ① `SELECT enabled, max_concurrent_jobs FROM publication.gateway_models WHERE gateway_model = $1 FOR UPDATE`：没有行＝新建，有行＝已有，同时拿到改前值（审计要用）。
   - ② 新建：`INSERT ... (gateway_model, max_concurrent_jobs, updated_by) VALUES ($1, COALESCE($3, 1), $2)`——省略时取**平台固定值 1**；已有：`UPDATE ... SET max_concurrent_jobs = COALESCE($3, max_concurrent_jobs), updated_by/updated_at 只在值真的变了时动`。两处都用**原始绑定参数**，**不用 `EXCLUDED`**（它省略时带的是新行的 1，会把已有模型的名额悄悄重置）。SET **不含 `enabled`**（重新发布不能把停用的模型悄悄打开）。
   - ③ 审计：见第 6 条。
   - 语义：命令**省略**该字段 → 新建取 1，已有行**名额与时间戳都不动**；命令**给了值** → 写它。与 `consumer_reference_rates` 一致的只是**语义**（"省略即保留已有的值"），不是那句 SQL 的形状。
   - 与 `PATCH` 的锁序：发布走咨询锁、`PATCH` 走行锁；命令给了值就以它为准，比较与写入在**同一事务、同一条写路径**里完成，不在 Rust 里先读后写再写回。
4. **它仍是运行状态**：名额不进 `runtime_revisions` / `runtime_entries`、不进该次发布的快照 JSON 与发布响应、不进 `OfferingCandidate`、Job 不固定它；发布事务写它，只是"上架这个模型的同一时刻把额度落在一张运行状态表上"。
   类型随列收紧：`publication.gateway_models.max_concurrent_jobs` 变 `NOT NULL` 之后，`ActiveOfferings.max_concurrent_jobs` 从 `Option<u32>` 收紧成 `u32`（"没有值"在类型上不可表示），`direct_execution.rs` 里那句 `unwrap_or(...)` 随之消失，不会被硬编码 1 顶回来；`DirectExecutionLimits` 的 `default_max_concurrent_jobs` 与 `AppState` 的对应字段、读面的 `max_concurrent_jobs_default`、`main.rs` 的环境变量读取函数一并删掉。发布命令带它，是因为"上架一个模型"就是运营给这个模型定额度的时刻；路由策略不进发布命令，是因为它不属于某个模型的定义（`ADR-0020`）。
5. **编辑路径**：`PATCH /api/v1/gateway-models/{model}` 的**省略＝这次不改**——启停按钮只发 `{enabled}`，这条必须继续成立（#94 已交付的语义）；**请求里给了名额就必须是正整数**，`null`／0／负数／超出上界（取该整数列的范围，即 `1..=i32::MAX`）→ 400 并点名；`enabled` 同样可省略。
6. **审计**：两条写入方都用 `gateway_model.set_max_concurrent_jobs`（载荷给改前改后），但**触发口径不同，这是有意的**：`PATCH` 走 #94 已交付的规则——**请求里给了这个字段就写一条，空改动也写**（"运营按了一次保存"这件事本身要看得到）；发布路径**只在已有模型的名额真的变了时写**（发布的主语是修订，不是改名额；值没变却写一条会让审计里堆满"名额从 N 变 N"）；**新建的模型不另写**，那次发布本身有发布审计，名额是它的一部分。发布路径不动开关列，因此也不写 `set_enabled`。
7. **控制台**：发布抽屉加数字字段，**只有运营改过它才发送**（按表单的"字段是否被碰过"判断；型号名是自由文本，用上架模式重发已有模型名时不能因为预填就把名额钉住）。字段旁写明："留空＝新建的模型按 1（一次一任务）；已有模型保持现值，要改就填"。**型号名命中已有模型时，字段旁显示它的当前值**（只作提示，不写回表单）。**改价态显示当前值**，同样只在被改过时才发送。模型卡片仍能改；非法值在 API 与表单两处点名拒绝。
8. **合同与属主同一变更里同步**：Spec `0001`（**改写 M1 与 V-D17**、M2 加发布命令那一句、§5.3 新增 V-D18）、Spec `0005`（**只动 §6**：去掉"模型没设名额时用部署缺省"；§3 措辞不变）、design `0006` **§2.2 的读响应示例**（删顶层 `max_concurrent_jobs_default` 与模型内的 `null`）与 §2.3/§2.4、design `0012` 升 v4、design `0017` 升 v3、design `0009` §3、`CONTEXT.md` 的模型并发名额词条、`configuration.md`、`.env.example`、**`docs/operations/deployment.md` §3.3 与它的衍生（`production.md`、`production-docker.md`）**——它们现在写着"升级＝先部署后观察、没有单独的迁移步骤"，照做会把容量静默降到 1，必须补上无窗口 RUNBOOK。
9. **与既有记录的边界（部分取代，互链）**：`.agents/notes/implemented/platform/2026-10-08-gateway-model-concurrency-quota.md` 里作废的是——决定 1 的"可空＝用部署缺省"、决定 6 的"`null` 清成缺省"与读面顶层缺省字段、决定 7 的"旧变量降级为部署缺省"，以及验证表里对应的那几行；**仍有效**的是：判定维度「账户 × 网关模型」、名额落在模型行、取值路径（受理同一次查询带出）、审计动作名与"空改动也记一笔"的形状。同一变更里把作废处标注失效范围并双向链接（`.agents/notes/README.md`：不改写成相反结论，只标边界并互链）。
   另外 `.agents/notes/implemented/platform/2026-09-20-flat-request-body-and-asset-roles.md` 里"模型没设时用部署缺省"那句也要同步改掉（它现在把缺省当现行事实）。
   **被推翻的备选**：`#94` 记录里"**非空列 + 迁移回填 1：落选（静默降容）**"这一条被本提案采纳——用户明确要求进程配置不再是名额来源，静默降容因此从"落选理由"变成**声明过的后果**（见第 2 条与"风险"）。
10. **术语口径**：`CONTEXT.md` 的**模型并发名额**词条去掉"模型没设时用部署缺省"之后，**不要写成新的运行时缺省**；要写"由运营按模型给；发布命令没给时新建的模型按平台固定值 1"。

**验证切入点**

- 真库端到端：上架带 2 → 读面是 2、受理按 2 判（第三个并发回 429）；上架省略 → 新模型是 1。
- 重新发布不给名额 → 现值不变；给新值 → 立刻更新；重新发布不改变 `enabled`（用一个已停用的模型验证）。
- `PATCH` 给 `null`／0／负数／超列宽 → 400 并点名；给正整数 → 生效。
- 迁移：在"迁移 `0048` 之后、本次迁移之前"的库上造存量行（名额可 `NULL`）→ 升上来是 1 且列 `NOT NULL`。
- 运行配置、源码与文档里不再读／不再列 `GENERATION_MAX_CONCURRENT_JOBS`：`apps/api/src/main.rs` 的读取函数与 `AppState` 字段、`DirectExecutionLimits` 字段、读面顶层字段、`configuration.md`、`.env.example`，以及夹具侧写死它的地方（`apps/api/tests/http_contract/harness.rs` 约 1121／1213／1254／1503 行、`apps/web/e2e/start-api.mjs`）——夹具的并发形参改成**把名额带进发布命令**，否则所有并发在飞的用例都会因为没有名额而按 1 拒绝；历史迁移文件与已交付 Agent Note 按各自规则不改写（当前列注释由新迁移重写）。
- 控制台：发布抽屉的字段**只在被运营改过时发送**（留空不发送）；改价态显示当前值、同样只在被改过时发送；卡片能改；非法值点名拒绝。
- 相邻行为不回归：#94 的 429 语义、跨副本共同遵守、`cases_publication` 等组。

## 备选方案

- **保留配置缺省，只把它标成可选**：落选。用户明确说它"本来就是不要的"；留着它等于"没设过的模型由配置文件决定"，正是需求排除的形态。
- **列保持可空、`NULL` 当 1**：落选。"未设"会长期存在，读面与控制台都要解释两层含义；必填 + 上架时给出更直白。
- **名额随修订冻结**：落选（同 #94：改一个并发数不该要求重新发布，且它不影响已受理的 Job）。
- **上架成功后另调一次设置接口**：落选。发布成功与名额写入会分成两个事务，留下"发布成功、名额没写成"的半成品。
- **发布命令把 `enabled` 一起写**：落选。那会让重新发布把停用的模型悄悄打开（`enabled` 今天只由 `PATCH` 与发布 INSERT 的默认值管）。
- **回填沿用部署现值**：做不到。迁移读不到进程环境；只能回填平台固定值 1，并把"逐个模型设回"写进升级说明。

## 验收条件

设计侧的完成判据：

- 运行配置、源码、文档与**当前列注释**里都不再出现 `GENERATION_MAX_CONCURRENT_JOBS`（历史迁移文件按校验和规则不改，由新迁移更新列注释）；名额只有一个来源与两个写入方（发布的同一事务、`PATCH`）；
- 控制台上架抽屉留空时**不发送**该字段（新建取 1、已有模型不动）；改价态显示当前值；卡片能改；
- **升级的容量变化是声明过的后果**：在"迁移 0048 之后、本次迁移之前"的库上升级后，每个模型都是 1，且 RUNBOOK 的四步可执行；
- 上架、改价、编辑三条界面路径的行为与 Spec `0001` 的新条目逐条对得上；
- 列必填 + 回填 1 的迁移在"已有存量行"的库上应用成功，且升级说明写清容量变化与恢复顺序；
- 上面「验证切入点」的每条都有对应用例或迁移证据；
- 两份 Spec 修订与各属主文档同步完成并通过评审后，本设计才成为实施依据。

## 风险

- **升级即改容**：原来把变量设成 8 的部署，升级后每个模型是 1，直到运营逐个设回。这是"配置里不再有名额"的必然结果；升级说明与发布说明必须写清顺序。
- **上架的体感**：抽屉默认留空，新建模型按 1 跑；文案要说清"留空＝1（一次一任务），已有模型保持现值，要改就填"。
- **两套锁的并发交错**：发布用咨询锁、`PATCH` 用行锁；命令给了值就以它为准，写值在 SQL 里原子完成，不在 Rust 里先读后写。
- **读面形状是破坏性变化**：删掉顶层 `max_concurrent_jobs_default`，控制台与用例必须在同一变更里改。
- **素材导入与 bootstrap 夹具不带该字段**：它们走"省略 → 新模型取 1"，所以不用改，但要在用例里钉住这条语义。
